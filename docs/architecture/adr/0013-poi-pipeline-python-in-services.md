# ADR 0013: POI 파이프라인은 파이썬 모듈로 services/ 에 둔다 — 원본은 파일에, 표에는 살아 있는 것만

## 배경

편의시설(POI) 47만 건은 프로토타입(`apps/navi_proto`, navi-proto 브랜치)의 파이썬 스크립트가
TMAP 에서 격자로 긁어 JSONL 로 두고, 사람이 순서를 정해 돌렸다. 음식은 서울·부산·경주·강릉만
있고 전국은 아직이다. 폐업 대조(공공데이터 상가정보)도 손으로 돌린다. 적재는 `tools/scripts/seed-poi.sh`
로 사람이 한다(MZ2AZ-314 가 `poi` 표와 조회·카드 API 를 만들었다).

멘토 제안(2026-09-02·09-05): 이 배치를 **Airflow 로 관리**하고, **파이썬으로**. 그리고 「원본
47만 건을 굳이 DB 에 다 넣을 필요가 있나」.

제약 셋. 저장소는 Bazel 단일 빌드이고 아직 파이썬 모듈이 없다(`MODULE.bazel` 에 rules_python 이
주석으로만 준비돼 있었다). 팀은 셋이고 파이프라인은 하나다. 맥 한 대의 kind 클러스터에 SigNoz
와 함께 올라가야 한다.

## 결정

우리는 파이프라인을 **`services/poi-pipeline/` 파이썬 모듈**로 두고, **Airflow DAG 는 얇게** —
태스크 넷(수집·생존 대조·적재·보고)이 그 모듈의 명령을 부르기만 한다. 모듈은 **표준 라이브러리만**
써서 Bazel 검사가 pip·네트워크 없이 돈다. 툴체인은 Bazel 이 내려받는 3.12 다.

**원본은 파일, 표에는 살아 있는 것만.** 47만 건 원본 JSONL 과 훑은 칸 장부는 데이터 디렉터리
(PVC)에 남기고, 공공데이터에 살아 있는 것(음식 43.7%)만 `poi` 표에 UPSERT 한다. 명소·교통은
상가가 아니라 대조 없이 전부. 네이버 매칭은 배치가 아니다 — 카드는 서버가 누를 때 채운다(ADR 0011).

## 검토한 대안

| 선택지 | 채택하지 않은 이유 |
| --- | --- |
| `agents/poi-pipeline/` | LLM 이 없다. `agents/` 의 규칙(프롬프트·평가·도구 스키마)이 하나도 해당하지 않는다 |
| 스프링(scene-api) 안의 `@Scheduled` 배치 | 멘토가 짚은 것은 파이썬·Airflow 다. 수집기 1,000줄이 이미 파이썬이고, 격자·재개·쿼터 논리를 자바로 다시 쓰면 얻는 게 없다. 서비스 하나가 배치까지 안으면 배포 단위가 커진다 |
| cron + `just` 레시피 + 장부 파일 | 이미 그 형태다. 재시도·백필·화면이 없어 지금 겪는 문제(사람이 센다)가 그대로다. 기술적으론 충분하지만 운영 가시성과 학습을 버린다 |
| Prefect · Dagster | 가볍지만 표준성이 낮고, 멘토 평가 항목은 Airflow 다 |
| 47만 건 전부 `poi` 표에 | 56% 가 폐업·이전이라 화면에 죽은 가게가 뜬다. 원본은 파일로도 충분히 다시 쓸 수 있다 |
| pip 로 psycopg 를 들여 직접 적재 | 붙는 길(직접 psql · kind 파드)을 `seed-poi.sh` 가 이미 알고 변환 SQL 이 멱등이다. 첫 파이썬 모듈에 pip 잠금까지 함께 들이면 검토할 것이 둘이 된다 — 필요해질 때 |

## 결과

**좋아지는 것**

- 수집이 매일 03:00 스스로 돈다. 셀 단위 장부로 끊긴 데서 이어받고, TMAP 하루 한도는 Pool 이 나눈다.
- 파이썬이 Bazel 에 들어왔다 — `agents/` 가 생길 때 같은 툴체인을 쓴다.
- 표에는 살아 있는 가게만 있어 지도의 점을 믿을 수 있다.

**나빠지는 것 / 감수하는 비용**

- kind 에 프로세스 셋(웹서버·스케줄러·메타 DB)이 더 뜬다 — 메모리 2~3 GB. 켤 때만 켜고
  `just airflow-pause` 로 재운다(SigNoz 와 같은 방식).
- 공공데이터 CSV 는 자동으로 못 받는다(포털이 로그인·약관 뒤에 있다). 분기마다 사람이 받아 PVC 에 넣는다.
- 적재가 `seed-poi.sh` 에 묶여 있어 Airflow 이미지에 psql 이 들어간다.

**후속 작업**

- MZ2AZ-315 — 이 결정의 구현. kind 에서 DAG 한 번 성공이 끝나는 조건.
- 첫 pip 의존성이 생기면 `MODULE.bazel` 의 pip 블록을 켠다(주석에 적혀 있다).
- 원격 환경의 Airflow 는 별도 결정 — 로컬 kind 값만 있다.

## 검증

- `just check` 가 파이썬 단위 검사(가짜 fetch)를 포함해 초록이다.
- `just airflow-up` → `just airflow-trigger poi_daily` 뒤 `poi` 표 행 수가 는다.
- `poi` 표에 든 음식 POI 의 id 가 전부 `poi_alive_food.jsonl` 에 있다.
