# ADR 0013: 가이드 챗봇은 파이썬 에이전트가 맡고 scene-api 는 프록시한다 — LLM·도구·코스 계산은 agents/trip-guide, 저장은 서버

> [0012](./0012-guide-chat-is-served-by-the-server.md) 를 대체한다. 0012 는 「LLM 호출·도구 실행·
> 프롬프트를 scene-api 안에 둔다」고 정했고, 파이썬 에이전트를 따로 두는 안을 기각했다. 그 기각의
> 전제가 이틀 뒤 바뀌었다 — 아래 배경에 무엇이 바뀌었는지 적는다. 0012 의 앱 쪽 원칙(앱은 LLM 의
> 주소·모델·키를 모른다, 화면 상태를 요청에 실어 보낸다, 근거를 `toolsUsed` 로 돌려준다)은 그대로
> 유효하고 이 ADR 도 그것을 지킨다.

## 배경

0012 가 파이썬 에이전트 안을 기각한 이유는 둘이었다.

1. *"도구가 전부 scene-api 의 데이터라 서비스 하나가 더 생기고 왕복만 는다."*
2. *"프롬프트·오케스트레이션이 300줄 안팎이라 언어를 하나 더 들일 크기가 아니다."*

0012 는 2026-09-05 에 `MZ2AZ-239-챗봇-계약` 브랜치에서 쓰였고 main 에 합쳐지지 않았다. 같은 날
`agents/trip-guide`(MZ2AZ-200·201, 김태환)가 PR #73 으로 main 에 들어왔다. 실제 크기와 내용은
이렇다.

| | 0012 가 전제한 것 | main 에 있는 것 |
| --- | --- | --- |
| 크기 | 프롬프트·오케스트레이션 300줄 | 소스 약 3,300줄, 결정적 시험 약 1,300줄, 평가 약 430줄 |
| 도구 | 3 개 (`poi_nearby`·`route`·`add_to_cart`) | 10 개 — 촬영지 검색 4, 장바구니 1, 코스 계획·수정 4, 편의시설 1 |
| 코스 계획 | 없음 (앱의 `RoutePlanner` 가 LLM 을 직접 부름, 별도 ADR 로 미룸) | **LLM 없는 알고리즘** — 후보 점수 → 지역 → 날짜 클러스터링 → 2-opt → 시간표. 고치기(`revise_day`·`move_stop`) 포함 |
| 검증 | 검수표 (사람이 돌림) | 단위 시험 99 개 + 지표 5 종 평가(실현 가능률·결정성·동선 효율·작품 커버리지·도구 선택). 모델·네트워크 없이 돈다 |
| LLM | 맥의 mlx_lm 8B, 도구 1 회 실측 30 초 | DeepSeek API, 챗봇 경로 실측 3~5 초, 계획만은 0.02 초 |

즉 **「언어를 하나 더 들일 크기가 아니다」는 더 이상 사실이 아니다.** 이미 들어와 있고, 그 안의
핵심은 프롬프트가 아니라 코스 계산 알고리즘과 그것을 지키는 평가다. 이것을 자바로 옮기는 것은
이식이 아니라 재작성이고, 평가까지 옮기지 않으면 계산이 맞는지 알 길이 없어진다.

「왕복만 는다」는 절반만 맞다. 에이전트가 scene-api 에 보내는 것은 공개 GET 6 종뿐이고
(`/places`·`/contents`·`/contents/{id}/places`·`/places/{id}`·`/pois`), 쓰기는 하나도 없다.
홉 하나가 더 붙는 비용은 밀리초 단위이고, 모델 호출 3~5 초 옆에서는 보이지 않는다. 0012 의
「30 초」는 로컬 8B 모델의 시간이었지 네트워크의 시간이 아니었다.

팀의 실제 제약도 있다. 에이전트는 김태환, scene-api 는 정권호가 맡는다. 한 코드베이스에 넣으면 두
사람이 같은 배포 단위를 두고 부딪히고, 프롬프트를 고칠 때마다 스프링 전체를 다시 낸다.

에이전트가 **가질 수 없는 것**이 하나 있다. 사용자 신원(`X-Device-Id`)이다. 쓰기 API 14 개가 전부
그 헤더로 계정을 찾는데, 에이전트가 그것을 넘겨받으면 권한이 새는 구조가 된다. 그래서 에이전트는
「무엇을 저장하라」를 말만 하고(`effects`) 저장은 신원을 아는 쪽이 해야 한다.

## 결정

우리는 **가이드 챗봇의 LLM 호출·도구 실행·프롬프트·코스 계산을 `agents/trip-guide` 에 두고,
`services/scene-api` 는 두 창구를 열어 에이전트를 부르고 저장을 대신한다.**

| 창구 | 받는 것 | scene-api 가 하는 일 |
| --- | --- | --- |
| `POST /guide/chat` | 대화 이력·현위치·화면 상태(`context`) | 에이전트 `/guide/chat` 에 넘긴다. 응답의 `effects` 중 `cart.*` 는 `CartStore` 로 저장하고, `plan.*` 과 `ui` 는 손대지 않고 앱에 돌려준다 |
| `POST /guide/plan` | 작품·일수·속도·출발점·must·avoid (구조화된 값) | 에이전트 `/plan` 에 넘기고 그대로 돌려준다. 모델도 저장도 없다 — 앱의 일정짜기 마법사용 |

지켜야 할 규칙 넷.

- **에이전트는 신원을 모른다.** scene-api 는 `X-Device-Id` 를 에이전트에 넘기지 않는다. 저장은
  scene-api 가 `effects` 를 읽고 한다. `cart.add` 의 `placeId` 가 `null` 이면 거절한다 — 이름으로
  대신 찾으면 동명 장소에 걸린다.
- **`plan.*` 은 저장하지 않는다.** 계약이 이미 「편집하는 동안 서버로는 아무것도 나가지 않는다」고
  못 박고 있다(`PUT /courses/{id}`). 챗봇이 짠 일정은 초안으로 앱에 가고, 저장은 사용자의 「완료」가
  부르는 `PUT /courses/{id}` 한 번뿐이다. 챗봇만 예외로 두면 「취소」가 동작하지 않는 화면이 생긴다.
- **편집 중인 코스는 앱이 정본이다.** scene-api 는 DB 에서 코스를 읽어 에이전트에 넘기지 않는다.
  앱이 `context.plan` 에 실어 보낸 편집 사본을 그대로 통과시킨다. DB 것을 넘기면 챗봇이 옛
  일정을 고쳐 돌려준다.
- **에이전트가 안 뜨면 `503 GUIDE_UNAVAILABLE`.** 규칙 기반으로 조용히 떨어지지 않는다. 앱은 그
  사실을 화면에 말한다(0012 와 같다).

`effects`·`ui` 의 모양은 계약이다 — `contracts/schemas/guide/` 에 한 벌만 둔다. 에이전트의
`schemas/effects.json` 이 그리로 옮겨 가고, 양쪽이 같은 파일을 본다.

## 검토한 대안

| 선택지 | 채택하지 않은 이유 |
| --- | --- |
| 0012 대로 스프링 안에 구현하고, trip-guide 의 코스 엔진을 자바로 옮긴다 | 재작성이다. 1,146 줄의 계획 엔진과 99 개 시험·평가 5 종을 함께 옮기지 않으면 계산이 맞는지 알 수 없고, 옮기면 파이썬 쪽과 두 벌이 된다. 담당자도 갈린다 |
| 시점으로 나눈다 — 여행 중 가이드(0012 의 도구 3 개)는 스프링, 촬영지 탐색·코스 계획은 에이전트 | 챗봇이 둘이 되고 프롬프트도 둘이 된다. 앱이 「지금 어느 챗봇에 물을지」를 골라야 하고, 시트 하나에 대화가 두 갈래로 갈린다. 0012 의 도구(`route`·여행 상태 읽기)는 에이전트에 **더하면** 되는 것이라 나눌 이유가 없다 — 후속 작업으로 남긴다 |
| 앱이 에이전트를 직접 부른다 | 0012 가 기각한 이유 그대로다. 모델·키·주소가 앱에 박히고, 저장(`cart.*`)을 할 신원이 앱에만 있어 에이전트가 저장을 부탁할 곳이 없다 |
| 에이전트가 `X-Device-Id` 를 받아 쓰기 API 를 직접 부른다 | 에이전트가 사용자 신원을 들게 된다. 알 필요 없는 정보를 들면 권한이 새는 구조다. 읽기는 헤더가 필요 없으니 지금처럼 직접 부르는 것이 맞다 |

## 결과

**좋아지는 것**

- 챗봇과 마법사가 같은 엔진을 쓴다. 「도깨비로 1박 2일」을 말로 하든 화면에서 고르든 같은 일정이
  나오고, 응답 모양(`plan`·`effects`·`ui`)도 같아 앱이 한 벌로 받는다.
- 계산이 평가로 지켜진다. 계수를 바꾸면 실현 가능률·동선 효율 지표가 따라 움직이고, 100% 아래면
  시험이 실패한다.
- 프롬프트·모델·계수를 스프링 배포와 다른 주기로 바꿀 수 있다. 전부 파일이고 설정이다.
- 0012 의 앱 쪽 성질은 그대로다 — 앱은 모델을 모르고, 근거(`toolsUsed`)를 받고, 화면 상태를 보낸다.

**나빠지는 것 / 감수하는 비용**

- 배포 단위가 하나 는다. `rules_python` 이 `MODULE.bazel` 에서 꺼져 있어 지금은 에이전트의
  BUILD 도 컨테이너도 없다 — 켜는 것은 의존성 추가라 팀 결정이 먼저다(CLAUDE.md §9). 그전까지
  에이전트는 노트북에서 `python3 -m web.server` 로만 돈다.
- 네트워크 홉이 하나 붙는다. 밀리초 단위이지만, 에이전트 주소·타임아웃이 scene-api 의 설정이
  되고 그것을 환경마다 맞춰야 한다.
- scene-api 요청 스레드가 3~5 초를 기다린다. 이 PR 에서 가상 스레드를 켠다(자바 21 · Spring Boot
  4.1 — 설정 한 줄). 그러면 병목이 톰캣 스레드에서 DB 커넥션 풀로 옮겨 가는데, 이 경로는 DB 를
  거의 안 쓴다.
- 0012 가 계약에 넣었던 여행 중 화면 상태(다녀옴·여행 단계·가는 곳·걸은 거리)는 에이전트의
  `context` 에 아직 없다. 「다 돌았어?」「몇 곳 남았어?」에 답하려면 그 항목을 에이전트 쪽
  `context_block` 에 더해야 한다 — 후속 작업.
- 상용 API(DeepSeek, 이후 Bedrock)로 사용자 위치·담은 지점 이름이 밖으로 나간다. 0012 와 같은
  비용이고, 좌표는 모델에게 안 주므로 안 나간다.

**후속 작업**

- 계약: `POST /guide/chat`(0012 의 것에 `effects`·`ui` 추가, `context` 를 에이전트 모양으로)과
  `POST /guide/plan`. `contracts/schemas/guide/` 에 effects·ui 스키마. `just gen`.
- scene-api 구현: 에이전트 클라이언트(주소·타임아웃은 설정), 컨트롤러 둘, `effects` 처리기,
  가상 스레드 켜기. 에이전트를 가짜로 세운 단위 시험.
- 배포: `rules_python` 활성화 결정 → 에이전트 BUILD·컨테이너·Deployment. Bedrock 자격 증명은
  MZ2AZ-317.
- 에이전트: 0012 의 여행 중 상태를 `context` 에 받도록 확장. 필요하면 `route` 도구 추가.
- 앱: iOS `RouteGuide.ask` 를 생성 클라이언트로(0012 의 후속과 같다). Android 동일. 마법사
  (`RouteWizardView`)는 `POST /guide/plan` 으로.

## 검증

- 에이전트를 로컬에서 띄우고 scene-api 의 두 창구에 실제 요청을 흘린다. 「도깨비로 1박 2일
  짜 줘」가 `plan.draft` 를 돌려주고 DB 에 코스 행이 **생기지 않는다.** 「그거 담아 줘」가
  `cart.add` 를 돌려주고 `cart_items` 에 행이 **생긴다.** `placeId: null` 인 `cart.add` 는 거절된다.
- 에이전트를 끄면 `503 GUIDE_UNAVAILABLE` 이 온다. 규칙 기반 답이 오면 이 결정을 어긴 것이다.
- `POST /guide/plan` 은 API 키 없이도 답한다. 같은 입력에 같은 일정이 나온다(에이전트 평가의
  결정성 지표가 100% 를 유지한다).
- scene-api 코드에 프롬프트 문자열·모델 ID·도구 정의가 없다(`grep` 으로 확인). 있으면 0012 로
  되돌아간 것이다.
- 다시 볼 시점: 에이전트에 0012 의 여행 중 상태를 더한 뒤에도 「다 돌았어?」류 질문에 도구 0 회로
  답하지 못하면, 시점으로 나누는 대안을 다시 검토한다.
