# ADR 0006: 앱 API 클라이언트는 명세에서 생성한다

## 배경

[ADR 0002](./0002-product-stack-spring-python-native-mobile.md) 가 크로스 플랫폼
프레임워크를 쓰지 않기로 하면서 감수한 비용이 **"모바일 기능을 두 번 만든다"** 이고,
같은 문서가 검증 항목으로 **"두 모바일 앱이 실제로 어긋나지 않는가"** 를 걸어 뒀다.

어긋남이 가장 잘 생기는 자리가 API 호출이다. 필드 이름 하나, 쿼리 파라미터 하나가
iOS 와 Android 에서 달라지면 화면은 멀쩡해 보이는데 결과가 다르다. 손으로 쓰면 그런
차이가 리뷰에서 눈에 띄지 않는다.

서버 쪽은 이미 같은 판단을 해 뒀다. `contracts/openapi/scene-api-v1.yaml` 에서
Spring 인터페이스를 생성하고 컨트롤러가 그것을 구현하므로, 계약 위반이 컴파일
오류가 된다 ([ADR 0003](./0003-spring-boot-bazel.md)). 앱에도 같은 장치가 필요하다.

도구는 이미 `MODULE.bazel` 에 있다 — `openapi_tools_generator_bazel` 이 Spring
인터페이스를 만들고 있고, 그 파일에 **"생성기 이름만 바꾸면 언어가 바뀐다 — spring ·
swift5 · kotlin"** 이라고 적혀 있다. 이 ADR 은 그 방침을 앱까지 확장하면서, 미뤄 둔
위험을 기록으로 남긴다.

## 결정

**우리는 앱의 API 클라이언트를 손으로 쓰지 않고 `contracts/openapi/` 의 명세에서
생성한다.** iOS 는 `swift5`, Android 는 `kotlin` 생성기를 쓰고, 생성물은 커밋하지
않는다.

## 검토한 대안

| 선택지 | 채택하지 않은 이유 |
| --- | --- |
| 손으로 쓴 클라이언트 (URLSession 직접 호출) | 두 앱이 갈리는 것을 막을 장치가 없다. ADR 0002 의 검증 항목이 사람의 주의력에만 걸린다 |
| 서버 응답을 `[String: Any]` 로 받아 화면에서 꺼내 쓰기 | 명세가 바뀌어도 컴파일이 통과한다. 계약을 강제하는 지점이 사라진다 |
| 생성물을 커밋해서 도구 의존을 없애기 | 명세와 생성물이 어긋난 상태가 저장소에 남는다 (`contracts/README.md`). 어느 쪽이 정본인지 흐려진다 |
| 다른 생성기(Swagger Codegen 등)로 갈아타기 | 서버가 이미 이 도구를 쓴다. 둘을 쓰면 같은 명세에서 두 벌의 해석이 나온다 |

## 결과

**좋아지는 것**

- 명세에서 필드가 사라지거나 타입이 바뀌면 **앱이 컴파일되지 않는다.** 서버 쪽
  `scene_api_spring_lib` 와 같은 장치가 앱에도 생겼다.
- 검색 규칙을 앱이 다시 구현하지 않는다. `GET /contents` 와 `GET /places` 에 같은
  `q` 를 넣기만 하면 두 탭이 채워지고(MZ2AZ-167), 그 대칭은 서버 통합 테스트가 지킨다.
- Android 는 생성기 이름만 바꾸면 된다.

**나빠지는 것 / 감수하는 비용**

- **`openapi_tools_generator_bazel` 이 유지보수자를 구하고 있다.** `MODULE.bazel` 이
  이미 적어 둔 위험이며, 이 ADR 로 승격한다. 완화책은 하는 일이 단순하다는 점이다 —
  "JAR 을 받아 실행" 이라 방치되면 `tools/bazel/defs/` 에 같은 것을 직접 써도 부담이 작다.
- **생성물을 그대로 `swift_library` 에 넣을 수 없다.** 생성기가 소스 아닌 파일
  (`README.md`·`Cartfile`·`project.yml`)을 같이 내고, 걸러서 디렉터리로 넘겨도
  rules_swift 가 오브젝트 파일 이름을 맞추지 못한다. `tools/bazel/defs/merge_tree_sources.bzl`
  이 그것을 메우며, 근거는 그 파일 머리말에 적었다. **대가는 진단 메시지의 줄 번호가
  합친 파일 기준이 된다는 것**이다.
- 생성 코드의 이름이 앱과 부딪힐 수 있다. 실제로 명세의 `Scene` 모델이 SwiftUI 의
  `Scene` 과 부딪혀 `SwiftUI.Scene` 으로 한정해야 했다.

**후속 작업**

- Android 모듈이 생길 때 `kotlin` 생성기 타깃 추가.
- 서버 주소가 지금은 소스에 있다(`http://localhost:8081/v1`). 배포 환경이 생기면
  네이버 지도 키와 같은 방식(빌드 시점 주입)으로 옮긴다.

## 검증

- **명세를 고치면 앱이 깨지는가.** 필드 하나를 지우고 `just check` 가 빨간불이 되는지
  확인한다. 초록이면 이 결정이 의도한 장치가 동작하지 않는 것이다.
- **두 앱이 같은 타입을 쓰는가.** Android 가 붙은 뒤, 같은 엔드포인트에 대해 두 앱의
  호출 코드가 같은 모양인지 본다 — 다르면 생성기 설정이 갈린 것이다.
- **도구가 살아 있는가.** 반년마다 `openapi_tools_generator_bazel` 의 최근 커밋을
  확인한다. 멈춰 있고 Bazel 이나 생성기 버전이 올라가 깨지면, 위에 적은 대로
  `tools/bazel/defs/` 로 옮긴다.
