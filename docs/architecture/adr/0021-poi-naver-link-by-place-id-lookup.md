# ADR 0021: 편의시설 네이버 링크는 장소 번호로 — 링크용 검색만 비공식으로 되살린다

## 배경

[0020](./0020-poi-card-public-data-and-naver-link.md) 은 베타 전에 네이버 비공식 호출을 모두 내리고 「네이버에서 아무것도
가져오지 않는다」고 정했다. 편의시설의 네이버 링크는 앱이 만드는 **이름 검색 화면**(`map.naver.com/p/search/<이름> <시군구>`)이
됐다.

써 보니 그 링크가 약하다(2026-10-09, 권호). 같은 구에 같은 이름이 여럿이면 함께 뜨고, 사용자는 검색 결과에서 그 가게를 다시
골라야 한다. 0020 이전에는 그 가게의 네이버 장소 화면으로 바로 갔다. 그것은 미리 모아 둔 자료가 아니었다 — 편의시설을 열 때마다
서버가 그 자리에서 네이버를 찾아본 것이다. 백업(2026-10-04)에는 13 곳뿐이라 백업으로는 되살릴 수 없다.

## 결정

**편의시설의 네이버 링크는 그 가게의 장소 화면(`https://map.naver.com/p/entry/place/{번호}`)으로 한다. 장소 번호를 찾으려고
네이버 비공식 검색 하나만 다시 부른다.** 0020 의 나머지(카드는 우리 자료로, 사진·평점·영업시간은 가져오지 않는다)는 그대로다.

- **검색만 부른다.** 검색 결과(장소 번호·이름·주소·좌표)는 우리 편의시설과 같은 곳인지 고르는 데만 쓰고(`NaverMatcher`, 규칙 그대로)
  응답으로 내보내지 않는다. 사진·평점·영업시간을 주는 **상세 호출은 하지 않는다.**
- **저장은 장소 번호 하나.** `poi_naver` 에 번호만 채운 행을 둔다. 찾았든 「없음」이든 저장해 다시 묻지 않는다. 「못 받음」(타임아웃·차단)은
  저장하지 않는다.
- **언제:** 편의시설 상세(`GET /pois/{poiId}`)를 열 때, 저장된 것이 없으면 그때 한 번. 한 번 부를 때 0.7 초까지만 기다린다(재검색까지
  최대 두 번 — 계약 「최대 1.5 초」). 목록·지도·챗봇은 부르지 않는다 — 호출 수는 상세를 연 횟수를 넘지 않는다.
- **못 찾으면 버튼이 없다.** 네이버에 없거나, 꺼졌거나 막혔거나 느리면 `naverPlaceUrl` 이 비고, 앱은 네이버 지도 버튼을 **보이지
  않는다** — 이름 검색 화면으로 넘기지 않는다(엉뚱한 가게로 보내느니 없는 편이 낫다, 권호 2026-10-09). 「못 받음」은 저장하지 않으므로
  다음에 열 때 다시 찾는다. 네이버가 막으면(403·429) 60 초 동안 묻지 않는다.
- **스위치가 둘이다.** `scenetrip.naver.link-lookup.enabled`(검색, 켬)와 `scenetrip.naver.enabled`(상세·카드, 끔). 문제가 되면
  앞의 것만 끈다.
- 카드 창구(`/pois/{poiId}/card`·`/pois/cards`, deprecated)는 표를 보지 않고 늘 「못 찾음」·`pending` 이다 — 표에 쌓이는 장소 번호를
  카드로 내주지 않는다.
- 계약: `PoiDetail.naverPlaceUrl`(선택) — scene-api 1.6.0. 앱: MZ2AZ-374.

## 검토한 대안

| 선택지 | 채택하지 않은 이유 |
| --- | --- |
| 이름 검색 링크 유지(0020), 또는 못 찾은 곳만 검색 링크로 | 검색 결과에서 사용자가 그 가게를 다시 골라야 한다. 같은 이름이 여럿이면 엉뚱한 곳을 누른다 |
| 검색어를 다듬기(도로명·동 붙이기) | 결과 맨 위가 그 가게일 확률은 오르지만 여전히 검색 화면이다. 사용자 경험이 0020 이전보다 못하다 |
| 백업 CSV 로 되살리기 | 13 곳뿐이다 |
| 네이버 공식 지역검색 API | 장소 번호를 주지 않는다(0011 실측 4%) |
| 상세(카드)까지 되살리기 | 사진·평점·영업시간은 네이버와 가게·방문자의 것이다 — 0020 의 이유가 그대로다. 링크만으로 「그 가게로 바로」는 이룬다 |

## 결과

**좋아지는 것**

- 편의시설의 네이버 버튼이 그 가게 화면으로 바로 간다(찾은 곳).

**나빠지는 것**

- **비공식 호출이 다시 있다.** 네이버 지도 웹의 내부 주소를 그 페이지인 척 부른다 — 이용 약관 위반 소지가 남는다. 0020 보다 부르는 양과
  가져오는 것은 적지만(검색 한 번, 번호 하나) 없지는 않다. 정식 출시 전에 다시 본다.
- 처음 여는 편의시설은 상세 응답이 검색만큼(보통 0.3 초) 늦다.
- 네이버에 없는 편의시설과, 네이버가 막은 동안 처음 연 편의시설에는 네이버 버튼이 없다 — 화면은 깨지지 않는다.
- 0020 의 「네이버에서 아무것도 가져오지 않는다」는 더 이상 참이 아니다. MZ2AZ-355 를 요청한 정승길에게 MZ2AZ-374 로 알렸다.

## 검증

- 서버: 상세 호출이 어떤 경로로도 나가지 않는다(`scenetrip.naver.enabled=false` 에서 `detail` 은 늘 실패). 링크 스위치를 끄면
  검색도 나가지 않는다. 카드 창구는 표에 장소 번호 행이 있어도 「못 찾음」·`pending` 이다.
- 로컬에서 편의시설 몇 곳을 열어 `naverPlaceUrl` 이 그 가게 화면으로 가는지 본다. 두 번째 열 때는 네이버를 부르지 않는다.
- 운영: 막힘(403·429) 로그가 잦으면 링크 스위치를 끈다.
