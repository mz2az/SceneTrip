# ADR 0026: API e2e 는 로컬 kind 의 별도 인스턴스에서, 바깥 서비스는 시험이 띄운 가짜 HTTP 로

## 배경

ADR 0005 는 `e2e` 레인을 「첫 타깃이 들어올 때 정한다」 고 미뤘다. 2026-10-18 사용자가 기능 전체에 대한 e2e 를 요청했다.
지금 시험은 단위(DB 가짜)·통합(실제 DB, 바깥 API 는 `@MockitoBean`)까지라, **컨테이너 이미지·쿠버네티스 설정·비밀값 주입·
진짜 HTTP 서버·바깥 API 와의 실제 HTTP 왕복·MinIO 서명 주소**를 본 시험이 없다. 바깥 서비스(카카오 길찾기·LLM·네이버·구글/애플)는
유료이거나 비공식이라 시험이 진짜로 부를 수 없다. 사용자 결정: API e2e 먼저 · 바깥은 가짜 · 로컬 kind
([api-e2e.md](../../project/plans/api-e2e.md)).

## 결정

우리는 API e2e 를 **로컬 kind 에 평소 서버와 따로 띄운 `scene-api-e2e`**(같은 이미지·같은 DB) 에 대고 돌리며, 바깥 서비스는
**시험 프로세스가 호스트에 띄운 가짜 HTTP 서버**(0.0.0.0:18900, 파드는 `host.docker.internal`)로 주소만 바꿔 대체한다. 시험은
파이썬 표준 라이브러리 `py_test`(`//tests/e2e:api_e2e_test`, 태그 `e2e` · `local` · `no-sandbox` · `external`)이고 **CI 에서 돌리지 않는다**.

## 검토한 대안

| 선택지 | 채택하지 않은 이유 |
| --- | --- |
| 평소 로컬 scene-api 에 대고 돈다 | 평소 서버의 바깥 주소(네이버 진짜 호출)·가입 강제(꺼짐)를 시험용으로 바꿔야 한다. 개발 중 쓰는 서버가 시험 때마다 달라진다 |
| 가짜를 클러스터 안 파드로 | 시험이 답을 바꾸고 받은 요청을 보려면 가짜와 시험 사이에 또 통신이 필요하다. 시험 프로세스가 직접 띄우면 함수 호출로 끝난다 |
| 바깥 서비스를 진짜로 부른다 | 비용·호출 한도, 답이 바뀌어 깨진다. 진짜 연결은 배포 뒤 스모크(`navigation-smoke` 등)가 본다 |
| CI 에서 kind 를 띄워 매 PR 마다 | ADR 0005 가 통합 레인에서 기각한 이유(기동 시간)가 더 크게 든다 — 이미지 빌드·kind 적재까지. 나중에 핵심 흐름만 골라 다시 본다 |
| JVM 시험(RestAssured 등) | 새 의존성이 든다. 파이썬 표준 라이브러리로 HTTP·RSA 서명(pow)·가짜 서버가 다 된다 |

## 결과

**좋아지는 것**

- 배포 묶음(이미지·설정·비밀값)이 붙어 도는지를 PR 전에 본다. 바깥 API 클라이언트가 보내는 주소·헤더·JSON 이 실제로 검증된다.
- 로그인이 진짜 `POST /auth/google` 경로를 탄다(가짜 JWKS).

**나빠지는 것 / 감수하는 비용**

- CI 가 돌리지 않으니 사람이 `just e2e-up` · `just test-e2e` 를 돌려야 한다.
- 평소 로컬 데이터와 DB 를 같이 쓴다 — 시험은 자기가 만든 행만 보고, 시험 행은 남는다(로컬 전용).
- 가짜의 답은 우리가 아는 바깥 API 모양이다 — 바깥이 모양을 바꾸면 e2e 는 모르고 스모크가 안다.

**후속 작업**

- 진짜 trip-guide + 가짜 LLM(모델 주소를 환경변수로), 애플 로그인 전체 흐름 — 2차.
- 앱 화면 e2e(iOS·Android).

## 검증

e2e 가 단위·통합이 못 잡는 실패(설정·비밀값·직렬화·바깥 HTTP 모양)를 한 번이라도 잡는가. 석 달 동안 하나도 못 잡으면 범위를 핵심 흐름으로
줄인다.
