# ADR 0008: 안드로이드 화면을 Jetpack Compose 로 짓는다

## 배경

[ADR 0002](0002-product-stack-spring-python-native-mobile.md) 가 모바일을 **네이티브
두 벌**로 정했다. 크로스플랫폼을 쓰지 않는 대신 **두 앱이 어긋나지 않게 하는 것**을
스스로 검증 항목으로 걸었다. 그 대가를 매일 치르는 자리가 UI 다.

iOS 검색 탭이 먼저 완성됐다. 그 과정에서 버그 열두 건을 잡았는데, 되짚어 보면 거의
전부가 코드 결함이 아니라 **"이 화면이 무엇을 해야 하는가" 를 몰랐던 것**이었다 —
첫 화면에 「인기」를 붙일지, 칩이 지도 핀도 좁힐지, 첫 진입이 서울인지 남한 전체인지.
그 답들은 확정 동작 문서로 굳었고, 안드로이드는 그것을 옮기기만 하면 된다.

옮길 방법이 둘이다.

- **뷰 + XML** — 안드로이드의 오래된 방식. 레이아웃을 XML 로 적고 코드에서 찾아 쓴다.
- **Jetpack Compose** — 코틀린 코드로 화면을 선언한다. SwiftUI 와 같은 계열이다.

새 의존성을 `MODULE.bazel` 에 더하는 일이라 (CLAUDE.md §9) 가볍게 정할 수 없다.

## 결정

**Jetpack Compose 를 쓴다.**

가장 큰 이유는 취향이나 최신성이 아니라 **ADR 0002 가 스스로 건 검증 항목**이다.
같은 화면을 두 언어로 만들 때, 두 코드의 **구조가 같으면 어긋남이 눈에 보인다.**

    // iOS                              // Android
    @State private var committed = ""    var committed by remember { mutableStateOf("") }
    VStack { ... }                       Column { ... }
    ForEach(places) { PlaceRow($0) }     items(places) { PlaceRow(it) }

뷰 + XML 로 같은 화면을 만들면 RecyclerView · Adapter · ViewHolder · DiffUtil 이
붙는다. 코드가 두세 배가 되는 것보다 나쁜 것은 **한쪽에만 있는 개념이 생긴다**는
점이다. iOS 코드를 읽고 안드로이드 코드를 고치는 일이 번역이 되고, 번역에는 오역이
따른다. 확정 동작 문서 하나로 두 앱을 맞추려는 전략이 거기서 새기 시작한다.

지도만 예외다. 네이버가 Compose 용 지도를 내놓지 않아 `MapView` 를 `AndroidView` 로
감싼다. iOS 가 `UIViewRepresentable` 로 하는 것과 **같은 성격의 예외**라, 이 자리
역시 두 앱이 대칭이다.

## 결과

**좋아지는 것**

- iOS 에서 확정한 화면 규칙을 구조를 유지한 채 옮긴다. 실제로 검색 탭 뼈대(두 탭 ·
  「인기 N」 표기 · 칩이 목록과 지도를 같이 좁힘 · 첫 화면 작품 탭에서만 민 핀)가
  같은 모양의 코드로 옮겨졌다.
- 화면 상태가 코틀린 값 하나로 모인다. XML 과 코드에 나뉘어 있지 않으므로 "지금 이
  화면이 무슨 상태인가" 를 한 곳에서 읽는다.

**치르는 대가**

- `MODULE.bazel` 이 길어졌다. Compose 아티팩트는 멀티플랫폼이라 이름 하나가 둘이고
  (`ui` 와 `ui-android`), 짝까지 전부 못 박지 않으면 해석이 멈춘다.
- **컴파일러 플러그인이 필요하다.** `@Composable` 함수는 평범한 코틀린 함수로
  컴파일되지 않는다. 플러그인을 빠뜨리면 **컴파일은 되는데 화면이 갱신되지 않는다** —
  조용히 잘못 도는 쪽이라 빠뜨리면 찾기 어렵다. 그래서 모듈 안이 아니라
  `//tools/bazel/kotlin` 에 한 벌만 둔다.
- 플러그인 버전이 **Kotlin 컴파일러 버전과 같아야 한다.** `rules_kotlin` 을 올릴 때
  둘을 함께 올려야 하고, 어긋나면 컴파일러가 플러그인을 거부한다.
- ktlint 의 `function-naming` 이 `@Composable` 의 대문자 이름을 거부한다. 규칙을
  끄지 않고 `.editorconfig` 에서 `@Composable` 만 예외로 뺐다.

**되돌리려면**

화면 코드를 다시 쓰는 일이다. 지금은 검색 탭 뼈대뿐이라 비용이 작지만, 탭이 늘수록
커진다. 되돌릴 이유가 생긴다면 그것은 성능일 텐데, 우리 화면은 목록과 지도라
Compose 가 못 버틸 규모가 아니다.

## 대안

**뷰 + XML.** Bazel 설정이 지금 그대로면 되고 새 의존성이 없다. 안드로이드 개발자가
가장 많이 아는 방식이기도 하다. 그러나 위에서 적은 대로 **두 앱의 구조가 갈린다** —
ADR 0002 가 네이티브 두 벌을 택하며 감수하기로 한 비용을 필요 이상으로 키운다.

**크로스플랫폼(Compose Multiplatform 등)으로 한 벌만 만든다.** ADR 0002 가 이미
기각했다. 이 ADR 은 그 결정을 다시 열지 않는다 — **iOS 와 안드로이드는 코드를
공유하지 않는다.** 공유하는 것은 계약과 확정 동작 문서다.
