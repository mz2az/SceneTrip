# ADR 0011: 편의시설 카드는 네이버 장소의 비공식 호출로 채운다 — 데모 한정

> 0009·0010 은 길찾기 PR(MZ2AZ-296)에 있다. 번호가 비어 보이면 그쪽이 아직 안 합쳐진 것이다.

## 배경

경로 탭의 편의시설 핀을 누르면 카드가 뜬다 — 사진·영업시간·별점·리뷰 수. 우리 자료
(TMAP 수집, `poi` 표)에는 이 중 아무것도 없다. 승길이 확인했다: 리뷰·별점 0/40, 갱신
시점 0/40, 영업시간 25%. 사진과 평점은 **네이버 장소에서만** 온다.

네이버가 개발자에게 여는 공식 지역검색 API 는 장소 **id 를 주지 않는다**(2,000 건 실측 —
`link` 가 네이버 장소 URL 인 경우 4%). id 가 없으면 사진·평점이 있는 상세 페이지에 닿을
수 없다. 프로토타입(`apps/navi_proto`, 승길)은 그래서 네이버 지도 웹페이지가 자기 화면을
그리려고 부르는 내부 주소 둘을, 그 페이지인 척하는 헤더로 불렀다.

```
bff-gateway.place.naver.com/graphql          검색 → id · 이름 · 좌표
map.naver.com/p/api/place/summary/{id}       상세 → 사진 · 영업시간 · 별점 · 리뷰 수
```

데모에 이 카드가 필요하다. 그리고 이 방식은 정식 서비스에 쓸 수 없다.

## 결정

**데모 동안 이 비공식 호출을 서버에서 쓴다.** 단, 다음을 지킨다.

- **한 클래스에 가둔다** — `NaverPlaceClient`. 네이버와 말하는 코드는 여기뿐이고, 절대
  던지지 않는다. 카드가 뜨는 화면이 바깥 사정으로 죽지 않는다.
- **스위치가 있다** — `scenetrip.naver.enabled`. 막히거나 형식이 바뀌면 내린다. 그러면
  카드는 「꺼져 있음」이 되고 핀·목록·상세(우리 자료)는 그대로 산다.
- **결과는 표에 둔다** — `poi_naver`. 한 곳은 한 번만 묻는다. 못 찾은 것도 저장해 다시 묻지
  않는다. 판정 규칙을 고치면 `rule_version` 을 올려 옛 판정을 무효화한다.
- **초당 3 건, 일꾼 하나.** 여럿 조회는 표에 있는 것만 주고 없는 것은 뒤에서 채운다. 막히면
  60 초 쉬고, 연속 세 번이면 스스로 내린다.
- **데모 동선은 미리 채운다.** 데모 중 호출을 0 에 가깝게.
- **사진은 URL 만.** 네이버 CDN 주소를 앱이 직접 그린다(핫링크). 파일을 받아 두지 않는다 —
  그건 저작권 복제다.

**정식 출시 전에 대체한다.** 대체를 정해야 하는 시점은 다음 중 먼저 오는 것이다.

- 검색 목록 화면에 사진이 필요해질 때 — 검색마다 30 건이면 호출이 자릿수가 달라진다.
- 스토어 제출 전.
- 네이버가 막거나 형식을 바꿔 스위치를 내린 채 한 주가 지날 때.

## 검토한 대안

- **네이버 공식 지역검색만 쓴다.** 이름·주소·전화·좌표까지는 되지만 id 가 없어 사진·평점에
  못 간다. 카드에서 사진을 빼면 되지만 데모의 「눌렀더니 뜬다」가 사라진다. 매칭(있나 없나)
  용도로는 여전히 쓸 수 있어 문을 닫진 않는다 — 실측 스크립트는 이것으로 쟀다.
- **카카오 로컬 검색.** 사진·평점·영업시간을 주지 않는다(8/13 확인).
- **앱에서 직접 부른다.** 프로토타입이 그랬다. 앱마다 흩어진 호출은 막혀도 모르고, 규칙을
  고칠 수 없고, 결과가 기기마다 따로 쌓인다. 서버 한 곳이 낫다 — 막혀도 스위치 하나.
- **사진을 우리 S3 로 복사.** 저작권. 가게와 방문자의 것이지 네이버 것도 아니다.
- **TMAP 상세 API(공식).** 영업시간 25%·홈페이지 12% 를 더 준다. 카드를 「우리 자료만」으로
  갈 때 보탤 수 있어, 대체안의 일부다.

## 결과

- 카드 API 둘(`GET /pois/{id}/card`, `GET /pois/cards`), 표 하나(`poi_naver`, V14), 클래스 넷
  (`NaverPlaceClient` · `NaverMatcher` · `PoiCardFetcher` · `PoiCardFiller`), 서비스 하나.
- 매칭 규칙은 프로토타입의 `match_ok` 를 옮기고 건물 좌표로 다시 확인했다(볼트
  「2026-09-03 네이버 매칭 거리 실측」). 시군구 재검색을 더해 +6~11p.
- 실측(2026-09-04, 강남): 단건 처음 530 ms, 표에서 5 ms. 다섯 곳 중 둘 찾음.
- 이 ADR 이 유효한 동안 `NaverPlaceClient` 밖에서 네이버 주소가 나타나면 안 된다.

## 검증

- 스위치를 내리면(`enabled=false`) 카드가 200 에 `found:false, why:"꺼져 있음"` 으로 오고 다른
  경로가 전부 산다 — 단위 테스트가 본다.
- `just poi-card-smoke` 가 배포된 서버에서 단건·표·여럿·일꾼을 흘려 본다. 호출 10 번 안쪽.
- 대체 시점의 조건 셋 중 하나가 오면 이 ADR 을 대체하는 새 ADR 을 쓴다. 그때까지 이 문서가
  「왜 비공식을 쓰고 있나」의 답이다.
