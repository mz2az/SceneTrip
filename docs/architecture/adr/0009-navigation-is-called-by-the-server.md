# ADR 0009: 길찾기는 서버가 부른다 — 유료 외부 API 의 키는 앱에 두지 않는다

## 배경

MVP 데모를 굴리려고 iOS 앱이 카카오 길찾기 API 를 직접 불렀다. REST 키가 앱 바이너리에
박혀 있었고(`Secrets.kakaoRestKey`), 계약의 `POST /navigation/next-leg` 는 서버가 `501` 을
돌려주고 있었다. 앱 코드 자신이 「스토어에 내기 전에 백엔드로 옮긴다」고 적어 뒀다.

멘토와의 논의에서 반론이 있었다 — 「특별히 백엔드에서 처리하지 않는다면 프론트에서
호출하는 것이 더 빠르다」, 「프론트에 API 키가 있어도 안전하게 암호화되어 있지 않냐」.
전자는 원칙으로서 맞다. 후자는 사실이 아니다 — 앱이 키를 **쓰려면 가지고 있어야** 하고,
기기 주인은 프록시로 나가는 요청 헤더(`Authorization: KakaoAK …`)를 그대로 읽는다.
암호화 강도의 문제가 아니라 구조의 문제다.

같은 앱에 네이버 지도 키도 박혀 있는데 그것은 그대로 둔다. 번들 ID 에 묶여 남이 못 쓰는
키다. **키의 종류가 기준이다.**

실측이 이관 근거 하나를 지웠다. 프로토타입 주석은 카카오 routing 을 「문서에 없는
엔드포인트」라 했는데 지금은 공식 문서에 있다 — 「막힐 수 있으니 서버로」는 근거가 아니다.

## 결정

우리는 **유료이거나 서버용으로 규정된 외부 API 는 서버가 부르고, 그 키는 서버에만 둔다.**
길찾기(카카오 대중교통·도보)가 첫 사례다. 앱은 우리 계약(`NextLeg`)만 본다.

기준은 셋이다. 하나라도 걸리면 서버다.

1. **유료·쿼터.** 카카오 길찾기는 무료 쿼터가 계정당 첫 앱 하나, 하루 1,000/1,000 건이고
   넘으면 종량 과금(10원/건)이다. 앱이 부르면 몇 건 나갔는지 서버가 모르고, 계약이
   요구하는 「여행 중 코스만·가입자만·한 구간씩」을 강제할 수 없다.
2. **키가 새면 쓸 수 있는 방어가 서버에만 있다.** 카카오는 REST 키 유출 대비책으로
   「호출 허용 IP 주소」를 제공한다. 고정 IP 에서만 걸 수 있는 장치라 앱에 키를 두면
   그 방어를 통째로 못 쓴다.
3. **두 벌이 한 벌이 된다.** iOS·Android 가 각자 카카오를 부르면 양 끝 도보 기우기 같은
   가공 로직을 두 번 짜고 두 번 유지한다. 서버에 두면 한 벌이고, 엔진을 T맵으로 바꿔도
   앱은 모른다.

앱에 둬도 되는 키는 **번들 ID·패키지명에 묶여 훔쳐도 못 쓰는 것**뿐이다 — 네이버 지도
SDK 키가 그렇다.

## 검토한 대안

| 선택지 | 채택하지 않은 이유 |
| --- | --- |
| 앱이 직접 부른다 (현상 유지) | 키가 앱에서 나간다. 쿼터·호출 통제를 서버가 못 한다. 실제로 카카오 데브톡에 키 유출로 쿼터가 소진된 문의가 있다 |
| 앱이 부르되 키를 난독화한다 | 헤더로 나가는 순간 읽힌다. 난독화는 시간을 벌 뿐이다 |
| 서버가 키만 발급해 준다 (토큰 중계) | 카카오 REST 키는 단일 정적 키라 위임 토큰이 없다. 결국 키 자체를 내주는 것과 같다 |
| 무조건 서버 (모든 외부 API) | 네이버 지도 타일까지 서버로 중계하면 지연과 비용만 는다. 번들 묶인 키는 앱에 둔다 |

## 결과

**좋아지는 것**

- 키가 저장소·앱 바이너리 어디에도 없다. 서버 Secret 하나.
- 호출 횟수를 서버가 센다. 계약의 통제(401·409·한 구간씩)가 실제로 강제된다.
- 가공 로직(양 끝 기우기, 뺄셈으로 도보 거리, 요금 범위 중간값)이 한 곳에 있고 테스트가 잠근다.
- 엔진 교체가 앱과 무관하다.

**나빠지는 것 / 감수하는 비용**

- 한 다리 더 건넌다. 우리 서버 왕복 수십 ms 가 카카오 왕복 수백 ms 위에 얹힌다.
  캐시로 되돌리려 했으나 카카오가 길찾기 응답 저장을 「실시간 호출만」이라 답해 뺐다.
- 서버가 외부 API 의 장애·쿼터를 떠안는다. 503 과 로그·메트릭이 그 자리다.
- 이 서비스의 첫 외부 HTTP·첫 Secret 이라 결정할 것이 많았다(`RestClient` 직접 생성,
  관측 두 겹, `secretKeyRef` + `optional`). 다음 클라이언트는 이 길을 따른다.

**후속 작업**

- 앱에서 `KakaoTransit.swift` 와 `kakao_rest_key` genrule 을 뺀다.
- 카카오 콘솔에 서버 IP 를 「호출 허용 IP」로 건다 — 원격 환경이 생길 때.
- 남용 방지(MZ2AZ-205) — 「한 계정이 하루 몇 번」.
- 네이버 지역검색·T맵 POI 키가 서버로 올 때 같은 기준을 적용한다.

## 검증

- 앱 바이너리와 저장소에 `KakaoAK` 나 REST 키 문자열이 없다 — 스토어 제출 전 확인.
- SigNoz 의 `http.client.requests{uri=/v2/routing/{kind}}` 로 대중교통/도보 호출 수가
  갈려 보인다. 쿼터(1,000/일)에 닿기 전에 안다.
- 503 `ROUTING_UNAVAILABLE` 이 로그에 429 로 찍히는 날이 오면 유료 전환이나 호출 억제를
  정한다 — 그때 이 ADR 의 「유료·쿼터」 근거가 실제 청구서로 확인된다.
- 다시 볼 때: 카카오가 앱용 키(번들 묶임)로 길찾기를 열면 기준 1·2 가 약해진다. 그때
  기준 3 만으로 서버를 유지할지 재검토한다.
