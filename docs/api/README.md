# API 문서

SceneTrip API 를 사용하는 쪽을 위한 안내: 인증, 페이지네이션, 오류 의미,
요청 제한, 버전 정책.

**명세는 여기가 아니라 [`contracts/`](../../contracts/README.md) 에 있습니다.**
이 디렉터리는 API 를 *어떻게 쓰는지* 설명하고, `contracts/` 는 API 를 *정의하며*
빌드 입력이 된다.

| 문서 | 목적 |
| --- | --- |
| [`auth.md`](./auth.md) | 인증·인가 모델 — 로그인은 없고, `X-Device-Id` 로 계정을 찾아 그 계정에 저장한다 |
| [`errors.md`](./errors.md) | 오류 형식과 상태 코드 의미 |
| [`scene-api-guide.md`](./scene-api-guide.md) | scene-api 사용 가이드 — 화면별 호출 패턴과 알려진 한계 |
| `<서비스>-guide.md` | 서비스가 늘면 같은 형태로 하나씩 |

**버전 정책은 여기 두지 않는다.** [`contracts/README.md`](../../contracts/README.md)
가 이미 규정한다 — 파괴적 변경은 메이저 버전을 올려 새 파일로 내고, 제자리 수정은
금지다. 같은 규칙을 두 곳에 적으면 한쪽만 고쳐져 어긋난다.

## 명세를 눈으로 확인하려면

```bash
just docs-api    # 명세를 펼친 단일 HTML 을 만들어 브라우저로 연다
```

`contracts/openapi/scene-api-v1.yaml` 을 3단 화면으로 펼친다 — 왼쪽 목차, 가운데 파라미터와
응답 필드, 오른쪽 예시 JSON. 검색과 딥링크가 있어 엔드포인트로 바로 갈 수 있다.

**네트워크 없이 열리는 파일 한 장(940KB)이다.** 렌더러와 명세를 페이지 안에 박아 넣어
서버도 인터넷도 필요 없다 — 그대로 남에게 보내도 열린다.

**생성물은 커밋하지 않는다.** 명세가 바뀌면 문서도 낡는데, 커밋해 두면 둘이 어긋난 상태가
저장소에 남아 어느 쪽이 맞는지 알 수 없게 된다. 명세만 진실로 두고 필요할 때 다시 만든다.

### 이 문서에 나오지 않는 것

**오류 코드 목록.** 명세는 오류 *형식*(`ApiError`)만 정의하고, `PLACE_NOT_FOUND` 나
`INVALID_BBOX` 같은 코드의 뜻은 [`errors.md`](./errors.md) 가 규정한다. 둘을 같이 봐야 한다.

그 밖의 것은 다 나온다 — enum 의 허용값(`Lang` 의 `ko`·`en`·`ja`·`zh-Hant`)도, `allOf` 로
물려받은 필드(`ContentDetail` 의 11개)도, 예시 JSON 도 실제로 렌더링되는 것을 확인했다.
