# 인증·인가

## 로그인은 구글·애플, 토큰은 JWT 다

비밀번호는 받지 않는다. 구글·애플 소셜 로그인만 있고, 우리 쪽 인증은 짧은 JWT 액세스
토큰과 일회용 리프레시 토큰이다 — [ADR 0018](../architecture/adr/0018-social-login-with-jwt.md).

> **서버 구현 상태** — 구글 로그인(가입 겸)·갱신·로그아웃·`/me`·탈퇴가 돈다
> ([MZ2AZ-331](https://mz2az.atlassian.net/browse/MZ2AZ-331) · [MZ2AZ-256](https://mz2az.atlassian.net/browse/MZ2AZ-256)).
> **애플 로그인(`/auth/apple`)은 아직 `501`** 이다 — 애플 개발자 설정이 준비된 뒤다. 서명 키
> (`SCENETRIP_AUTH_JWT_SECRET`)가 없는 환경은 서버가 로그인을 끈 채 뜬다. 설계와 앱이 할 일은
> [social-login.md](../project/plans/social-login.md) 에 있다.

로그인하지 않아도 대부분이 된다. 막혀 있는 것은 마켓 쓰기·여행 중 길찾기·가이드 챗봇뿐이다
([아래](#가입해야-넘는-벽)).

## 주체는 계정이다 — 헤더는 열쇠일 뿐이다

여기가 가장 자주 오해받는 자리다.

**저장의 주체는 `X-Install-Id` 가 아니라 그 값으로 찾아낸 계정(`app_user.id`)이다.**
헤더는 자물쇠를 여는 열쇠이지, 서랍 자체가 아니다.

```
X-Install-Id (설치 UUID)  →  user_device.install_uuid  →  app_user.id  →  저장
```

서버는 처음 보는 설치 UUID 를 받으면 **비회원 계정을 하나 만들어** 짝지어 두고, 그
뒤로는 같은 계정을 찾아 준다. 이 변환은 `UserStore` 안에서만 일어난다.

`app_user` · `user_device` 표는 `V8` 로 이미 들어와 있고, 장바구니(`saved_place`)·
코스·찜·마켓이 전부 계정을 주체로 저장된다.

### 앱이 하는 일은 설치 UUID 를 보내는 것뿐이다

설치 UUID 를 계정으로 바꾸는 일은 서버 안에서만 일어난다. 앱은 계정 id 를 모른다.

### 왜 둘을 같은 값으로 두지 않았나

설치 UUID 는 사람이 아니라 **그 설치본**을 가리킨다. 앱을 지웠다 깔면 새로 생기는데,
그것이 곧 주체이면 그 사람의 장바구니와 코스가 통째로 끊긴다.

한 겹 떼어 두면 로그인이 붙을 때 `user_device` 가 가리키는 곳만 계정 쪽으로 바꿔
달면 되고, **데이터는 한 줄도 움직이지 않는다.**

## 헤더를 요구하는 곳

장바구니 · 코스 · 찜 · 마켓이 **전부** `X-Install-Id` 를 필수로 받는다. 조회만 하는
검색·지도 API 는 받지 않는다 — 누가 부르든 결과가 같기 때문이다.

```
POST /v1/cart/items
X-Install-Id: 9f2c8a10-4b3e-4d21-9c7f-1a2b3c4d5e6f
Content-Type: application/json

{ "placeId": 7, "sourceContentId": 42 }
```

없거나 UUID 형식이 아니면 `400 MISSING_INSTALL_ID` 다.

## X-Install-Id 는 무엇인가

**앱이 최초 실행 때 한 번 만들어 보관하는 UUID** 다. 서버가 발급하지 않는다.

가리키는 것은 기기가 아니라 **그 설치본**이다. 같은 폰이라도 앱을 지웠다 깔면 새 값이
된다. 헤더는 원래 `X-Device-Id` 였는데, 그 이름 때문에 "폰을 바꿨는데 왜 데이터가
없죠" 를 버그로 오해하게 되어 배포 전에 표 이름(`user_device.install_uuid`)에 맞춰
바꿨다(MZ2AZ-328).

| 항목 | 값 |
| --- | --- |
| 만드는 쪽 | 앱 (최초 실행 시 1회) |
| 형식 | UUID |
| 보관 | iOS 키체인 · Android EncryptedSharedPreferences 권장 |
| 수명 | 앱을 지우면 사라진다 |

**앱 저장소가 아니라 키체인에 두는 것을 권한다.** 이 값을 잃으면 서버는 그 사람을 처음
보는 것으로 여겨 **새 계정을 만든다.** 이전 계정은 그대로 남아 있지만 그것을 가리킬
열쇠가 없어 사용자는 장바구니와 코스를 잃은 것처럼 느낀다.

UUID 는 **추측할 수 없어야 한다.** 순번이나 기기 식별자(IDFV·ANDROID_ID)에서 파생하지
말고 안전한 난수로 만든다.

## 무엇을 보장하지 않는가

**설치 UUID 는 인증이 아니다.** 남의 `X-Install-Id` 를 알면 그 **비회원** 계정의 장바구니와
코스를 읽고 고칠 수 있다. 막을 방법이 없다 — 헤더 값 하나가 전부이기 때문이다.

가입한 계정은 다르다. 토큰 없이 설치 UUID 만 오면 `401 SESSION_REQUIRED` 다
([아래](#로그인하면)).

그래서 **민감한 것을 담지 않는다.** 지금 담기는 것은 공개 장소의 ID 와 사용자가 붙인
코스 이름 정도이고, 그것이 새어도 피해가 없다. 이 전제가 깨지는 기능(개인 메모, 결제)이
들어오면 그때는 실제 로그인이 선행 조건이다.

## 가입해야 넘는 벽

다섯 동작만 `401 SIGN_IN_REQUIRED` 로 막혀 있다.

- 마켓에 올리기 · 담기 · 좋아요 · 내리기
- 여행 중 길찾기

나머지는 계정 없이 다 된다 — 검색하고, 장바구니에 담고, 작품을 찜하고, 코스를 만들어
여행을 시작하는 데까지 가입이 필요 없다. 로그인 벽을 앞에 세우면 사람들이 앱을 써 보기도
전에 나간다.

마켓을 막은 이유는 비회원이 올린 뒤 앱을 지우면 그 코스를 아무도 내릴 수 없어서다.
길찾기를 막은 이유는 다르다 — 종량제 API 라 호출마다 돈이 나가는데, 계정이 없으면 누가
얼마나 썼는지 셀 수가 없다.

판정은 `app_user.registered_at` 한 칸이 전부다. 비회원과 가입 사용자가 같은 표를
쓰고, 가입해도 행이 새로 생기지 않는다.

가입은 `/auth/google` · `/auth/apple` 이 `registered_at` 을 채우는 것이다. 로그인한 앱은
토큰을 붙여 이 벽을 넘는다.

## 로그인하면

**계정 행과 데이터의 소속은 그대로다.** 이 설치본의 비회원 계정에 구글·애플 신분이 붙고
`registered_at` 이 채워질 뿐이다.

```
비회원      설치 UUID → 계정 → 데이터
로그인 후    설치 UUID → 계정 → 데이터        (같은 계정, registered_at 만 채워진다)
            (provider, sub) ↗
```

"로그인 시점에 장바구니를 계정으로 옮기는" 승계 작업이 **필요 없다.** 이미 계정에 붙어 있기
때문이다. 옮기는 것은 그 소셜 계정이 **다른 설치본에서 이미 가입해 있을 때**뿐이다 — 이
설치본의 비회원 데이터를 그 계정으로 자동으로 합친다(MZ2AZ-256).

로그인한 앱은 요청마다 **`X-Install-Id` 와 `Authorization: Bearer` 를 둘 다** 보낸다. 서버가
계정을 정하는 순서:

1. 토큰이 있으면 토큰의 계정. 만료면 `401 ACCESS_TOKEN_EXPIRED` → 앱이 `/auth/refresh` 후 재시도
2. 없으면 설치 UUID 로 찾은 계정 — 그것이 **가입 계정이면 `401 SESSION_REQUIRED`**

로그아웃(`/auth/sign-out`)하면 그 설치본은 **새 비회원 계정**으로 바뀐다. 가입 계정을 계속
가리키면 설치 UUID 만으로 그 계정에 닿으려 하게 되기 때문이다.

## 그 밖에

**요청 제한(rate limit)이 없다.** v1 은 로컬·내부 환경에서만 돌기 때문이다. 외부에
노출하기 전에 반드시 붙여야 하며, 그때 `429` 와 대응 코드를 [errors.md](./errors.md)
에 더한다.

**CORS 설정이 없다.** 소비자가 네이티브 앱이라 브라우저 출처 검사가 걸리지 않는다.
웹 클라이언트가 생기면 그때 정한다.
