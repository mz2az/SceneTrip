# 오류 형식과 상태 코드

SceneTrip 의 모든 HTTP API 가 같은 오류 형식을 쓴다. 정의는
[`contracts/openapi/scene-api-v1.yaml`](../../contracts/openapi/scene-api-v1.yaml) 의
`ApiError` 스키마가 정본이고, 이 문서는 **각 코드가 무슨 뜻이며 클라이언트가 무엇을
해야 하는지**를 적는다.

## 형식

```json
{
  "code": "PLACE_NOT_FOUND",
  "message": "장소를 찾을 수 없습니다: 9999",
  "traceId": "0af7651916cd43dd8448eb211c80319c"
}
```

| 필드 | 필수 | 용도 |
| --- | --- | --- |
| `code` | 예 | **기계가 분기하는 값.** 클라이언트 로직은 이것만 보고 판단한다 |
| `message` | 예 | 사람이 읽는 설명. **사용자에게 그대로 보여 주지 않는다** |
| `traceId` | 아니오 | 이 요청의 추적 ID. SigNoz 에서 같은 값으로 조회한다 |

**`message` 를 화면에 그대로 띄우지 않는다.** 서버 사정을 설명하는 문구라 사용자에게
쓸모가 없고, 문구가 바뀌면 화면도 흔들린다. 사용자에게 보일 문구는 `code` 를 보고
클라이언트가 고른다.

**`traceId` 는 문의·버그 리포트에 붙인다.** 이 값이 있으면 그 요청 하나의 서버 로그를
바로 찾을 수 있다. 없으면 시간대로 뒤져야 한다.

## 상태 코드

| 코드 | 언제 | 클라이언트가 할 일 |
| --- | --- | --- |
| `400` | 파라미터가 규칙에 맞지 않음 | **재시도하지 않는다.** 요청을 고쳐야 한다 |
| `404` | 대상이 없음 | 목록으로 돌아가거나 빈 상태를 보여 준다 |
| `401` | 가입해야 할 수 있는 동작 | 가입을 권하는 화면으로 보낸다 |
| `403` | 남의 것을 고치거나 지우려 함 | 그 동작 버튼을 애초에 보이지 않게 한다 |
| `409` | 이미 있는 것을 또 만들려 함 | 충돌 안내를 띄운다 (예: "이미 저장된 장소입니다") |
| `500` | 서버 결함 | 재시도 가능. `traceId` 를 남긴다 |
| `501` | 아직 구현되지 않은 경로 | **그 화면을 아직 만들지 않는다.** 명세에 자리만 잡힌 상태다 |

`401`·`403`·`501` 은 코스·마켓 API([MZ2AZ-199](https://mz2az.atlassian.net/browse/MZ2AZ-199))와
함께 계약에 들어왔다. **아래 코드 목록에는 아직 없다** — 그 코드를 내는 핸들러가
구현되는 커밋에서 함께 추가한다. 이 문서가 "구현된 것" 만 적는다는 규칙(맨 아래
상자)을 지키기 위해서다.

`401` 이 붙는 자리는 넷뿐이다 — 마켓 좋아요, 마켓에서 담기, 마켓에 올리기, 여행 중
길찾기. 검색·장바구니·작품 찜·코스 만들기는 **계정 없이 다 된다.** 로그인 벽을 앞에
세우면 사람들이 앱을 써 보기도 전에 나가기 때문이다.

지금은 가입할 방법 자체가 없어(로그인 스토리 8/23 주차) 이 넷은 아무도 통과하지
못한다. 계약에 자리만 잡아 둔 상태다.

**목록이 비는 것은 오류가 아니다.** 검색 결과가 없으면 `200` 에 `items: []` 이고
`total: 0` 이다. `404` 는 **경로에 지정한 대상**이 없을 때만 쓴다.

## 코드 목록

### 파라미터 (`400`)

| `code` | 뜻 |
| --- | --- |
| `INVALID_PARAMETER` | 파라미터가 명세의 제약을 어겼다 — 길이·범위·형식·enum 값. 어느 파라미터인지는 `message` 에 있다 |
| `INVALID_BBOX` | `bbox` 형식이 틀렸다. `minLng,minLat,maxLng,maxLat` 순서의 숫자 4개여야 한다 |
| `CONFLICTING_AREA_FILTER` | `bbox` 와 `radiusMeters` 를 함께 보냈다. 영역 조건은 하나만 쓴다 |
| `INVALID_SORT` | `sort=distance` 인데 기준점(`lat`·`lng`)이 없다 |
| `INCOMPLETE_ORIGIN` | `lat` 과 `lng` 중 하나만 보냈다. 둘은 짝이다 |
| `MISSING_DEVICE_ID` | `X-Device-Id` 헤더가 없거나 UUID 형식이 아니다. 장바구니·코스·찜·마켓이 전부 이 헤더를 요구한다 |
| `UNKNOWN_COURSE_ITEM` | 편집 완료(`PUT /courses/{courseId}`)가 그 코스에 없는 항목 `id` 를 가리켰다. 이미 지워졌거나 남의 코스 것이다 — **새로 담는 장소라면 `id` 를 아예 비워야 한다** |

### 대상 없음 (`404`)

| `code` | 뜻 |
| --- | --- |
| `CONTENT_NOT_FOUND` | 그 `contentId` 의 작품이 없다 |
| `PLACE_NOT_FOUND` | 그 `placeId` 의 장소가 없다 |
| `CART_ITEM_NOT_FOUND` | 장바구니에 그 장소가 담겨 있지 않다 |
| `COURSE_NOT_FOUND` | 그 `courseId` 의 코스가 없다. **남의 코스도 여기에 해당한다** — 있다는 사실 자체를 알려 주지 않는다 |
| `ENDPOINT_NOT_FOUND` | **경로 자체가 없다.** 명세에 없는 주소를 불렀다 |

앞의 셋과 `ENDPOINT_NOT_FOUND` 는 뜻이 다르다. 앞의 셋은 "경로는 맞는데 그 id 의 대상이
없다" 이고, 마지막은 "그런 주소가 아예 없다" 다. 후자는 대개 **API 버전 접두사를 빠뜨렸거나
경로에 오타가 난 경우**다 — 명세의 `servers.url` 을 확인한다.

### 충돌 (`409`)

| `code` | 뜻 |
| --- | --- |
| `DUPLICATE_CART_ITEM` | 이미 담긴 장소를 또 담으려 했다 |
| `COURSE_SHORTER_THAN_PROGRESS` | 여행 중인 코스를 지금 걷고 있는 일차보다 짧게 줄이려 했다. 3일차를 걷는 중이면 2일 코스로 만들 수 없다 |

### 서버 결함 (`500`)

| `code` | 뜻 |
| --- | --- |
| `INTERNAL_ERROR` | 서버가 요청을 처리하지 못했다. 재시도해도 된다 |

`500` 의 `message` 는 언제나 같은 문구다. 예외 종류나 스택 트레이스를 응답에 흘리지
않는다 — 내부 구조가 드러나고, 클라이언트가 그것으로 할 수 있는 일도 없다. 원인은
서버 로그에만 남는다.

## 이 목록을 늘릴 때

**코드를 늘리기 전에 기존 코드로 표현되는지 본다.** 코드가 많아질수록 클라이언트의
분기가 늘고, 대부분의 분기는 결국 같은 화면을 띄운다.

새 코드를 더하면 세 곳을 함께 고친다 — 명세의 `ApiError` 설명, 이 문서, 그리고 그
코드를 내는 핸들러. `AGENTS.md` §10 이 규정한 대로 **코드와 문서가 어긋나면 같은
커밋에서 고친다.**

기존 코드의 **뜻을 바꾸는 것은 파괴적 변경**이다. 클라이언트가 그 값으로 분기하고
있기 때문이다. 새 코드를 더하는 것은 파괴적이지 않다 — 클라이언트는 모르는 코드를
기본 처리로 넘기면 된다.

> [!note] 전부 구현됐다
> 위 코드는 모두 `services/scene-api` 의 `ApiExceptionHandler` 하나에서 나온다.
> 코드를 늘릴 때는 이 문서와 명세의 `ApiError` 설명, 그리고 그 코드를 내는 핸들러
> 셋을 같은 커밋에서 고친다.
