# 포스터·홈 작품 이동·닉네임 UI 검증 (MZ2AZ-431)

2026-10-13. 최신 main의 iOS 화면과 별도 QA 기기를 사용했다. 사용자 기기의 옛 후기·사진·코스와
루트의 기존 미커밋 시안은 보존했다. 블로그형 후기와 AI 사진(MZ2AZ-428)은 이 변경에 포함하지 않는다.

## 구현과 자동 검사

- 홈·검색 행·자동완성·작품 상세의 포스터를 고정 칸을 중심으로 채우는 표시로 복구했다.
  원본 비율에 따라 가장자리가 잘리며, 관광공사 장소 사진은 전체 비율을 유지한다.
  홈·목록은 작품 선택, 상세만 유효한 `producerUrl` 링크를 사용한다.
- 닉네임 화면의 이름 미리보기·입력 길이·지우기·스크롤 본문과 하단 저장/취소를 구현했다.
  저장 중 입력·닫기를 잠그고 접근성 글자 크기에서는 큰 시트로 시작한다.
- 저장소도 요청 시점의 epoch·회원 ID와 응답 ID를 검사한다. 계정 A의 저장 응답이 늦게 와도
  계정 B를 덮거나 A의 질문 이력을 표시하지 않는다. 정상 저장·공백 정규화도 회귀 시험으로 확인한다.
- 계정 전환 및 다른 회원의 응답 재현 시험 2개가 수정 전 실패하는 것을 확인한 뒤 수정했다.
  최종 iOS 685개 시험과 `just check`의 119개 빌드·21개 시험 대상이 통과했다.
- 검증 에이전트가 지적한 계정 오염·영어 문구 누락을 수정하고 다시 코드 검토를 받았다.
- PR CI의 첫 iOS 실행은 기존 검색 사용량 시험에서 200회 `Task.yield()` 안에 비동기
  페이지 실패 응답이 도착하지 않아 실패했고 자동 재시도에서 통과했다. 반복 횟수에 의존하던
  대기를 최대 3초의 조건 확인으로 바꿨다. 제한을 넘기거나 대기가 취소되면 여전히 실패한다.

## 실제 화면에서 확인한 범위

| 확인 | 근거·결과 |
| --- | --- |
| 홈 포스터 | 작은 화면의 세 작품 이미지가 고정 칸을 채우는 스크린샷 확인 |
| 홈 가로 이동 | iOS 기본 접근성 `scroll right`로 첫 작품 x가 0.0533에서 -0.9467로 이동하고 뒤 작품이 표시됨. `scroll left`로 처음으로 복귀 |
| 작품 선택 | 홈의 기생충 선택 뒤 작품 상세·제작사 링크 버튼과 촬영지 목록 표시 확인 |
| 닉네임 입력 | 실제 QA 화면에 `SceneFan_QA`를 입력한 뒤 같은 이름 미리보기·11/16·키보드·하단 동작 확인 |
| 입력 지우기 | 실제 지우기 동작 뒤 미리보기 여행자·0/16·비활성 저장 확인 |
| 영어·다크 | `Author name preview`, `Choose a nickname` 등 번역과 다크 색 대비 확인 |

조작 도구의 성공 응답만으로 통과 처리하지 않았다. 초기 Orca 터치/드래그는 화면 변화가 없어
미검증으로 처리했고, Device Hub의 기본 접근성 동작과 별도 기기 스크린샷으로 변화가 발생한
경로만 위 표에 기록했다.

## 남은 검증 조건

- 팀원이 사용한 플랫폼·OS·기기·코스 개수와 새 앱 설치 여부는 아직 전달되지 않았다.
  본 기기의 접근성 가로 이동은 정상이며 팀원의 손가락 스와이프 문제 원인을 확정하지 않았다.
- 이번 검증에서 외부 Safari의 제작사 최종 URL까지 관찰한 증거는 없다. 링크 조건은 기존
  ProducerLink 회귀 시험·코드와 상세 버튼의 실제 존재로 확인했다.
- 새 UI에서 실제 회원의 닉네임을 바꾸는 서버 저장은 실행하지 않았다. 기존 서버 저장 동선과
  새 저장소의 정상·계정 전환·응답 ID 검사는 별도 회귀 시험으로 확인했다.

## 검사 환경

전체 검사 첫 시도에는 Android SDK 환경이 빠졌고, 잘못 고른 다른 SDK에는 API 37만 있었다.
프로젝트에 고정된 API 36·build tools 36.1.0을 가진 기존 SDK를 `ANDROID_HOME`으로 지정한 뒤
동일한 `just check` 전체를 통과했다. SDK 버전·테스트 레인을 낮추거나 소스를 우회하지 않았다.
