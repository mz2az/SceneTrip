# 커뮤니티 블로그형 본문·AI 사진 검증 (MZ2AZ-428)

2026-10-13. 대표 사진 한 장과 문단 사이 사진, 작성 배치의 저장·복원, 기존 추천 글 20개의
AI 변환 사진을 검증했다. 본문 배치 없는 옛 글과 기기 전용 글도 유지한다.

## 실제 자료와 API

- 로컬 V32 적용 및 새 scene-api 롤아웃 후 글 20개(post 27~46)와 사진 첨부 32개를
  기존 ID에 적용했다. AI 사진은 고유 원본 31종이며 입력·출력 해시·출처·프롬프트를 보존한다.
- 20개 상세의 본문·블록 순서·사진 수와 실제 다운로드 파일의 해시를 모두 대조했다.
  원본 사진 32장과 글의 코스 사본 및 원래 코스 20개는 동일했다. 사진을 덮거나 지우지 않았다.
- 실제 `POST /uploads`·서명 PUT·`POST /posts`·GET으로 첫 문단/사진/다음 문단의 순서,
  설명·출처·AI 표시와 사진 바이트를 확인했다. 시험 글과 새 시험 사진 한 장만 정리했다.
- 업로드 첫 시도에는 `mc pipe` 기본 528MiB 버퍼가 로컬 MinIO의 512MiB 한도를 넘어
  OOMKilled로 재시작됐다. DB 갱신 전 중단됐고 16MiB·동시 1개로 같은 상태를 재개했다.
  전체 적용·확인이 완료됐고 그 뒤 컨테이너 재시작 수는 늘지 않았다.

## 실제 iOS 화면

별도 SE3 QA 기기에서 대구 글을 다시 열고 대표 사진 한 장·제목·작성자·출처를 확인했다.
청라언덕 문단 뒤에 해당 AI 사진이 있고 다음 서문시장 문단으로 이어지는 화면을 확인했다.
사진을 누르면 전체 화면이 열리며 확대 버튼으로 100%에서 200%로 실제 값과 화면이 변했다.
접근성 동작의 성공 응답만으로 통과 처리하지 않고 별도 기기 스크린샷을 대조했다.
다크 모드·영어에서도 글과 AI 표시·사진·코스가 보이는 것을 확인했다. 사용자가 작성한
한국어 본문과 출처는 번역하지 않고 원문으로 표시한다.
SE3의 최대 접근성 글자 크기에서는 제목·출처가 여러 줄로 흐르고 아래 내용을 스크롤로
읽을 수 있는 것을 확인했다. 검증 뒤 QA 기기의 글자 크기는 기본으로 되돌렸다.

작성 배치의 삭제·문단 변경·미리보기·읽기 실패·설명 길이와 불확실 게시 처리, 계정/권한은
단위 시험·서버 통합 시험·실제 API 흐름으로 확인한다. UI에서 실제 소셜 로그인과 사진첩
선택부터 게시까지 이어지는 전체 과정은 이 검증에서 실행하지 않았다.

## 자동 검사와 검토

배치 불일치·중복/범위 밖 사진·본문 정규화·옛 글 NULL 호환을 Java/iOS 시험으로 확인한다.
변환 파일 변조·출처 누락·다른 가이드 대응·바깥 파일·저장 키·본문 한도와 실제 31종/32첨부
재료는 독립 도구 시험으로 검사한다. 검증 에이전트의 저장/권한/순서 및 적용 중단 검토를
받고, 원본 백업의 원자적 저장·입력/업로드 직전 출력 해시·5000자 한도를 보강했다.

로컬 전량 POI DB에서 서버 전체 통합 실행은 535개 성공·6개 실패였다. 실패는 표본 상점이
없는 다섯 시험과 밀집 뷰포트의 인덱스 질의 계획 한 시험이다. 블로그 저장·복원은 통과했다.
이 결과를 전체 통합 통과로 표시하지 않는다. PostStore만 별도 선택한 18개 시험은 모두
통과했다. 선택 인자는 통합 스크립트가 그대로 전달하도록 고쳤다.
전체 POI 통합 실패는 [MZ2AZ-432](https://mz2az.atlassian.net/browse/MZ2AZ-432)에
기록했다. 새 선택 필드는 명세의 기존 속성 뒤에 추가해 Android의 기존 위치 인자 생성자와
Swift 이름 인자 순서를 유지한다.

계약을 소비하는 `community-post.md`·`community-regional-guides.md`를 갱신했다.
`review.md`·`review-app.md`의 리뷰 사진 한도·업로드 계약은 재검토했고 영향이 없다.

최종 `just check`는 빌드 타깃 121개·시험 타깃 22개가 통과했다. iOS 692개, 서버 단위
757개, 블로그 자료 도구 9개 시험이 통과했고 적용된 20글·32사진을 실제 API로 다시
확인했다. PR CI의 실행·로그 결과는 PR에 기록한다. 운영 DB·AWS 반영은 하지 않았다.

첫 PR CI의 macOS 최적화 빌드는 새 시험의 `Slot` 멤버 초기화가 fileprivate여서 실패했다.
공개된 초안 시작 동작으로 슬롯을 얻고 읽기 실패·대기 상태를 확인하도록 시험을 고쳤다.
이 실패를 실행 차단이나 앱의 사진 저장 성공으로 바꾸어 기록하지 않는다. 수정 뒤 CI와
같은 `--config=ci`를 넘긴 `just test //apps/scenetrip-ios:unit_test --config=ci`가 통과했다.
최종 PR CI의 로그도 확인한다.
