04:57까지 Android 단위 테스트 59개가 통과했다. 장바구니 삭제 실패 시 목록 보존,
온보딩 완료의 한 번 처리, POI 이름 번역 왕복·묶음 보존, 머무는 시간 합계,
커뮤니티 계정 전환·목록 보존·소유자 삭제·게시 응답 소실 후 중복 방지,
검색 취소·이어 받기·새 응답 총수 기록·인증/재시도 없는 통계 요청을 포함한다.
코스 작품 보충·뷰포트 조회 후 작품 검색어 보존·생성된 장소 상세 JSON 파싱·공공누리
사진 비율 규칙도 포함한다. 코스 편집 실화면에서 발견한 차이를 반영하며 추가 검증 중이다.
새 중복 회귀 테스트를 먼저 실패시킨 뒤 촬영지 ID·POI ID·이름과 좌표 판정을 맞췄다.
후보끼리와 모든 일차에 이미 담긴 장소를 함께 확인한다.

Android 기본 GPS가 미국에 있어 촬영지와 현위치를 한 화면에 맞추면 세계 지도가 보였다.
04:46에 비교용 두 기기의 가상 GPS를 서울시청 좌표로 맞췄다. Android 초안을 다시 열어
한국의 현위치·촬영지가 보이는 것을 확인했다. 기기 위치 차이를 앱 오류로 확정하지 않는다.

## 반영 범위와 미완료 검사

서버 여행후기 목록·전문·사진·코스 사본·내 글을 연결했다. 기존 SharedPreferences의 글과
사진은 비공개 옛 글 목록으로 보존하며 서버에 자동 게시하거나 지우지 않는다.
게시 응답을 잃으면 초안을 잠그고 게시 여부 확인을 제공한다. 사진 없는 글은 동일 게시물을
확정할 근거가 부족하므로 재전송하지 않는다. 이 실패 규칙은 가짜 계약 클라이언트로 검증했다.

검색 목록은 서버 total을 표시하고 중복 행을 제외하며, offset은 받은 행 수로 계산한다.
분류가 켜지면 남은 장소를 이어 받고 아직 일부라면 +와 안내 문구를 표시한다.
통계 전송은 생성 EventsApi를 사용하며 별도 10초 클라이언트에서 인증 갱신·재시도 없이 보낸다.

05:05에 전체 `just check`가 통과했다. 포맷·린트·전체 빌드와 단위 테스트 대상 19개가
모두 성공했다. 이후 시험한 fontScale 매니페스트 변경은 실화면 상태 보존에 실패해 철회했다.

실계정 게시·사진 업로드·타 계정 코스 담기, 큰 글자 전환 시 초안 유지, 코스 안내·오류 상태의
양 플랫폼 스크린샷 비교는 아직 끝나지 않았다. 이 항목은 통과로 계산하지 않는다.
전체 기능·UI 동등성 완료로 보고하지 않는다. 사용자 요청으로 현재 변경을 중간 커밋에
보존하고 신규 기능 수정을 중단했다. 이후 요청에 따라 검증된 개선을 이번 PR 범위로
제출하고, 최신 main 병합 후 전체 검사와 원격 CI 통과를 병합 조건으로 삼는다.
아래 미완료 항목은 후속 작업으로 남긴다.

## 중단 시점과 재개 항목

2026-10-12 사용자 요청으로 신규 수정·E2E 실행을 중단했다. 기본 작업 트리는 수정하지
않고 별도 브랜치의 Android 구현과 이 기록을 보존한다. 다음 순서로 재개할 수 있다.

1. 실행 중 글자 배율을 바꿔도 코스 초안이 유지되도록 상태 소유 위치를 점검한다.
   fontScale 매니페스트 변경은 효과가 없어 철회했으며, Compose 시트 내부 상태도 확인해야 한다.
2. 코스 지도는 실제 하단 패널 높이와 iOS의 40pt 맞춤 여백을 비교한다. Android 공통 검색 지도는
   카메라 하단 여백을 화면의 48%로 제한해 60% 코스 패널 아래로 핀이 가려지는 차이가 남아 있다.
3. Android POI 묶음 구성원·선택 해태, 코스 가이드·여행 안내·오류 상태를 양 플랫폼에서 비교한다.
4. 인증된 테스트 계정의 게시·사진 업로드·타 계정 코스 담기를 검증한다.
5. 최신 iOS 기준 커밋을 다시 확인하고 전체 검증 뒤 PR을 생성한다.

큰 글자 검사는 Android 배율을 1.0으로 복원하고 시험 초안을 닫은 상태로 마쳤다.
사용자의 기존 iOS 계정·코스와 Android 옛 기기 글은 보존했다.

## 시뮬레이터 오류 우선 조치

03:03~03:04(KST)에 자동화 연결을 중단하고 현재 macOS 문제 보고서 창을 닫았다.
반복된 SpringBoard 보고서의 부모 프로세스는 모두 `28435`이며,
해당 `launchd_sim`은 iPhone 17 Pro 기기에 속했다. 이 기기만 데이터 삭제 없이 종료했다.
비교용 iPhone 17의 SpringBoard는 별도 부모 프로세스 `23214` 아래에서
전날 18:08부터 실행 중이었다. 03:05에 앱 화면을 다시 캡처해 정상 표시를 확인했다.

자동화 연결 시각과 문제 기기의 부팅 시각이 인접하지만, 로그만으로 디스플레이 초기화
실패의 내부 원인을 확정할 수 없다. 문제 기기를 다시 켜거나 초기화하지 않는다.
Android 제어는 iOS 연결 도구를 경유하지 않고 해당 기기의 adb로 직접 수행한다.
03:06 재확인에서 종료 후 2분 동안 새 충돌 보고서가 없고 문제 보고서 프로세스도
종료된 상태였다. 이 확인은 반복 팝업의 중단을 확인한 것으로, 문제 기기의 내부
디스플레이 초기화 오류가 수리됐다는 뜻은 아니다.

03:37에는 이미 실행 중인 비교용 iPhone 17에만 다시 연결했다.
04:47 재확인에서 마지막 SpringBoard 보고서는 여전히 03:00:10이며 새 보고서가 없었다.
문제 iPhone 17 Pro는 종료된 상태를 유지했다.

## 증거와 한계

원본 스크린샷은 로컬 임시 경로에 보관한다. 사용자 데이터나 인증 정보를 저장소에 포함하지 않는다.
화면 조작이 끝난 경로와 단위 테스트만으로 확인한 경로를 구분해 기록한다.
