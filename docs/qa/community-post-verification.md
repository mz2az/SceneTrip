# iOS 여행후기 서버 연결 검증 (MZ2AZ-396)

2026-10-11 로컬 `kind-scenetrip`의 scene-api 1.10.0/V27과 MinIO에서 확인했다.
AWS·유료 API는 호출하지 않았다. 기존 사용자·코스·리뷰 대신 `VERIFY396` 접두사를 가진
새 시험 계정 두 개, 코스, 후기와 1×1 PNG 두 장을 만들었다.

| 확인 | 결과 |
| --- | --- |
| `POST /uploads`, 목적 `post` → 서명 PUT → 글 게시 | 본문과 사진 두 장의 순서가 DB에 저장됨 |
| 반환된 사진 주소 GET | 빨강·파랑 사진의 원본 바이트와 순서 일치 |
| 작성자·다른 계정·비회원의 목록/상세 재조회 | 같은 글·사진이 조회되며 `isMine`은 작성자에게만 true |
| `GET /me/posts` | 작성자 목록에는 있고 다른 계정 목록에는 없음 |
| 촬영지·편의시설·직접 찍은 핀을 가진 코스 첨부 | 촬영지·편의시설만 공유됨. 개인 핀은 빠짐 |
| 다른 계정의 `POST /posts/{id}/saves` | 장소 두 곳이 새 코스로 저장되고 `origin: market` |
| 다른 계정의 삭제 | 404 |
| 작성자 삭제·삭제 뒤 공개 조회 | 204, 이후 404 |
| 시험 데이터 정리 | 새 계정·글·코스·사진 파일만 제거 |

전후 기존 DB 건수는 작품 128, 촬영지 521, 편의시설 910,394, 코스 2, 리뷰 4,
촬영지·편의시설 연결 82, 여행후기 0으로 동일했다. 첫 실행의 사진 정리에서 이미 이동된
임시 파일의 없음 응답을 오류로 취급해 중단했지만, 그 실행의 두 시험 사진도 별도로 제거했다.
그 뒤 전체 검증을 다시 실행하고 저장소까지 정리했다.

앱 단위 테스트는 가짜 API로 제한·권한·계정 변경·목록 실패·삭제 실패·사진 순서와
게시 중복 방지를 확인한다. 기존 개인 핀을 포함한 기기 글 사본의 왕복 테스트도 유지한다.

## 앱 화면에서 확인

같은 날 iPhone 17/iOS 26.5 시뮬레이터의 실제 사진 보관함에서 기존 시험 이미지 BIG4·BIG3을
차례로 선택했다. `VERIFY396` 접두사의 제목 37자와 본문 135자를 입력하고,
기존 VERIFY6 코스의 두 항목을 사본으로 첨부하여 게시했다. 서버의 새 글 ID 4에
사진 두 장이 저장되었고 앱 상세 화면에서 BIG4, 본문, 코스가 표시되었다.
사진을 넘겨 BIG3도 표시되는 것을 확인했다. 기존 코스는 수정하지 않았다.
앱을 종료한 뒤 `demoCourse: 0`으로 다시 실행하고 커뮤니티 목록에서 서버 글을 다시 열었다.
동일한 본문 135자와 원래 코스의 두 항목이 남아 있어 메모리 밖의 저장을 확인했다.
목록에서 본인 글을 옆으로 밀어 삭제를 확인한 뒤 빈 목록이 표시되었다.
비회원 `GET /v1/posts`도 `total: 0`이며 시험 글 ID 4가 사라진 것을 확인했다.
기존 기기 보관함 글 한 건, 서버 코스 두 건·리뷰 네 건과 사진 보관함 미디어는 보존했다.
화면 증거는 `community-before-post.jpg`, `community-post-detail.jpg`,
`community-second-photo.jpg`이며 목록 재조회·삭제 확인의 접근성 트리도 기록했다.

## 확인 범위와 남은 한계

- 사진 보관함 선택부터 앱의 게시·본문·코스·사진 넘기기는 화면으로 확인했다.
  다른 실제 기기에서의 표시는 확인하지 않았으며 다른 계정·비회원의 조회는 위 서버 대조 결과다.
- 게시 API에 멱등 키가 없다. 앱은 응답을 잃은 글을 재전송하지 않고 내 글에서 게시 여부를
  확인한다. 목록 상위 100건에서 하나를 확정하지 못하면 초안을 보존하고 확인을 다시 제공한다.
  사진 없는 글은 다른 기기의 동일 글과 구분할 수 없어 자동 성공 처리하지 않는다.
  선택 코스의 제목·일차별 촬영지/편의시설 IDs가 다른 글도 이번 게시 결과로 처리하지 않는다.
- 코스 담기에도 서버 멱등 키가 없다. 요청 응답이 끊긴 경우 내 코스 목록을 확인한 뒤 재시도한다.
- 글 고치기·좋아요·댓글·신고 화면은 이번 범위에 없다.
- 기기에 남은 옛 글은 자동 게시하지 않는다. 내 글의 별도 보관함에서 읽을 수 있다.
