## 0. 무슨 시험인가 — 오래 버티기(soak), 시나리오 v2
**목적**: 시간이 지나야 드러나는 문제(메모리·연결 누수)를 글쓰기·사진 올리기까지 넣고 본다. 초당 5 → 20 흐름(2 분), 20 유지 30 분. 흐름 여섯 전부.

흐름 — [시나리오 v2](scenario.md#v2--2026-10-18-커밋-9ac9e97)(네이버 링크 찾기 끔, 「v2 정정」):
  - **둘러보기** 50%(비회원): 작품 목록 → 상세 → 촬영지 → 검색 추천어 → 지도 영역 편의시설 30 개 → (70%) 편의시설 상세 → 사진 → 촬영지 상세
  - **후기 읽기** 8%(비회원): 여행후기 목록 → 상세
  - **담기** 14%(비회원): 장바구니 담기 → 보기 → 작품 찜 → 빼기
  - **여행** 12%(회원): 코스 만들기 → 담기 → 시작 → 길찾기(가짜 카카오) → 지우기
  - **챗봇** 8%(회원): 대화 한 턴(trip-guide → 가짜 LLM 2 번)
  - **쓰기** 8%(회원): 사진 올리기(진짜 S3) → 리뷰, 또는 사진 → 여행후기 쓰기 → 목록 → 상세 → 지우기
  - 단계 사이 1~3 초 쉼, 무작위 데이터, 토큰 만료 시 갱신, 앞 단계 실패 시 흐름 멈춤

**본 것**: k6, SigNoz(API 별 처리 시간·응답 코드·DB 시간·연결 풀), AWS(RDS CPU, ALB 5xx), 쿠버네티스 이벤트(상태 점검 실패·재시작), gateway 로그.

## 4. 401 121 건 — 미해결
- 시각: 14:16 8 · 14:17 63 · 14:18 50 — 처음 로그인(13:46~13:56) 뒤 액세스 토큰 수명 30 분이 지나는 때다.
- 같은 때 `POST /auth/refresh` 약 160 건(아래 API 표의 30 분 구간 안에서는 159 건)이 **모두 200** — v2 의 갱신은 돈다. 그런데도 401 이 남았다(`POST /courses` 64, `POST /uploads` 42 …).
- 추정: 시나리오의 갱신 조건(응답 몸체에 `ACCESS_TOKEN_EXPIRED`)에 걸리지 않는 401 이 있거나, 갱신 뒤 재시도에서 다른 이유로 401. 전체 요청의 0.06% 라 결과를
  바꾸지 않지만 원인을 아직 모른다 → 시나리오 쪽부터 확인한다.

## 5. 챗봇
89% 실패 — 실험 01·08 과 같은 원인. 이 시간에도 trip-guide 상태 점검 실패가 이어졌다(14:13 생존 15·준비 43, 실험 08).
