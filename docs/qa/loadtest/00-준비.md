# 00. 준비 일지

부하 테스트(MZ2AZ-502)를 시작하기 전까지 무엇을 어떤 순서로 했고, 무엇에 막혔고, 왜 그렇게 정했는지. 날짜별로 덧붙인다(고치지 않는다).
계획: [load-test.md](../../project/plans/load-test.md).

## 2026-10-18

### 1. 범위와 도구를 정했다
- 질문: 「실제 사용자의 많은 트래픽을 흉내 내야 하나?」 → 시험 종류를 나눈다(연기·기준·한계·급증·오래 버티기). 병목 찾기의 중심은
  **한계(계단식 증가)**. 흐름 단위·비중·생각하는 시간·도착률(arrival-rate)·데이터 다양성·합격선을 미리 정한다.
- 도구 **k6**, 부하는 **서울 리전 EC2(러너)** 에서 — 집 회선이 먼저 한계에 닿으면 서버 문제와 구분이 안 된다.
- **우리 서버는 전부 진짜, 바깥 회사 서버(Bedrock·카카오)로 나가는 요청만 가짜.** 가짜가 흉내 낼 것은 바깥의 겉모습(응답 모양·응답 시간·가끔의
  실패)뿐이라 어렵지 않다. 우리 서버가 응답을 읽고 처리하는 과정은 진짜로 돈다.
- 챗봇은 **trip-guide 는 진짜, 그 뒤 LLM 만 가짜** — trip-guide 는 한 대에 동시 4 건·대화 128 개 한도가 있어 먼저 막힐 후보다. 서버째 가짜로
  바꾸면 그것을 못 본다.
- 로그인: DEV 는 진짜 구글 로그인만 받는다 → 시험 동안만 구글 공개키 주소를 가짜로(방법 1, e2e 와 같은 방식). 운영 코드에 시험용 구멍을 만드는
  방법(3)은 PRD 에서 실수로 켜질 위험 때문에 뺐다.
- 부하를 막는 장치: 한 IP 에서 나가므로 gateway 의 IP 한도(초당 30)에 먼저 걸린다 → **DEV 시험 중에만 올린다.** 길찾기·챗봇 유료 한도는
  **시험 회원 수백 명**으로 나눈다(실제 사용자처럼).

### 2. k6 를 Bazel 로 받았다
- 왜 의존성으로: 「이전」 과 「이후」 를 **같은 도구**로 재야 비교가 된다 — 버전·SHA-256 고정(v2.3.0, 공식 체크섬과 대조). 저장소 원칙(도구는
  Bazel 이 받는다)과도 맞다.
- `just load-run smoke.js -e BASE_URL=https://api-dev.scenetrip.io/v1` — 노트북 → DEV 연기 확인 10/10 성공, p95 39.9ms.

### 3. PRD 의 바깥 호출 지연을 쟀다 — 가짜가 흉내 낼 값
- PRD SigNoz 화면은 Cloudflare Access 뒤라, 임시 접속(읽기)으로 ClickHouse 를 직접 조회했다. 끝나고 접속을 지웠다.
- Bedrock LLM 한 번 p50 2.58 초·p95 5.34 초(n=4), 에이전트 한 턴 p50 2.91 초·p95 6.17 초, 카카오 p50 65ms·p95 502ms(n=11).
- **한계**: 표본이 작다(사용자 적음 + 2026-10-17 SigNoz 디스크가 차서 3 시간 공백). 4 건 모두 일정짜기 마법사라 챗봇 대화 표본은 없다. DEV 에는
  바깥 호출 기록이 아예 없었다.

### 4. 가짜 바깥 서버 — 설계
- 자리: **DEV 클러스터 안 파드**(`fake-external`, 부하 시험 때만). DEV 는 「기본 모두 차단, 필요한 것만 허용」(NetworkPolicy `default-deny`)이라
  scene-api·trip-guide → 가짜 통로를 따로 연다.
- 흉내: 카카오 길찾기(응답 JSON 은 e2e 가짜를 재사용) · Bedrock(OpenAI 방식 `/chat/completions` — 도구가 주어지면 첫 호출은 도구 쓰기,
  다음 호출은 답) · 구글 공개키(JWKS). 지연은 위 실측의 로그정규 근사.
- 동시성: 기다리는 동안 다른 요청을 받는 구조(asyncio)로 — 수백 개가 2~5 초씩 기다려도 가짜가 먼저 막히지 않게. 가짜만 단독으로 두드려 확인한다.
- 시험 회원의 구글 ID 토큰: k6 에는 RSA 서명이 없어 **시험 전에 미리 만들어 둔 토큰 묶음**을 k6 가 읽는다(가짜 공개키와 짝인 비밀키로 서명).
- 남은 막힘: trip-guide 의 모델 주소는 `config/model.json` 에 박혀 있다 → 환경변수로 덮는 코드가 먼저 필요(시험 먼저).

### 5. 가짜 바깥 서버와 trip-guide 모델 주소 덮기를 만들었다
- **trip-guide**: `TRIP_GUIDE_MODEL_BASE_URL`·`TRIP_GUIDE_MODEL_AUTH`(`none` = 인증 헤더도 자격 증명 확인도 없음). 비면 지금과 같다. 켜지면
  시작 로그에 「이 파드는 Bedrock 이 아닐 수 있다 — 부하 테스트 전용」 경고. 시험 14 개를 먼저 써서 구현 전 실패(15)를 보고 구현, 단위 372 통과.
  모델 행동(프롬프트·모델 ID·파라미터)은 그대로라 실제 모델 평가는 돌리지 않았다.
- **가짜 바깥 서버** `platform/helm/scenetrip/files/fake_external.py`(표준 라이브러리, asyncio): 카카오(인증 헤더 없으면 401, 거리에 맞춘
  경로) · Bedrock `/chat/completions`(도구가 있으면 첫 호출은 도구 쓰기 → 다음은 답, 한 턴 LLM 2 번 / 일정 JSON 은 플래너 검사 통과) ·
  구글 JWKS. 지연은 PRD 실측의 로그정규, 실패 비율·배율은 환경변수.
  - **가짜가 병목이 아닌지**: 지연 2 초로 500 개 동시 → 2.04 초에 모두 200.
  - 시험 35 개(10 회 반복해도 통과). 에이전트의 실제 검사 함수(`parse_days`·도구 9 종 `validate_args`)로 가짜 응답이 통과함을 확인.
- **시험 회원 토큰**: `just load-tokens` 가 비밀키를 만들거나 읽어 ID 토큰 묶음과 공개키(JWK)를 만든다. 비밀키는 저장소에 두지 않는다 — 기본 내장
  공개키에는 짝 비밀키가 없으니 시험 때는 만든 공개키를 가짜에 넘긴다.
- 다음: 차트에 가짜 서버(ConfigMap·Deployment·Service)와 통로(NetworkPolicy), 시험 모드 켜고 끄기.

### 6. 차트에 시험 모드를 넣고 켜고 끄는 명령을 만들었다
- **차트** `loadtest` 값 묶음(기본 꺼짐): 켜면 가짜 바깥 서버(ConfigMap·Deployment·Service `fake-external`)와 통로(NetworkPolicy 둘), scene-api 의
  카카오·구글 공개키·client ID 덮기, trip-guide 모델 주소 덮기(`none` 인증), gateway IP 상한 2000r/s · burst 4000 · 동시 4000.
  - 동시 연결 상한(평소 60)도 올렸다 — 요청 상한만 올리면 LLM 처럼 몇 초 걸리는 요청이 한 IP 에서 60 개를 넘는 순간 막힌다.
  - **PRD 에서 켜면 렌더가 실패한다.** 꺼져 있으면 렌더가 바꾸기 전과 바이트 단위로 같다(DEV·PRD 둘 다 직접 비교, 시험이 계속 지킨다).
  - 렌더 시험 13 개를 먼저 써서 구현 전 실패 21 건(부분 시험 포함)을 보고 구현 → `//tools/aws:unit_test` 474 통과.
- **명령** `just loadtest-mode dev on|off`: 깔린 릴리스의 값은 두고 `loadtest` 만 바꿔 `helm upgrade --reset-then-reuse-values --atomic --wait`.
  dev·`scenetrip-dev` 컨텍스트만 받는다. 클러스터 접속(임시 access entry + 러너 SOCKS 터널)은 열지 않는다. 가짜 helm 으로 시험 10 개(먼저 실패 확인).
- 아직: DEV 에 실제로 켜 보지 않았다(클러스터 접속 필요). 켠 뒤 확인할 것 — fake-external 준비 상태, scene-api → 가짜 카카오·JWKS, trip-guide →
  가짜 모델, NetworkPolicy 가 다른 통로는 여전히 막는지, 끄면 원래대로인지.
- DEV 데이터 확인(API): 작품 128 · 촬영지 476 · 서울 도심 편의시설 78,611 — PRD(128 · 476 · 78,590)와 거의 같아 **적재가 필요 없다**. 여행후기·리뷰 같은
  사용자 데이터만 없다 → 시나리오가 만들어 가며 쓴다. DEV 카카오 키는 들어 있다(값은 보지 않음) — 가짜 카카오가 받는 `KakaoAK` 헤더가 실린다.
