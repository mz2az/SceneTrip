# Android 커뮤니티 블로그 검증 (MZ2AZ-428)

main e739948의 iOS PR266·계약1.13을 Android 독립 브랜치에서 소비한다.
[계획](../project/plans/android-community-blog.md)에 따라 대표 한 장·문단별 사진·작성 배치·미리보기·확대를 맞췄다.
계약·서버·iOS 소스와 공용 자료는 수정하지 않는다. 서명 URL은 메모리에서만 사용한다.

## 규칙·자동 검사

본문과 블록·사진 키·코스가 같아야 불확실한 게시를 성공으로 확정한다. 블록 순서가 달라도 성공으로
판정하던 회귀를 먼저 실패시킨 뒤 수정했다. 문단 NFC/줄바꿈·UTF-16 한도·사진 삭제/인덱스 재산정·
위치 범위·설명/출처 한도·옛 글·형식 위반 및 클라이언트 호출 차단을 단위 검사한다.
기존 계정 epoch·게시 불확실 상태·동일 POST 재전송 차단은 유지한다.
Android 단위107개와 전체 `just check` 빌드121개·시험22개가 통과했다.

공통 확대 화면의 `just android-photo-qa-test`가 원본 전체 비율·실제 두 손가락400%·
두 번 누르기100/200%·초기화·닫기/재열기·404 재시도·실제 씬 없는 경우의 포스터 대체 금지를 통과했다.
최종 재실행 중 두 번째 두 번 누르기의200% 확인이 한 번 실패했다. 시험 입력 사이에
UI idle 대기를 추가한 뒤 같은 전체 화면 검사를 통과했다. 제품 확대 로직을 이 실패 때문에 바꾸지는 않았다.

대구 글의 실제 세로형 AI 사진에서 대표 이미지가 제목·출처 위까지 그려지는 오류를 발견했다.
세로450×900 시험 PNG와 `just android-community-blog-qa-test`의 실제 제목 영역 픽셀로 먼저
실패를 재현했다. 대표의 부모 높이를220dp 이내로 명시하고 이미지를 해당 칸에 Fit으로 제한한 뒤
같은 화면 시험을 통과했다. 본문 사진은 원래 비율의 높이를 사용한다.

## 별도 QA 앱의 실제 터치

`just android-photo-qa-server`와 `just android-community-blog-qa`는 별도 설치본의 합성 사진·초안만 사용한다.
제품 AuthStore 로그인·실제 게시·업로드를 시작하지 않는다. ko/en·light/dark와
compose/read/legacy/retry/pending/failed 화면을 제공한다.

| 확인 | 관찰한 결과 |
| --- | --- |
| 작성·미리보기 | 대표 사진·제목·첫 문단·사진·다음 문단 순서, 사진 설명·출처·AI 표시 |
| 배치 변경·사진 삭제 | 첫 사진을 둘째 문단 뒤로, 두 번째를 첫 문단 뒤로 옮기고 설명·출처·AI를 입력. 첫 사진 삭제 뒤 남은 사진의 메타데이터·삽입 위치가 미리보기에 유지 |
| 확대 | 미리보기 사진을 터치해200%와 AI/출처·닫기 확인 |
| 큰 글자 | 미리보기를 연 상태에서1.0→1.6 뒤 사진·입력 메타데이터·순서 유지, 여러 줄 본문·출처 표시 |
| 실패 재시도 | 대표 한 장만 요청하는 시험에서404 안내 뒤 ‘사진 다시 받기’를 터치해200 사진 표시 |
| 영어·다크·1.6 | 흰 본문·AI 영어 안내·사진·검은 바탕. 사용자 본문과 출처는 한국어 원문 유지 |
| 영어 작성·1.6 | 상단 미리보기·취소 버튼과 사진 배치 안내 확인. 제목 편집 중에도 상단 버튼이 보임 |
| 옛 글 | bodyBlocks 없이 두 문단·원래 사진 순서 표시, AI 표시를 임의 추가하지 않음 |
| 대기·고를 수 없는 사진 | pending은 불러오는 중 표시 유지, failed는 다시 선택 안내. 실패를 정상 사진으로 대체하지 않음 |

Activity 시작 직후의 빈 화면은 통과 근거에서 제외하고 실제 요소·안내가 나타난 뒤 화면을 확인했다.
실제 OAuth와 사진첩 선택부터 회원 게시까지 이어지는 동선을 검증했다는 뜻은 아니다.

## 실제 공개 자료

공개 API에서 기존20글 ID27~46의 제목·본문/블록 대응과 사진 참조를 대조했다.
AI32사진 다운로드 해시가 main 제작 이력의 출력 해시와 일치하며 설명·출처·AI 표시도 일치했다.
첨부1일 코스의 장소 종류·ID·순서·체류 시간이 확정 지역 가이드와 일치했다.
원래 코스140~159를 다시 생성하거나 기존 글·사진을 덮지 않았다. API GET만 사용했다.
이전 원본 가이드 사진 해시는 현재 AI 사진 검증 기준으로 사용하지 않는다.

제품 APK에서 대구 글을 열어 세로 대표 사진 전체·설명·AI·출처와 제목이 겹치지 않는 것을 확인했다.
200% 확대와 닫기, 본문 문단 뒤의 사진, 다크 모드·글자 배율1.6의 대표·본문도 직접 확인했다.
20글 전부를 시각 검사했다는 뜻은 아니다. 화면 변경 직후의 이전 접근성 트리나 빈 시작 화면은 근거에서 제외했다.
시스템 다크 모드 변경으로 Activity가 재시작하면 홈으로 돌아와, 글을 다시 열고 확인했다.

## 보존과 한계

사용자 기기 전용2후기·5사진과 백업/iOS Simulator는 조작하지 않는다. root의 미커밋 시안22개와
다른 세션의 변경도 stage/stash/삭제하지 않는다. Android 옛 기기 JSON의 설치 전후 해시가 일치했다.
이 Android 기기의 옛 후기 사진 폴더는 없었으며 사진 수는0개였다.
DB seed/reset·자료 적용/복구·유료 가이드/길찾기·AWS 작업은 실행하지 않는다.
HTML과 화면 캡처를 저장소에 추가하지 않는다. 되돌리기는 Android PR revert로 충분하다.
별도 QA 설치본과 이 작업의 PNG 서버는 종료·정리했다. 시스템 글자 배율1.0과 원래 night=no를 복원하고
제품 앱이 실행된 독립 Android Emulator 창을 유지했다. 공용 API·Docker·iOS Simulator는 종료하지 않았다.
