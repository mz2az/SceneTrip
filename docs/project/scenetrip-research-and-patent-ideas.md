# SceneTrip 논문 주제 5개와 특허 아이디어 5개

작성·자료 확인일: 2026-09-20. 구현 확인 기준: 저장소 커밋 `c2842f9`.

## 1. 제안 범위와 우선순위

SceneTrip은 작품·촬영지 검색, 여행 코스 생성과 편집, 길찾기, 현장 방문 판정,
여행 가이드 대화를 연구에 활용할 수 있다. 이 문서는 학부생 2~3명이 주당 8~12시간씩
참여한다는 가정 아래, 논문 한 편의 시제품과 비교 실험을 6~10주에 마치는 범위를 제안한다.
표본 수와 기간은 착수 계획이며 확보된 데이터나 실험 결과를 뜻하지 않는다.

논문의 `Abstract`는 연구계획용 초록이다. 실제 실험 전이므로 성능 향상이나 통계적
유의성을 주장하지 않는다. 학회 제출본에는 측정한 결과와 한계를 채워야 한다.
특허는 발명 구체화를 위한 후보이며 신규성·진보성·등록 가능성을 확정한 결과가 아니다.

| 구분 | 주제 | 우선순위와 판단 이유 | 예상 기간 |
| --- | --- | --- | --- |
| 논문 L1 | 실제 이동시간과 영업시간을 반영한 촬영지 일정 검증 | 상: 현재 플래너의 추정과 현실 제약 사이 차이를 측정하기 좋다 | 8~10주 |
| 논문 L2 | 주장별 근거 확인과 답변 보류를 적용한 촬영지 가이드 | 상: 현재 도구 기반 가이드에 작은 검증 단계를 추가한다 | 6~8주 |
| 논문 L3 | 사용자 고정 일정을 보존하는 최소 변경 재계획 | 상: 기존 일정 수정 함수를 재사용하고 오프라인 실험이 가능하다 | 6~8주 |
| 논문 L4 | 공공 POI와 지도 장소의 일치 판정 및 보류 | 최우선: 기존 규칙을 대조군으로 두기 쉽고 오류를 수작업 확인할 수 있다 | 6~8주 |
| 논문 L5 | GPS 오차를 고려한 촬영지 방문 판정 | 중: 현장 로그 수집이 필요하지만 시연과 정량 평가가 가능하다 | 8~10주 |
| 특허 T1 | 근거 변경에 따른 일정의 부분 재검증과 최소 수정 | 우선 구체화: L1·L3의 실험을 발명 설명 자료로 활용한다 | 시제품 8~10주 |
| 특허 T2 | 사실 유형·유효기간·출처 충돌에 따른 현장 안내 제어 | 우선 구체화: L2의 주장–근거 연결을 확장한다 | 시제품 6~8주 |
| 특허 T3 | 시청 범위와 방문 순서에 맞춘 장면 해설 재배열 | 확장 후보: 작품의 장면·스포일러 데이터를 새로 구성한다 | 시제품 8~10주 |
| 특허 T4 | 인접 촬영지의 모호함을 반영한 방문·안내 상태 제어 | 확장 후보: L5를 장소 식별과 콘텐츠 재생까지 확장한다 | 시제품 8~10주 |
| 특허 T5 | 변화한 배경을 제외하는 촬영 장면 구도 안내 | 탐색 후보: 영상 정합과 촬영 가능 영역을 새로 구현한다 | 시제품 8~10주 |

처음 한 편을 고른다면 L4를 권한다. 데이터 확보가 어렵다면 외부 현장 수집이 적은 L3가
대안이다. AI 에이전트의 특징을 보여 주려면 L2가 적합하다. 특허는 T1·T2부터 구성요소
대조표를 작성할 만하지만 이 순서는 등록 가능성의 순위가 아니다.

| 실제 길찾기 | 서버가 다음 구간의 도보·대중교통 경로를 처리 | 일정 생성 단계의 경로값 연계와 평가용 스냅샷 | [NextLegPlanner.java](../../services/scene-api/src/main/java/com/mz2az/scenetrip/sceneapi/navigation/NextLegPlanner.java) |

현행 플래너는 직선거리에 우회 계수를 적용해 이동시간을 추정하며 영업시간·휴무일을
반영하지 않는다. [기존 평가](../../agents/trip-guide/evals/plan_eval.py)의 실현 가능성은
내부 시간 예산과 중복·좌표 등의 조건을 확인한다. 실제 교통과 영업시간을 만족했다는
실험으로 해석하면 안 된다. 대본 모델을 사용하는 도구 실행 확인도 실제 LLM의 도구
선택 정확도와 구별해야 한다.

출처도 추가 작업이 필요하다. 수집 CSV의 `source_url`은
[적재 SQL](../../services/scene-api/seed/candidates.sql)에서 DB에 넣지 않는다.
도구 목록을 표시하는 기능만으로 주장별 출처가 확보되지는 않는다. POI 전체 원본 역시
이 저장소에 모두 있다고 가정하지 않는다. [ADR 0014](../../docs/architecture/adr/0014-poi-source-is-public-data.md)의
공공데이터 출처와 실제 접근 가능한 표본을 확인한 뒤 실험셋을 확정한다.

## 3. 논문 주제 5개

### L1. 실제 이동시간과 영업시간 검증을 결합한 촬영지 여행 일정 생성

**Abstract.** 촬영지를 시간 예산 안에 배치한 일정도 실제 교통시간이나 영업시간을
반영하지 않으면 현장에서 실행하기 어렵다. 본 연구는 SceneTrip의 결정적 플래너에
경로별 이동시간과 장소별 시간창을 결합하고 생성한 일정을 별도 검증기로 평가한다.
같은 여행 요청에 대해 현행 방식과 개선 방식을 비교하여 제약 충족률, 방문 수,
시간 초과 사이의 관계를 분석한다. 연구 범위는 수도권의 짧은 여행 일정으로 제한한다.

**핵심 아이디어와 연구 질문.** 자연어 이해는 LLM에 맡기되 장소 선택·시간 계산·검증을
분리한다. 질문은 ‘현실 제약을 추가했을 때 방문지를 과도하게 줄이지 않으면서 실행
가능한 일정을 더 많이 만드는가’다. 기존 `make_plan`에 이동시간 행렬과 영업시간
시간창을 넣고 독립 검증기는 각 도착·출발 시각과 필수 방문 조건을 확인하도록 한다.
LLM과 계획기를 결합했다는 사실 자체보다 촬영지 데이터에서 생기는 오류를 분석한다.

**실험 방법.** 장소 20~40곳, 1~2일 여행 요청 80개를 목표로 한다. 비교군은
현행 추정 방식, 실제 이동시간 적용 방식, 실제 이동시간+영업시간 검증 방식이다.
모든 방식에 같은 장소 후보·요청·이동수단을 제공한다. 교통 API의 관측 시각과
영업정보 확인일을 기록하여 고정된 실험 입력을 만들고 변동 영향을 보는 실험은
별도 시각의 경로값으로 수행한다. 시간창은 수작업 확인 자료와 인위적 충돌 사례를
구분한다. 20개 요청으로 조정하고 60개는 평가까지 봉인한다.

**실험 결과 측정 방법.** 주 지표는 전체 요청 중 필수 방문·시간창·일별 시간 예산을
모두 지킨 일정의 비율이다. 빈 일정과 필수 장소 누락은 실패로 센다. 보조 지표로
시간 초과 분수, 방문 수, 작품 포함률, 계산시간, API 호출 수를 기록한다.
동일 요청의 방식 간 차이와 요청 단위 부트스트랩 95% 신뢰구간을 보고한다.
작은 사례는 완전탐색으로 실행 가능한 해의 존재를 확인하고 원래 불가능한 요청에
대한 올바른 거절률도 따로 측정한다. ‘검증 입력 아래의 가능성’과 실제 여행 성공률은
구별한다.

**관련 연구와 차이.** [TravelPlanner, Xie 외, ICML 2024](https://arxiv.org/abs/2402.01622)는
여행 에이전트의 정보 수집과 여러 제약 준수를 평가한다. SceneTrip 연구는 항공·숙박을
포함하는 광범위한 여행 계획 대신 촬영지 하루 동선과 검증기를 좁게 비교한다.
이 벤치마크의 과거 모델 성능을 현재 SceneTrip의 성능으로 옮겨 쓰지 않는다.

**향후 연구.** 혼잡도·날씨에 따른 이동시간 불확실성, 휠체어 접근성, 실제 여행 로그를
반영한다. 첫 연구에서는 전국 이동이나 실시간 최적화까지 포함하지 않는다.

### L2. 주장별 근거 확인과 선택적 답변을 적용한 촬영지 가이드

**Abstract.** 장소 조회 도구를 사용하는 가이드도 조회 결과에 없는 장면 설명이나
확인되지 않은 영업정보를 말할 수 있다. 본 연구는 답변을 사실 주장 단위로 나누고
각 주장에 연결된 출처와 데이터 필드를 확인하는 가이드를 제안한다. 근거가 없거나
충돌하는 내용은 답변을 보류한다. 기존 도구 기반 가이드와 비교하여 근거 없는 주장,
불필요한 거절, 응답 지연의 변화를 함께 측정한다.

**핵심 아이디어와 연구 질문.** 촬영 사실, 작품 속 설정, 현재 방문 정보를 별도
유형으로 둔다. ‘실제로 촬영한 장소’와 ‘작품 속에서 묘사된 장소’를 섞지 않는 것이다.
출처를 붙였다는 이유만으로 정답 처리하지 않고 출처가 해당 주장을 뒷받침하는지
확인한다. 현재 `place_detail`을 재사용하되 출처 저장·조회와 주장 검증을 추가한다.
완전한 자동 사실 판별보다 구조화된 사실 필드를 우선 검증하는 범위가 현실적이다.

**실험 방법.** 답변 가능한 질문, 자료가 없는 질문, 작품·장소 관계를 잘못 전제한
질문을 각각 100·50·50문항씩 배정하여 200문항을 만든다. 일반 LLM, 현행 도구 기반 가이드, 도구+출처 표시,
도구+주장 검증·보류의 네 방식을 비교한다. 일반 LLM은 참고군이며 핵심 비교는 같은
도구와 자료를 사용하는 뒤의 세 방식이다. 모델·프롬프트 버전과 생성 설정을 고정하고
각 문항을 3회 실행한다. 40문항은 조정용, 160문항은 평가용으로 두며 같은 장면의
바꿔 쓴 질문은 한쪽에만 배치한다.

**실험 결과 측정 방법.** 주 지표는 출력한 전체 사실 주장 중 근거가 없거나 근거와
충돌한 주장 비율이다. 답변 가능한 문항의 정답률과 답변율을 함께 보고하여 모두
거절하는 방식이 유리해지지 않게 한다. 출처 정확도는 붙인 출처 중 해당 주장을
뒷받침한 비율, 출처 완전성은 전체 사실 주장 중 유효한 출처가 붙은 비율로 정의한다.
평가자 2명이 방식 이름을 가린 답변을 독립 채점하고 일치도와 합의 절차를 기록한다.
추가로 불필요한 거절률, 필요한 보류의 재현율, 지연·토큰 비용을 잰다.
사실 주장 0개인 응답의 주장 오류율은 0이 아닌 산출 불가로 처리하고 보류 건수에
포함한다. 반복 실행 결과의 신뢰구간은 문항 단위로 계산한다.

**관련 연구와 차이.** [ALCE, Gao 외, EMNLP 2023](https://aclanthology.org/2023.emnlp-main.398/)는
답변의 정확성과 인용 품질을 평가한다. 여기서는 촬영 사실·극중 설정·현재 방문 정보의
혼동과 자료 부재 시 보류를 별도 오류 유형으로 분석한다. 출처 표시나 RAG 자체를
새로운 연구 기법이라고 주장하지 않는다.

**향후 연구.** 변경된 영업정보의 자동 갱신, 다국어 답변의 주장 보존, 출처가 서로
충돌할 때 질문을 되묻는 전략으로 확장한다.

### L3. 사용자 고정 일정을 보존하는 최소 변경 촬영지 코스 재계획

**Abstract.** 여행 도중 장소 하나를 빼거나 시간을 바꾸면 이미 합의한 다른 일정까지
달라질 수 있다. 본 연구는 SceneTrip의 일차 수정 기능에 고정 항목과 변경 비용을
추가하여 기존 일정을 가능한 한 유지하는 재계획 방법을 비교한다. 장소 삭제,
체류시간 증가, 출발 지연 시나리오에서 제약 충족과 일정 보존을 함께 평가한다.
수정량을 줄이는 대가로 늘어나는 이동시간과 계산시간도 분석한다.

**핵심 아이디어와 연구 질문.** 방문 완료 항목과 사용자가 고정한 장소·시간은
변경할 수 없는 제약으로 둔다. 변경 비용은 장소 삭제·추가 수, 남은 장소의 일차
변경 수, 남은 장소 쌍의 순서 역전 수로 나누어 계산한다. 먼저 제약을 만족시키고
그 안에서 위 순서대로 비용을 비교한 뒤 이동시간을 줄인다. 요청이 강제한 삭제는
별도로 기록하고 알고리즘이 추가한 변경을 비용으로 센다. 충돌로 해가 없으면 고정을
임의로 풀지 않고 충돌 항목을 반환한다. `revise_day`·`move_stop`을 재사용하되
큰 사례의 휴리스틱 탐색이 전역 최소 변경을 보장한다고 주장하지 않는다.

**실험 방법.** 기본 일정 50개에 삭제·체류시간 증가·출발 지연을 각각 적용하여
150개 수정 사례를 만든다. 현행 `revise_day`는 장소 추가·삭제만 받으므로 장소별
체류시간과 당일 출발시각을 받는 공통 평가 어댑터를 먼저 구현한다. 전체 재생성,
기존 일차 순서 재계산 규칙을 유지한 확장 기준선, 고정+변경 비용 방식에 같은
구조화된 요청을 넣는다. 확장 기준선은 원래 코드 그대로의 성능과 구별하며
자연어 해석 오류는 별도 실험으로 분리한다.
기본 일정 기준 10개는 조정용, 40개는 평가용으로 나누어 변형 사례가 섞이지 않게
한다. 작은 문제는 완전탐색 최적해와 대조하고 고정 조건이 충돌하는 사례도 넣는다.

**실험 결과 측정 방법.** 주 지표는 제약을 모두 지킨 해들 사이의 요청 외 장소 삭제·추가 수다.
고정 위반률과 전체 제약 충족률을 먼저 보고한 뒤, 공통으로 성공한 사례에서 변경량을
비교한다. 일차 변경 수·순서 역전 수·도착 시각 변화(분)와 방문 수·이동시간 증가율·
계산시간도 함께 기록한다. 공통으로 성공한 사례만
좋아 보이는 편향을 막기 위해 모든 사례의 실패 사유를 별도 표로 낸다. 선택적으로
참여자 20명에게 수정 전후를 보여 주고 원래 의도 보존 정도를 평가받되 탐색적
사용자 평가로 한정한다.

**관련 연구와 차이.** [Flex-TravelPlanner, Oh 외, 2025 프리프린트](https://arxiv.org/abs/2506.04649)는
순차적으로 추가되는 제약과 우선순위 충돌을 평가한다. 여기서는 모델의 대화 능력보다
기존 코스 편집 알고리즘이 고정 항목과 변경량을 얼마나 보존하는지 측정한다.

**향후 연구.** 여러 사용자의 고정 조건, 실제 교통 지연, 대화로 충돌 조건을 해소하는
절차를 연구한다. 첫 논문은 단일 사용자와 1~2일 일정에 집중한다.

### L4. 공공 POI와 지도 서비스 간 장소 일치 판정의 오류 비용과 보류 전략

**Abstract.** 같은 상호를 쓰는 다른 지점이나 좌표가 어긋난 시설을 잘못 연결하면
촬영지 주변 안내에 다른 가게의 정보가 붙는다. 본 연구는 SceneTrip의 이름·거리
규칙에 주소와 지점명 특징, 연결 보류 조건을 추가한다. 수작업 정답셋에서 정확한
연결을 얼마나 유지하면서 잘못된 연결을 줄이는지 비교하고 자동 처리율과 연결
정확도 사이의 관계를 분석한다.

**핵심 아이디어와 연구 질문.** 현행 `v3`도 이름·거리 조건을 통과한 후보가 없으면
미연결을 반환한다. 여기에 상위 두 후보의 점수 차가 작거나 주소·지점명이 충돌할 때
판단을 미루는 조건을 더한다. 현행 `v3`의 사유 코드를 오류 분석에 활용한다.
새 대형 모델 학습보다 동일 상호의 다른 지점을 구별하는 특징과 추가 보류
기준에 따른 변화를 밝히는 데 집중한다. 전화번호는 확보된
자료에만 쓰며 필수 입력으로 가정하지 않는다.

**실험 방법.** 한두 지역의 기준 POI 150곳에서 후보쌍 450개를 목표로 수집한다.
각 기준 POI의 전체 후보 목록과 정답 장소 또는 ‘후보에 정답 없음’을 함께 라벨링한다.
비교군은 최근접 연결, 현행 `v3`, 주소·지점명 추가, 추가 특징+보류 방식이다.
동명이점·체인점·넓은 관광지·좌표 오차 사례를 구분하여 표집한다. 동일 기준 POI와
지점은 분할을 넘지 않도록 묶고 조정 30%, 평가 70%로 나눈다. 두 평가자가 독립
판정하며 확인 불가능한 쌍은 불확실 라벨로 따로 보고한다.

**실험 결과 측정 방법.** 주 지표는 자동 연결 중 틀린 장소에 연결한 비율이다.
정확한 연결 수를 전체 기준 POI 수로 나눈 비율과, 자동 연결 수를 전체 기준 POI 수로
나눈 처리율을 함께 보고한다. 정답 후보가 존재하는 POI에 대한 연결 재현율도 별도로
계산한다. 보류 임계값을 바꾼 정확도–처리율 곡선, 지점 오연결률, 유형별 혼동표를
제시한다. 후보 검색 단계에서 정답을 놓친 비율도 측정하여 연결기의 실패와 구분한다.
오연결 비용과 미연결 비용의 비율을 1:1, 5:1, 10:1로 바꿔 민감도를 분석하되 실제
사업 손실액으로 해석하지 않는다.

**관련 구현과 차이.** [ADR 0014](../../docs/architecture/adr/0014-poi-source-is-public-data.md)는
공공데이터의 중복과 주소·전화번호 제약을 기록한다. 논문은 이 도메인에서 실제로
틀리는 장소 연결과 보류의 효과를 정답셋으로 검증한다. 일반적인 문자열 유사도나
거리 비교를 독창적 기법이라고 주장하지 않는다.

관련 학술연구인 [Deep Learning for Entity Matching: A Design Space Exploration,
Mudgal 외, SIGMOD 2018](https://pages.cs.wisc.edu/~anhai/papers1/deepmatcher-tr.pdf)은
데이터 형태별 개체 매칭 방법을 비교한다. 대조군 선택의 배경으로 삼되 POI 전용
연구나 보류 전략의 직접 근거로 소개하지 않는다. 첫 실험에서는 작은 정답셋에 맞는
규칙·간단한 점수 모델부터 평가한다.

**향후 연구.** 지역을 바꾼 일반화, 폐업·이전 정보의 시간 변화, 수작업 확인이 필요한
후보부터 고르는 능동학습을 다룬다. 초기 연구는 공개·사용 허용된 자료와 허용된 조회
결과만 사용하며 외부 지도 서비스의 대량 자동 수집을 전제하지 않는다.

### L5. 위치 정확도와 체류 조건에 따른 촬영지 방문 판정의 오탐·지연 분석

**Abstract.** 촬영지 근처를 지나가거나 건물 사이에서 GPS가 흔들리면 자동 방문
판정이 잘못되거나 늦어질 수 있다. 본 연구는 SceneTrip의 고정 반경·연속 체류
방식에 위치 정확도 조건과 서로 다른 진입·이탈 반경을 적용한다. 실제 수집한 같은
로그를 각 방식에 재생하여 방문 오탐과 판정 지연의 관계를 측정한다. 노이즈를
추가한 실험과 실기기 실험을 분리하여 결과의 적용 범위를 밝힌다.

**핵심 아이디어와 연구 질문.** 정확도가 낮은 관측은 바로 진입·이탈로 확정하지
않고 보류한다. 경계 부근의 한 번의 튐으로 체류시간이 초기화되지 않도록 진입과
이탈에 다른 조건을 둔다. 다만 관측이 오래 끊겼을 때 체류시간을 무한히 누적하지
않도록 최대 공백 시간도 둔다. 질문은 ‘오탐을 줄이는 만큼 알림이 얼마나 늦어지는가’다.

**실험 방법.** 개방 공간·건물 밀집 지역·인접 촬영지를 포함한 8곳, 참여자 6명,
실방문·통과·근처 대기 3상황의 144회 로그를 목표로 한다. 관찰자가 실제 도착·출발
시각과 장소를 별도로 기록한다. 100 m 진입 즉시 판정, 현행 100 m·300초 방식, 정확도 조건만
추가한 방식, 정확도+진입·이탈 분리 방식에 같은 로그를 넣는다. 조정용 장소와
평가용 장소를 나누고 참여자별 결과도 제시한다. 실험에서는 실기기 300초를 기준으로
삼으며 시뮬레이터의 5초 설정을 현장 성능으로 보고하지 않는다.
실방문과 근처 대기는 모두 600초 동안 관찰하여 300초 이후의 판정 기회를 확보한다.
근처 대기의 정답은 원형 반경이 아니라 관찰자가 확인한 실제 장소의 방문 여부다.

**실험 결과 측정 방법.** 주 지표는 통과·대기 상황의 오방문 판정률이다.
방문 정밀도·재현율, 중복 판정 수, 체류 타이머 초기화 횟수, 판정 지연의 중앙값과
95백분위수를 함께 제시한다. 실제 도착 시각부터의 총지연과 정해진 체류시간을
충족한 시점 이후의 추가 지연을 구분한다. 이벤트 대응 시간 범위와 위치 기준은
평가 전에 고정하며 같은 사람의 연속 위치점을 독립 표본으로 세지 않는다.
종료까지 판정하지 못한 실제 방문은 미탐지로 센다. 지연 분포에는 탐지된 사례 수를
붙이고 전체 실제 방문 중 제한 시간 내 탐지율도 보고한다.
배터리는 로그 재생으로 측정할 수 없으므로 별도 실기기 실험을 했을 때만 주장한다.

**관련 연구와 차이.** [Pérez-Torres 외, Sensors 2016](https://doi.org/10.3390/s16101693)은
스마트폰 내부의 체류 지점 탐지와 GPS 수집 간격·에너지 소비를 다룬다.
여기서는 이미 알려진 탐지 요소를 촬영지 방문 판정에 적용하고 경계 통과·인접 장소에서 나타나는
오탐과 안내 지연을 평가한다. 센서 융합이나 히스테리시스 자체를 새 발명으로 삼지 않는다.

**향후 연구.** 다른 기종·도시, 화면이 꺼진 상태, OS 방문 탐지 기능과 비교한다.
접근 가능한 영역과 실제 출입구 좌표를 결합하는 연구도 가능하다.

## 4. 공통 실험 원칙과 8주 착수안

평가 지표와 분할 단위는 실험 전에 정한다. 장소·기본 일정·질문 묶음이 조정용과
평가용에 동시에 들어가면 유사한 사례를 외운 효과가 섞인다. 결과는 평균만 제시하지
않고 유형별 실패, 효과 크기, 95% 신뢰구간을 함께 보고한다. 반복 생성은 문항별로,
GPS 로그는 참여자·경로별로 묶어 불확실성을 계산한다. 소규모 사용자 평가는 탐색적
결과이며 충분한 검정력이 확보됐다고 가정하지 않는다.

데이터가 부족하면 합성 사례로 조건별 동작을 검증할 수 있다. 다만 합성 자료의 결과와
실제 자료의 결과는 분리한다. 정답 작성자의 선호를 정답처럼 넣는 대신, 문헌·현장
관찰·원본 레코드에 근거한 판정 규칙을 남긴다. 참여자 로그는 동의를 받아 수집하고
연구와 무관한 이동 기록을 제외한다. 장면 스틸은
[ADR 0007](../../docs/architecture/adr/0007-scene-still-images-pending-rights.md)에 권리 미결로
기록돼 있으므로 논문·공개 데이터셋에는 직접 제작하거나 사용 권한을 확인한 자료를 쓴다.

| 기간 | 수행할 일 | 남길 산출물 |
| --- | --- | --- |
| 1주 | 한 주제 선택, 선행연구 확인, 실험 질문·주 지표 고정 | 연구 질문과 평가표 |
| 2주 | 자료 확보, 정답 작성 규칙과 데이터 분할 확정 | 버전이 있는 입력·정답셋 |
| 3~4주 | 대조군 재현, 최소 제안 기법 구현 | 같은 입력을 받는 비교 프로그램 |
| 5주 | 작은 예비실험으로 구현 오류와 지표 계산 확인 | 오류 수정 기록, 봉인한 평가 설정 |
| 6주 | 최종 평가와 구성요소 제거 실험 | 원시 결과, 비용·시간 기록 |
| 7주 | 실패 사례·신뢰구간 분석 | 비교표·그래프와 한계 |
| 8주 | 결과를 초록에 반영하고 원고·발표 자료 작성 | 제출 초안과 재현 절차 |

현장 수집이나 경로 데이터 확보가 늦으면 9~10주를 사용한다. 위 기간은 논문 한 편
기준이며 다섯 주제를 동시에 수행한다는 계획이 아니다. 구현을 시작할 때는 계약 변경을
먼저 반영하고 평가를 Bazel 타깃으로 선언한 뒤 `just` 레시피로 실행한다.

## 5. 특허 아이디어 5개

### 선행문헌 조사 범위

Google Patents에서 여행 일정 갱신, 부분 재계획, 출처 기반 답변, 위치 기반 해설,
지오펜싱, 촬영 보조를 검색하고 아래 문헌의 서지·본문·청구항을 확인했다.
대표 검색어는 `dynamic tourist travel planner`, `travel itinerary partial update`,
`corpus authority answer`, `GPS theater`, `geofencing location accuracy`,
`photography assistance`, `AR 관광 영상`이다.

아래 표는 관련성이 있는 문헌 목록이다. 같은 구성이 모두 같은 문헌에 기재됐다는 뜻도,
빠진 문헌이 없다는 뜻도 아니다. A·A1 공개공보와 B1·B2 등록공보를 구분하며
공개공보를 등록 권리로 표현하지 않는다. 국가별 현행 청구항·법적 상태와 동일 특허군의
전체 범위는 이번 조사에서 확정하지 않았다. KIPRIS·PATENTSCOPE·각국 등록원부의 추가
검색과 비특허문헌 검토가 필요하다.

### T1. 근거 변경에 따른 여행 일정의 부분 재검증 및 최소 수정 방법

**문제와 핵심 아이디어.** 장소 영업시간이나 이동시간이 바뀔 때 모든 일정을 다시
만들면 고정한 약속까지 달라질 수 있다. 일정 항목마다 적용 제약·외부 근거 버전·유효기간을
연결하고 변경된 근거에 의존한 항목만 먼저 무효화한다. 영향을 받는 구간을 계산한 뒤
사용자 고정을 보존하는 최소 수정안을 만든다. 수정 후에는 전체 필수 제약을 재검증한다.

**입력·처리·출력.** 입력은 현재 일정, 사용자 고정 항목, 이동·영업정보와 그 버전이다.
의존 관계 그래프에서 변경 영향 범위를 찾고 고정 항목 사이의 후보 구간부터 다시
계산한다. 경계를 넘는 영향이 있으면 범위를 확장하며 최종 검증을 통과한 경우에만
수정 패치와 검증 근거를 출력한다. 원래 일정의 버전이 달라졌으면 패치를 적용하지
않고 다시 검증한다. 출력에는 변경 항목, 변경 사유, 사용한 근거 버전이 포함된다.

**권리화 검토의 초점.** ‘AI가 여행 일정을 수정한다’는 기능은 범위가 너무 넓다.
근거 버전의 무효화 → 영향 구간 산출 → 고정 제약 보존 → 전체 제약 검증 → 버전이
맞는 패치 적용이라는 처리 순서와 자료 구조를 구체화한다. 후보 구간만 계산하더라도
전역 제약을 놓치지 않는 조건을 설명할 수 있어야 한다.

**관련 특허와 겹침.** [S1](https://patents.google.com/patent/EP4019903A1/en)은 위치에 따른
동적 일정 갱신, [S2](https://patents.google.com/patent/EP2708850A1/en)는 지연에 따른 구간
대체, [S3](https://patents.google.com/patent/US11250354B2/en)는 항목 변경의 영향 전파를
다룬다. [S4](https://patents.google.com/patent/WO2025111592A1/en)는 생성형 AI와 대화하며
대체 일정을 제공한다. 부분 수정·영향 분석·대화만으로 차별성을 주장하기 어렵다.
근거 버전과 검증 가능한 패치의 결합도 별도 선행조사가 필요한 가설이다.

**시제품과 측정.** L1·L3의 플래너에 의존 관계와 일정 버전을 추가한다. 전체 재검증
방식과 비교하여 재계산 항목 수·API 호출 수·시간·잔존 위반율·고정 위반율을 잰다.
검증기를 분리했지만 실제로는 같은 오류를 공유하는 경우를 잡도록 수작업 사례와
완전탐색 정답을 함께 둔다.

### T2. 사실 유형과 유효기간을 이용한 현장 가이드의 생성·갱신 제어 방법

**문제와 핵심 아이디어.** 촬영 당시 사실, 극중 설정, 현재 출입 정보는 적용 시점과
의미가 다르다. 이들을 같은 사실처럼 답하면 현재 들어갈 수 없는 곳을 안내하거나
극중 사건을 실제 역사로 설명할 수 있다. 각 주장에 장소·사실 유형·적용 기간·출처를
붙이고 현재 여행 맥락과 맞는 주장만 출력하도록 한다.

**입력·처리·출력.** 입력은 질문, 장소 ID, 여행 시각, 유형별 근거 레코드다. 후보
주장의 장소와 유효기간을 검사하고 같은 유형의 출처가 충돌하면 확인된 부분만
답하거나 보류한다. 답변의 문장·음성 캐시와 근거의 의존 관계를 저장하여 근거가
바뀌면 해당 구간만 무효화한다. 출력은 검증된 안내와 출처, 보류 사유, 갱신 대상이다.
출처가 오래됐다는 이유로 영구적인 촬영 사실까지 무효화하지 않도록 유형별 규칙을 둔다.

**권리화 검토의 초점.** 사실 유형별 시간 유효성 검사와 출처 충돌 처리, 문장·음성
구간의 선택적 무효화가 실제로 어떻게 연결되는지를 설명한다. 출처 점수나 RAG를
사용했다는 사실만으로는 차별성이 약하다.

**관련 특허와 겹침.** [S5](https://patents.google.com/patent/US20160217209A1/en)는
답변을 뒷받침하는 출처의 권위를 산출해 후보를 선택하며 임계값 미달 답변을 제거하는
구성도 다룬다. 따라서 신뢰도에 따른 보류 자체는 겹친다.
[S8](https://patents.google.com/patent/US11496863B2/en)은 지점별 안내 콘텐츠의 전달과
재생을 다룬다. 시간·유형 검증에 따른 안내 캐시 변경이 이들 구성 및 비특허문헌과
어떻게 다른지 추가 검토한다.

**시제품과 측정.** L2의 정답셋에 폐쇄·이전·잘못 연결된 작품 설정 사례를 추가한다.
오래된 정보 발화율, 사실 유형 혼동률, 충돌 탐지율, 근거 수정 후 잘못된 캐시가 남는
시간을 잰다. 기술 효과는 실험 전 가설이며 대답을 줄인 효과와 구분한다.

### T3. 작품 시청 범위와 현장 방문 순서를 반영한 장면 해설 재배열 방법

**문제와 핵심 아이디어.** 이동하기 편한 촬영지 순서는 작품의 장면 순서와 다르다.
장소에 맞는 해설을 그대로 재생하면 아직 보지 않은 회차의 내용이나 앞 설명이 필요한
정보가 먼저 나올 수 있다. 이동 경로 그래프와 장면 설명의 선후관계 그래프를 따로
두고 사용자가 허용한 회차와 이미 들은 설명을 만족하는 해설만 순서에 맞게 선택한다.

**입력·처리·출력.** 입력은 방문 순서, 시청 범위, 장면별 공개 허용 범위, 설명의
선행 조건과 재생 이력이다. 현재 장소에서 재생 가능한 노드를 찾고 필요한 배경
설명이 허용 범위 안에 있으면 먼저 삽입한다. 선행 조건을 만족시킬 수 없으면 해당
해설을 생략하거나 사용자에게 확인한다. 경로가 바뀌면 방문 순서와 해설 대기열을
함께 갱신한다. 출력은 장소별 재생 목록과 삽입·생략 사유다.

**권리화 검토의 초점.** 그래프 사용 일반론보다 이동 경로 변경이 해설 공개 조건과
선행 설명 충족 상태를 어떻게 갱신하는지가 검토 대상이다. 단순한 이야기 내용이나
취향 규칙에 머물지 않도록 단말의 재생·보류·재개 제어와 상태 저장 절차를 명시한다.

**관련 특허와 겹침.** [S6](https://patents.google.com/patent/US9550114B2/en)은 GPS와
이동 조건에 맞춘 이야기 재생을, [S7](https://patents.google.com/patent/US11255682B2/en)은
이동시간에 맞춘 설명 생성과 이야기 그래프를 다룬다. 비특허문헌인
[NarrativeGuide 연구, Zhang 외, 2025 프리프린트](https://arxiv.org/abs/2502.14456)도
서사 일관성과 이동시간을 함께 최적화한다. 이야기와 경로를 결합했다는 주장으로는
부족하며 시청 범위·선행 설명·재생 이력을 함께 처리하는 구성을 추가 조사해야 한다.

**시제품과 측정.** 직접 작성하거나 권한을 확인한 장면 요약으로 작품 2~3개와
촬영지별 해설 노드를 만든다. 일반 위치 재생과 비교하여 스포일러 허용 범위 위반률,
선행 설명 누락률, 중복 재생률, 대기열 갱신시간을 잰다. 소규모 이용자의 이야기
이해도는 보조 지표이며 자동 검증 지표와 별도로 제시한다.

### T4. 인접 촬영지의 위치 모호함을 반영한 방문 및 안내 상태 제어 방법

**문제와 핵심 아이디어.** 위치 오차 범위에 두 촬영지가 들어오면 가까운 좌표 하나만
고르는 방식은 다른 장소의 스탬프나 안내를 시작할 수 있다. 위치 정확도·체류 이력·
예정 방문지를 함께 보되 후보가 충분히 구별되지 않으면 판정을 보류한다. 장소
확정과 방문 기록·안내 재생을 하나의 상태 전이로 관리하여 중복 적용을 막는다.

**입력·처리·출력.** 입력은 위치·관측 시각·보고된 정확도, 후보 장소, 여행 세션이다.
후보별 가능 영역과 체류 근거를 갱신하고 후보 간 차이가 부족하면 추가 관측이나
사용자 확인을 요청한다. 예정 방문지는 보조 신호이며 위치 근거를 덮어쓰지 않는다.
확정 후 세션·장소·방문 회차 식별자를 붙인 이벤트를 내보내고 이미 처리한 이벤트는
재적용하지 않는다. 출력은 방문 확정·보류·취소와 안내 시작·재개 상태다.

**권리화 검토의 초점.** 위치 모호함의 해소 조건과 방문 기록·콘텐츠 제어의 결합을
구체화한다. GPS 정확도 값은 실제 오차의 보증으로 취급하지 않는다. 연결이 끊겼다가
돌아오거나 후보 장소가 바뀌는 경우의 상태 전이도 정의해야 한다.

**관련 특허와 겹침.** [S9](https://patents.google.com/patent/US9215560B1/en)는 위치
오차 영역과 지오펜스 중첩, 정확도에 따른 센서 사용, 서로 다른 진입·이탈 임계값을
다룬다. [S8](https://patents.google.com/patent/US11496863B2/en)은 위치·방향에 따른
오디오 투어 재생을 다룬다. 센서 융합과 도착 시 재생은 이미 가까운 기술이다.
후보 간 모호함, 방문 이벤트 중복 제거, 재생 상태의 결합 역시 알려진 기술들의 단순
결합인지 검토해야 하며 명칭만 바꿔 차이를 주장하지 않는다.

**시제품과 측정.** L5의 로그에 인접 촬영지와 통신 재연결 사례를 넣는다. 잘못된
장소 확정률·중복 스탬프율·오안내율·확정 지연·사용자 확인 횟수를 비교한다.
기록된 위치를 쓰는 초기 시제품에 카메라나 별도 센서를 필수로 붙일 필요는 없다.

### T5. 변화한 배경을 제외하고 촬영 가능 영역 안에서 구도를 안내하는 방법

**문제와 핵심 아이디어.** 드라마 장면에는 배우·차량·CG처럼 현장에서 재현할 수
없는 요소가 섞여 있다. 장면 전체를 맞추려 하면 잘못된 촬영 위치를 권할 수 있다.
참조 영상과 현재 영상에서 유지된 배경만 정합에 사용하고 유효한 일치 영역이
부족하면 이동 안내를 보류한다. 위치 제안은 사전에 확인한 촬영 가능 영역으로 제한한다.

**입력·처리·출력.** 입력은 사용 권한을 확인한 참조 이미지, 현재 영상, 변화 영역
마스크, 촬영 가능 영역이다. 첫 시제품에서는 마스크와 영역을 사람이 지정한다.
유지된 배경의 특징점으로 정합을 추정하고 오차·유효점 분포를 확인한다. 단안 영상만으로
정확한 이동 거리를 보장하지 않고 미리 수집한 촬영 지점 후보나 자세 센서로 보완한다.
출력은 구도 조정 방향, 허용된 촬영 지점 후보, 정합 불확실 시 보류 사유다.

**권리화 검토의 초점.** 제외 영역 선정 → 유지 배경 정합 → 불확실성 판정 →
촬영 가능 영역 검사 → 안내 또는 보류의 처리 절차를 검토한다. 두 영상의 정합만으로
현장의 보행 안전을 판정한다고 주장하지 않는다. 기존 컴퓨터비전 기법을 단순히
촬영지에 적용한 것과 구별할 구체적인 기술 효과가 있어야 한다.

**관련 특허와 겹침.** [S10](https://patents.google.com/patent/KR102671004B1/ko)은

## 7. 논문과 특허를 함께 진행할 때

논문에서는 비교 가능한 연구 질문과 검증 결과를, 특허에서는 구체적인 구성요소와
처리 절차의 차이를 중심으로 정리한다. 논문 실험이 잘 나왔다는 사실만으로 특허의
신규성이 증명되지는 않는다. T1·T2는 현재 코드와 연결하기 쉽지만 일반 일정 갱신·
출처 기반 답변 기술과 겹치는 범위가 넓다. T3~T5는 데이터와 구현 부담이 더 크고
일반적인 스토리·센서·영상 기법을 단순 결합한 것은 아닌지 살펴야 한다.

출원을 검토한다면 공개 발표·논문 공개 전에 학교 산학협력단이나 변리사와 공개 시점,
발명자·권리 귀속, 출원 국가를 정리한다. 출원 전 공개가 신규성에 영향을 줄 수 있으며
예외의 범위는 국가마다 다르다. [WIPO 특허 FAQ](https://www.wipo.int/en/web/patents/faq_patents).

측정 결과다. 이 문서는 그 후보를 고르기 위한 조사·연구계획서다.
