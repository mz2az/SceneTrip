# 작품 포스터를 기기에 30일 보관 + 화면 크기로 줄여 그리기 (MZ2AZ-507, 2026-11-10)

작품 포스터는 방송사·OTT 공식 사이트의 이미지를 주소로 받는다(우리가 저장·재배포하지 않음, ADR 0007). 우리 서버에 없으니
서버에서 줄일 수 없고, 앱이 받아 둔다. **포스터만** 다룬다 — 우리 서버(S3)에 있는 장소 사진·장면 그림은 서버 쪽 썸네일 같은
방법으로 따로 정한다(2026-11-10 사용자 결정). 서버 쪽 짝 티켓(MZ2AZ-508, 포스터 주소를 작은 크기로)은 끝났다 — 128장 46MB → 약 16MB.

## 지금 (2026-11-10 코드 확인)

| | iOS | Android |
| --- | --- | --- |
| 화면 크기로 줄여 풀기 | ✗ `AsyncImage` 가 원본 크기로 푼다 | ✓ 긴 변 약 360px(`ImageCache.load`) |
| 메모리 보관 | ✗ (관광공사 사진 로더 `PhotoLoader` 만 80MB) | ✓ 80MB |
| 기기(디스크) 보관 | 시스템 기본 `URLCache` 뿐 | ✗ |

포스터를 그리는 곳 — iOS: 검색 줄·추천 목록·작품 상세(`RemoteImage`), 프로필 찜 목록, 홈 작품 카드·지금 뜨는 작품, 새 코스의 작품 고르기·첫 화면 그림.
Android: 같은 화면들(`RemoteImage`·`NewCoursePhoto`).

## 규칙 (두 앱 같게)

- **보관:** 받은 원본 바이트를 앱 캐시 폴더 `posters/` 에 파일 하나로. 파일 이름은 포스터 주소의 SHA-256 16진수 — 주소가 바뀌면 새 파일이라 낡은 그림이 남지 않는다.
- **기간:** 저장한 지 **30일**이 지난 파일은 쓰지 않고 지운 뒤 다시 받는다.
- **용량:** 합계 **100MB** 를 넘으면 마지막으로 쓴 때가 오래된 것부터 지운다(새로 저장한 직후에 본다). 읽을 때마다 「마지막으로 쓴 때」 를 지금으로.
- **그리기:** 기기 보관이나 네트워크에서 받은 바이트를 화면 크기로 줄여 푼다 — 긴 변 **360px**(Android 지금 값, iOS 사진 로더와 같다). 푼 그림은 메모리에(iOS 새로 80MB, Android 지금 것).
- **순서:** 메모리 → 기기 보관 → 네트워크. 네트워크 응답은 성공(2xx)이고 24MB 이하일 때만 저장한다(Android 지금 상한).
- **실패:** 링크가 깨졌거나 오프라인이면 지금처럼 자리표시자. 실패는 저장하지 않는다.
- **하지 않는 것:** 사용자 사진(후기·여행후기)·장소 사진·장면 그림은 기기에 남기지 않는다(지금처럼). 새 라이브러리를 들이지 않는다.

## 순수 규칙 (시험을 먼저 쓴다)

`PosterDiskRules`(두 앱 각각):
- `fileName(url)` → SHA-256 16진수(소문자 64자).
- `expired(savedAt, now)` → 30일(정확히 30×24시간)을 넘었나.
- `evictions(entries, maxBytes)` → 지울 이름들. `entries` 는 (이름, 바이트, 마지막으로 쓴 때). 합계가 `maxBytes` 이하가 될 때까지 마지막으로 쓴 때가 오래된 것부터, 같으면 이름순.
- 상수: 30일, 100MB, 360px, 24MB.

## 완료 조건

- 앱을 껐다 켠 뒤 홈·검색의 작품 포스터를 열 때 이미 본 포스터를 네트워크로 다시 받지 않는다(시뮬레이터·에뮬레이터 네트워크 기록).
- iOS 에서 큰 포스터(JTBC 등)를 원본 크기로 풀지 않는다.
- 30일 지난 파일과 100MB 넘는 몫이 지워진다(순수 규칙 시험).
