# 커뮤니티 블로그형 본문과 AI 변환 사진 (MZ2AZ-428)

상단 사진 슬라이드를 대표 사진 한 장으로 바꾸고, 본문 문단 사이에 작성자가 정한
사진을 표시한다. 문단·사진 순서는 서버에 저장한다. 기기에 남은 옛 후기 두 개와
사진 다섯 장, 기존 서버 글·첨부 코스·권한·불확실한 게시 응답 처리도 보존한다.

## 계약과 저장

`TripPostCreate`와 `TripPostDetail`에 선택적인 `bodyBlocks` 배열을 더한다.
기존 생성자 순서를 유지하도록 새 속성은 기존 속성 뒤에 선언한다.
텍스트 블록은 `text`, 사진 블록은 기존 `photoKeys`/`photoUrls`의 `photoIndex`를
참조한다. 임의 HTML이나 외부 이미지 URL을 받지 않는다. 사진에는 선택적인
`caption`, `credit`, `aiGenerated` 표시를 둔다. 첫 사진이 대표인 기존 규칙은 유지한다.

텍스트 블록을 빈 줄로 이어 붙인 값이 `body`와 같아야 한다. 사진 인덱스는 유효한
범위에 있어야 하고 각 첨부 사진이 본문에서 한 번씩 참조돼야 한다. 최대 텍스트
64개·사진 8개를 허용한다. V32는 선택적인 JSONB `body_blocks` 칸을 더하며, 기존
글은 NULL을 유지한다. 사진·코스 사본 표는 변경하지 않는다.

## iOS 작성·읽기

빈 줄을 문단 경계로 사용한다. 사진별 삽입 위치·설명·AI 변환 표시를 정하고
미리보기에서 대표 사진 및 실제 문단/사진 순서를 확인한다. 사진을 지우거나 문단을
줄이면 현재 사진 목록에 맞춰 인덱스·삽입 위치를 다시 산정한다. 업로드 중·실패한
사진은 기존 규칙대로 게시를 막고, 게시 응답을 잃었을 때 본문 배치도 대조한다.

상세는 제목·작성자와 대표 사진 한 장, 문단/사진 배열, 첨부 코스 순서로 읽는다.
사진은 원래 비율과 설명·출처·AI 변환 표시를 유지하고 누르면 100~400%로 확대한다.
배치가 없는 옛 글은 본문 문단 사이에 기존 사진을 순서대로 표시한다. 옛 기기 글을
다시 저장하거나 공개 게시하지 않는다. Android는 기존 동기화 세션이 계약 반영 뒤
별도 브랜치에서 맞춘다.

## 추천 가이드 사진

MZ2AZ-423의 추천 글 20개·코스 20개는 유지한다. 사진 첨부 32개에 쓰인 원본 31개를
내장 이미지 생성 도구로 변환한다. 장소의 건물·지형·간판 등 사실은 유지하고 구도를
조정하며 사람을 제거한다. 결과를 실제 사진과 대조한 뒤 새 파일로 저장한다. 원본 URL,
이용 유형, 입력/출력 해시, 프롬프트, 장소·가이드 대응은 제작 이력에 남긴다.
AI 변환 표시는 실제 적용한 사진에만 붙인다. 사용자가 전달한 변호사 상담과 제작
방침을 따른다. 이미 확인한 공공누리 제1유형 원본의 출처 표기는 유지한다.

적용은 로컬 kind DB/MinIO의 지정된 추천 글 20개만 대상으로 한다. 기존 글·사진·코스와
사용자 자료를 먼저 백업하고 소유자 및 기대 상태가 일치할 때만 트랜잭션으로 갱신한다.
운영 환경 적재·AWS 배포는 자동 실행하지 않는다.

사진은 내용 해시·가이드·사진 순서에서 계산한 새 UUID 키로 로컬 MinIO에 올린다.
기존 키를 덮거나 지우지 않는다. 원본 객체와 게시글·사진·코스 사본을 별도 상태 폴더에
백업한다. DB 갱신 직전 지정 글을 잠그고 원래 행/사진/코스 사본을 다시 대조하며, 글 본문·배치와
사진 키만 한 트랜잭션으로 갱신한다. 중단 후 같은 상태 폴더로 재개하고 이미 적용한 값도 대조한다.

## 검증과 완료

계약 생성 뒤 잘못된 블록·사진 인덱스·본문 불일치 거절, 순서 저장/복원, 옛 글 호환,
업로드 실패/불확실 게시와 사진 삭제 시 배치를 시험한다. 로컬 실제 글·사진 업로드와
읽기, 대표 사진 한 장, 문단별 사진, 확대·실패 재시도·라이트/다크·큰 글자를 확인한다.
검증 에이전트 검토 및 `just check`, CI 로그 확인 뒤 PR로 main에 반영한다. 실제
촬영지/권호님 최신 SQL 적재 상태 확인은 별도 데이터 감사 결과를 따른다.
