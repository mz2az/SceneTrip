# 웹 「어디로 가세요?」 시안 — 로컬에서만 보는 껍데기

- **상태**: 시안 B 로 좁힘(2026-11-07, 디자인 점검 반영). 로컬(`just web-dev`)에서만 본다. 고른 안만 다듬어 dev → main 으로 낸다
- **왜**: 광고로 온 사람의 대부분이 첫 화면만 보고 나간다. 1주차 광고에서 「Coming to Korea this week?」 소재만 앱 안 행동 3.8%(다른 소재 0.3%·1.5%)
  — 이미 여행을 정한 사람에게는 「어떤 드라마?」 보다 **「어디로 가세요?」** 가 먼저다. 앱의 주된 길을 도시 → 며칠 → 촬영지(직접 고르기 또는 알아서) → 코스로 바꾼다
- **기반**: `dev` 브랜치(main + 웹 실험 #416 도시별 성지·#417·#418). 도시 묶기는 #416 의 `homeCities.ts`·`homeCityModel.ts` 를 그대로 쓴다
- **누구**: 광고로 처음 온 외국인 여행자(방문자의 85% 이상 몽골, 앱 기본 언어 영어). 휴대폰, 처음 보는 앱

## 1. 바꿔 보는 법

`SCENETRIP_NO_API_CACHE=1 just web-dev` → `http://localhost:5173/?proto=b` (`a` 질문 카드만, 끄기 `off`). 고른 값은 탭을 닫을 때까지 남는다(sessionStorage).
화면 오른쪽 아래 「시안」 단추로 바꾸고 「처음부터」 로 시안의 저장값(여행)을 지운다. **값을 주지 않으면 지금 화면 그대로다.** 배포 번들(`import.meta.env.DEV` 가 거짓)에서는 장치 자체가 켜지지 않는다.

`SCENETRIP_NO_API_CACHE=1` 이 필요한 이유: 개발 서버의 응답 캐시(`vite.config.ts`)가 열쇠에 `X-Install-Id` 를 넣지 않아, 담은 뒤 `GET /cart` 가 10분 동안 옛 답을 돌려준다.

## 2. 결정(사용자, 2026-11-07)

| # | 정한 것 | 왜 |
| --- | --- | --- |
| 1 | 「아직 몰라요」 → 지금 홈 + 맨 위 「어디로 여행 가세요?」 카드(시안 A 의 카드) | 여행지를 안 정한 사람도 막다른 길 없이 둘러보고, 마음이 생기면 바로 고른다 |
| 2 | 전체 화면 질문은 **처음 온 사람만**: 정한 여행 없음 + 코스 0개 + 장바구니 0곳 | 기존 사용자가 자기 코스를 이어 보려는데 끼어들지 않는다. 기존 사용자는 홈 맨 위 카드만 본다 |
| 3 | 「며칠?」 다음 갈림 「직접 고를게요 / 알아서 짜 주세요」 — 시안에서는 둘 다 껍데기 그대로 | 지금은 화면 비교 단계다. 운영에 낼 때 「알아서」 를 앱 계산으로 낼지 서버 AI 로 낼지 따로 정한다 |
| 4 | 코스를 만든 직후 = 기존 코스 편집 화면 + 맨 위 한 줄 안내(6초) | 처음 보는 복잡한 화면에서 「뭐지?」 대신 「됐다, 이제 고치면 된다」 |

## 3. 화면과 위계 (먼저 보이는 순서)

```
처음 온 사람
 ┌ Q1 도시 ─────────────┐   ┌ Q2 며칠 ────────┐   ┌ Q3 어떻게 ──────────────┐
 │ ① 해태 + 앱 한 줄      │   │ ① 「부산, 며칠?」 │   │ ① 「코스를 어떻게 짤까요?」│
 │ ② 「한국 어디로?」      │ → │ ② 당일·2·3·4일   │ → │ ② 알아서 짜 주세요(주)   │
 │ ③ 도시 사진 8칸         │   │    큰 단추 4개   │   │ ③ 직접 고를게요(보조)    │
 │ ④ 「아직 몰라요」 (작게) │   └──────────────────┘   └────────────────────────┘
 └──────────────────────┘                                  │              │
                                                    알아서 → 초안 미리보기   직접 → 촬영지 목록(담기)
                                                    (빼기·바꾸기·순서)       (아래 「N곳으로 코스 만들기」)
                                                              └──── 저장 → 코스 편집 + 한 줄 안내 ────┘
다시 온 사람(여행 있음) : 홈 맨 위 「내 여행 · 부산 · 2일」 카드 ① 여행 이름 ② 상태 한 줄 ③ 주 단추 ④ 더 보기·다른 여행
기존 사용자·「아직 몰라요」 : 홈 맨 위 「어디로 여행 가세요?」 카드(도시 칩) → 촬영지 목록 → 며칠 → 코스
```

- 질문 화면 셋은 위에 **진행 점 3개**(지금 단계 강조)와 뒤로 단추. 단계마다 할 일이 하나라 「다음」 단추가 없다 — 고르면 넘어간다
- 「알아서 짜 주세요」 를 주 단추(채운 파랑)로, 「직접 고를게요」 를 보조(테두리)로 — 처음 온 사람에게는 고르는 부담이 적은 쪽이 먼저다
- 도시 칸은 촬영지 수가 많은 순 8곳(서울·부산·제주·인천·수원·포항·대구·경주 …, #416 의 고정 순서). 칸마다 그 도시 대표 사진 + 이름 + 「촬영지 N곳」

## 4. 상태

| 화면 | 받는 중 | 비었음 | 실패 | 됨 |
| --- | --- | --- | --- | --- |
| Q1 도시 | 회색 칸 8개(사진 자리) | 도시가 0개 = 실패와 같게 | 「목록을 못 불러왔어요」 + 다시 시도 단추 | 칸을 누르면 Q2 |
| 촬영지 목록 | (도시 목록과 함께 이미 받음) | 그 도시 촬영지가 없으면 「아직 촬영지가 없어요」 + 다른 도시 고르기 | 담기 실패: 기존 토스트(장바구니) | 담은 칸은 채운 단추 「담음」, 아래 단추 숫자가 오른다 |
| 초안 미리보기 | 「코스를 짜는 중이에요…」(약 1초, 껍데기) | 촬영지가 하루 수보다 적으면 있는 만큼만, 0이면 「이 도시는 촬영지가 적어요 — 직접 고르기」 | — (껍데기라 실패 없음) | 날마다 장소 줄 |
| 코스 저장 | 단추 「만드는 중…」(눌러도 다시 안 감) | 0곳이면 단추 잠금 | 단추 위 빨간 한 줄 + 다시 누르기 | 코스 편집 + 한 줄 안내 |
| 내 여행 카드 | — | 담은 곳 0: 「아직 담은 곳이 없어요」 + 「촬영지 고르기」 | 도시 목록 실패면 도시 이름만 | 코스 있음: 「코스 보기·고치기」 |

| 단계 | 하는 것 | 느낌 | 받쳐 주는 것 |

## 6. 기존 부품·규칙 (새로 만들지 않는다)

- 색·간격: `design/tokens.css` 의 `--accent`·`--grouped-background`·`--system-background`·`--card-shadow`·`--separator`. 카드 모양 `homeCard()`. 칩 모양은 #416 `HomeCitySpots` 의 Chip 과 같게
- 글자: 제목 26–28 heavy, 본문 15–17, 보조 12–14 `secondary` — 지금 앱(iOS 를 옮긴 크기) 그대로. 본문은 15 아래로 내리지 않는다
- 해태: `PinoMascot`(홈 머리글과 같은 것)
- 터치: 누르는 것은 모두 44×44 이상(초안의 빼기·바꾸기·순서 단추 포함). 사진 위 글자는 아래쪽 어둡게 깐 그라데이션 위에만
- 접근성: 질문 단추는 `aria-pressed`, 진행 점은 「1/3단계」 읽기 글자, 사진은 장식(`alt=""`)이고 이름이 글자로 따로 있다
