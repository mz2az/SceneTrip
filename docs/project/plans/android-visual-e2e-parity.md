# Android iOS 화면·E2E 동등성 확인

## 기준과 목표

2026-10-12 최신 `origin/main`의 iOS 앱을 기준으로 Android 앱의 화면과 사용자 흐름을 맞춘다.
시작 기준 커밋은 `6fa9df2`다. 기존 디자인 작업이 있는 기본 작업 트리는 보존하고,
`MZ2AZ-148-android-visual-e2e` 작업 트리에서 진행한다.

두 앱을 실제 기기에 설치하고 같은 로컬 API, 한국어·영어, 위치, 화면 단계로 비교한다.
스크린샷과 접근성 트리를 함께 사용해 글자·아이콘·간격·색·시트·오류·상태 전환을 확인한다.
운영체제 상태 표시줄과 시스템 인증·사진 선택 UI의 차이는 앱 자체 화면과 구분한다.

## 점검 순서

1. 두 앱의 빌드·실행, 서버 연결, 현재 화면을 확인한다.
2. 홈·탭바·프로필·설정·온보딩을 같은 단계에서 촬영하고 차이를 수정한다.
3. 검색·자동완성·필터·작품·촬영지·POI 상세·장바구니·사진첩·리뷰를 비교한다.
4. 코스 목록·생성·편집·저장·취소·공유·지도·가이드·여행 안내를 비교한다.
5. 커뮤니티·로그인 안내·닉네임·내 기록·언어 전환을 비교한다.
6. iOS에만 추가된 로직과 서버 계약 소비를 확인하고 Android에 반영한다.
7. 오류·빈 상태·큰 글자·시트 닫기·복귀·연속 탭 전환을 다시 확인한다.
8. Android 단위 테스트·실화면 E2E·전체 `just check`를 실행한다.
9. 비교 증거와 미검증 경로를 QA 기록에 남기고 커밋·PR로 제출한다.

## 검증 원칙

관찰한 차이마다 재현 조건과 두 앱의 결과를 기록한다. 상태 규칙 변경은 회귀 테스트를 먼저 작성한다.
APK/IPA 빌드는 기존 Bazel 타깃과 `just` 레시피를 사용한다. 새 소스는 BUILD 목록에 같이 반영한다.
공개 조회와 별도 테스트 데이터의 로컬 저장을 사용하며 사용자의 기존 계정·코스는 삭제하지 않는다.
실계정이 필요한 경로는 인증 가능 여부를 확인하고, 실행하지 못한 경로는 통과로 기록하지 않는다.
검증 결과가 빨간 상태에서는 완료로 보고하거나 병합하지 않는다.
