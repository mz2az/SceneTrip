# Android 커뮤니티 블로그 동기화 (MZ2AZ-428)

iOS PR266의 main e739948을 기준으로 Android 독립 브랜치에서 계약1.13을 소비한다.
iOS·서버·계약 소스, 공용 DB/MinIO 자료·root 시안과 기기 전용 원본은 변경하지 않는다.
이미 적용된 추천20글·AI32사진·20코스를 읽으며 seed/reset·사진 재생성은 하지 않는다.

## 구현

- 생성 모델 TripPostBlock을 사용해 빈 줄 문단·photoIndex·설명·출처·AI 표시를 저장/복원한다.
  최대64문단·8사진·설명500자·출처1000자와 본문5000자를 NFC/UTF-16 기준으로 검사한다.
- 초안 사진 UUID에 위치/메타데이터를 연결한다. 삭제 뒤 현재 배열로 인덱스를 다시 만들며,
  문단 감소 뒤 위치를 범위 안으로 맞춘다. 업로드 실패/대기·계정 변경·불확실 게시 잠금은 유지한다.
- 작성 위치 선택·설명·출처·AI 선택과 미리보기를 제공한다. 읽기/미리보기는 같은 블록 표시를 쓴다.
  대표 사진은 첫 장 하나, 본문 사진은 원래 비율로 표시하고 설명·출처를 번역하지 않는다.
- bodyBlocks가 없는 옛 서버/기기 글은 읽기 시 문단 사이 사진을 순서대로 배치한다.
  서명 URL을 디스크에 저장하거나 기기 글을 공개하지 않는다.
- 사진 로딩 실패/재시도·전체 화면100~400% 확대/이동·닫기·AI/출처를 제공한다.
  기존 씬 사진 확대의 공통 화면을 재사용해 씬의 실제 사진만 허용하는 규칙을 유지한다.
- 불확실 게시 확인은 사진 키/본문/코스뿐 아니라 보낸 bodyBlocks도 일치해야 성공으로 판단한다.

## 검증

먼저 불확실 게시의 블록 불일치 회귀를 실패시키고, 문단 정규화·삭제/재배치·범위·메타 한도·옛 글을
단위 검사한다. 별도 QA APK로 작성·미리보기·사진 실패/재시도·확대·라이트/다크·ko/en·배율1.6을 확인한다.
실제 공개 추천 글의 대표/문단/사진/출처/코스 화면을 확인하며 모의 QA와 실제 데이터 증거를 구분한다.
OAuth/사진첩부터 실제 게시까지의 연속 동선·실기기는 확인한 범위만 보고한다.
just check·PR CI 네 job과 원문 로그 확인 뒤 main에 병합하고 Jira428에 Android 범위를 기록한다.
HTML은 저장소에 만들지 않는다. 되돌리기는 Android PR revert이며 DB 조작은 필요하지 않다.
