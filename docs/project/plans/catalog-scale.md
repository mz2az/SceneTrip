# 목록 규모 — 작품 128편·촬영지 486곳에서 틀리게 보이는 화면 (MZ2AZ-372)

- **상태**: iOS 를 고쳤다(2026-10-09, 작업 트리). 검증에서 나온 것(코스 줄의 작품이 `scenes` 에 있다 · 찜 직후 다시
  읽기 · 칩을 켜면 끝까지 받기 · 홈이 온 것부터 그리기)을 같은 날 반영했다. Android 는 따라간다(§8)
- **담당**: 정승길(iOS). 서버 쪽 요청은 §6 — 정권호
- **근거**: 지라 MZ2AZ-372 본문(고칠 것 1~7 · 「서버 쪽」), 계약 `contracts/openapi/scene-api-v1.yaml`,
  로컬 DB(작품 128 · 보이는 촬영지 486, 2026-10-08 밤 적재)

이 문서의 사실은 코드와 로컬 서버에서 확인한 것이다. 확인하지 못한 것은 「추측」 이라고 적었다.

## 1. 무엇이 틀렸나 — 「앞쪽 N건이 전부」

작품 11편·촬영지 93곳(뒤에 155곳)일 때 앱은 목록을 한 번에 다 받았고, 그 「받아 둔 전부」 를 여러 화면이 돌려 썼다.
128편·486곳이 되자 받는 양의 상한이 전부보다 작아졌는데 화면은 여전히 그것을 전부로 다뤘다.

| # | 화면 | 가정 | 실제 |
| --- | --- | --- | --- |
| 1 | 마이페이지 「찜한 작품」 | 작품 앞 100편에서 찜한 id 를 찾으면 된다 | 찜한 셋(id 7·8·11)이 101번째 뒤라 목록이 비었다 |
| 2 | 검색 탭 작품 목록 | `limit=100` 이면 전부다 | 128편 — 28편이 안 보였고 탭에는 「인기 작품 100」 |
| 3 | 분류 칩 | 유형은 한국어 라벨이다 | 새 데이터는 코드(`cafe`) — 칩이 전부 0건 |
| 4 | 촬영지 줄·상세·코스 줄·성지 카드 | 유형을 그대로 찍어도 읽힌다 | `store_daily`·`public_office` 가 화면에 나왔다 |
| 5 | 「이 지역 검색」 과 장소 목록 | `limit=200` 이면 전부다 | 전국 축척에서 443곳 중 200곳 — 「200곳」 이라고만 적었다 |
| 6 | 코스 편집의 장소 검색 | 받아 둔 200곳 안에서 거르면 된다 | 그 밖의 곳(경복궁)은 이름을 쳐도 안 나왔다 |
| 7 | 자동완성 배지 · 「1 places」 · 지도 이름표 | 첫 별칭이 영어 제목이다 / 수는 늘 여럿이다 / 이름은 짧다 | 일본어 별칭 배지, 단수 어긋남, 80자 이름표 |

같은 꼴이 티켓 밖에도 있었다(§4).

## 2. 고친 방식

### 2-1. 이어 받기 — `Models/Paging.swift`

순수 값 하나가 「어디까지 받았나 · 전부 몇 건인가 · 더 있나」 를 든다. 한 쪽을 받으면 `advanced(received:total:)`,
새 쪽은 `merged(_:with:by:)` 로 뒤에 붙인다(같은 id 는 한 번만).

- 다음 요청의 `offset` 은 **서버가 돌려준 줄 수**다. 겹쳐서 버린 줄을 빼고 세면 다음 쪽이 한 칸 앞에서 시작한다.
- 빈 쪽을 받으면 `total` 이 뭐라 하든 멈춘다 — 총수와 실제가 어긋나도 끝없이 묻지 않는다.
- 화면의 수는 `total` 이다(`shownTotal`). 받은 줄 수가 아니다.

| 목록 | 한 쪽 | 언제 받나 |
| --- | --- | --- |
| 작품(검색 탭) | 50편 | 목록 끝의 「받는 중」 줄이 화면에 들어올 때(`SceneData.loadMoreContents`) |
| 촬영지(검색 탭) | 200곳(계약 상한) | 같은 방식(`loadMorePlaces`) — 검색어든 지도 범위든 처음 물은 조건 그대로 |
| 코스 편집의 장소 검색 | 40곳 | 같은 방식(`RoutePlaceSearch.loadMore`) |
| 찜한 작품 | 100편 | 한 번에 끝까지(사람이 누른 만큼이라 작다) |

이어 받기가 실패하면 목록 끝에 「더 불러오지 못했어요 · 다시 시도」 가 남는다. 저절로 다시 부르지 않는다.
새 검색이 걸리면 이어 받던 응답은 버리고(`contentRun`·`placeRun`), 목록과 칩 줄은 맨 처음 자리로 돌아간다
(`SceneData.listSerial`).

**알아 둘 것 — 실질 쪽 크기가 두 배다.** 한 쪽이 붙은 직후 「받는 중」 줄이 아직 살아 있어(목록이 줄을 조금 미리
만들어 둔다) 다음 쪽이 한 번 더 나간다. 작품은 50편이 아니라 100편씩 붙는 셈이다. 겹치거나 빠지지는 않는다 —
호출 수만 는다. 끝줄이 실제로 화면 가까이 왔는지를 재서 고칠 수 있는데, 붙는 순간의 배치 순서에 기대는 코드가 돼
이번에는 두었다.

### 2-2. 찜 목록 — 찜 API 가 주는 요약으로

`GET /favorites/contents` 는 `ContentList`(작품 요약)를 돌려준다. `LikeStore` 가 id 만 남기고 버리던 것을
`works` 로 들고 있고, 마이페이지는 그 가운데 지금 하트가 켜진 것(`likedWorks`)을 그린다.

하트를 새로 켜면 한 번 다시 읽는다(요약이 서버에만 있다). **그 다시 읽기는 요약만 채우고 하트(id 집합)는 덮지
않는다**(`LikeSync.idsAfterSummaryReload`) — 덮으면 응답이 떠난 뒤에 누른 것이 지워진다(A 를 켜고 곧바로 끄면 하트가
다시 켜지고 서버와 어긋난다, A·B 를 연달아 켜면 B 가 깜빡인다). 서버 값으로 하트를 맞추는 것은 전과 같이 요청이
실패했을 때와 화면을 열 때·계정이 바뀔 때뿐이다(MZ2AZ-366 의 규칙 그대로).

### 2-3. 유형 — `Models/PlaceType.swift`

코드 → 표시말(한국어·영어) → 칩 묶음을 한 표에 둔다(§3). 규칙:

1. 코드와 옛 한국어 라벨을 **둘 다** 받는다(옛 라벨 → 코드 표 `legacy`).
2. 표에 없는 값·빈 값은 **적지 않는다**(`label` 이 nil). 칩에서는 「기타」.
3. 옛 한국어 라벨도 코드로 접은 뒤 그 코드의 표시말로 적는다 — 「병원」 이 영어 화면에서 Hospital.

분류 칩은 「전체 · 음식점·카페 · 명소·자연 · 거리·다리 · 건물·시설 · 기타」 여섯이다. 걸러서 0건이면
「이 분류의 촬영지가 없어요」 를 띄운다(전에는 빈 화면).

**칩은 받아 둔 것 안에서 거른다** — 서버에 유형으로 거르는 인자가 없다. 그래서 **칩이 켜지면 목록 끝이 보이든
말든 끝까지 받는다**(`SearchTabList.fillForChip`). 끝줄이 보일 때만 받으면, 걸러진 줄이 화면을 넘는 칩(음식점·카페
34줄)은 나머지를 받지 않아 목록과 핀이 조용히 일부만 보였다.

- 상한은 열 쪽(2,000곳)이다. 넘으면 멈추고 그 뒤는 목록 끝줄이 받는다.
- 칩을 끄거나 바꾸거나 상세로 들어가면 멈춘다(돌아오면 이어 간다).
- 못 받으면 멈추고 목록 끝에 「다시 시도」 — 누르면 끝까지 다시 받는다.
- 받는 동안 탭은 「34+」, 안내는 「이 분류를 443곳 중 200곳에서 찾았어요 / 나머지를 확인하는 중이에요」.
  다 받으면 안내가 사라지고 탭의 수가 정확해진다. 두 숫자가 서로 다른 것을 세지 않는다.
- 첫 화면(인기 10곳)은 그 10곳이 찰 때까지만 받는다 — 인기순이라 앞에서 찬 10곳이 그 분류의 상위 10곳이다.

표시말은 번역 표(`Localizable.strings`)가 아니라 이 표 안에 한국어·영어를 같이 뒀다 — 코드마다 두 말이 다 있는지를
단위 시험이 본다(`PlaceTypeTests`). 칩 이름과 안내 문구는 번역 표에 있다.

### 2-4. 지도·목록의 총수

- 여기의 총수는 **물은 조건의 총수**다. 전국 축척에서 「443곳」 은 그 화면 범위 안의 수이고 전체(486)가 아니다 —
  화면 밖(제주 일부 등)은 세지 않는다.
- 켜진 「이 지역 검색」 단추: 다 받았으면 「이 지도에서 12곳 · 해제」, 일부면 「이 지도에서 443곳 중 200곳 · 해제」.
- 장소 탭 위 한 줄: 「443곳 중 200곳을 보고 있어요」. 지도 범위로 찾은 것이면 「지도를 확대하면 더 보여요」 와
  **「이 화면 다시 검색」** 단추(지금 보이는 범위로 다시 받는다 — 기존 `searchInViewport` 그대로),
  검색어로 찾은 것이면 「목록을 내리면 이어서 보여요」.
- 목록과 지도는 같은 배열이다(「3번 줄 = 3번 핀」). 목록을 내려 다음 쪽을 받으면 핀도 그만큼 는다.
- **핀 묶음(클러스터)은 하지 않았다**(§5).

### 2-5. 코스 편집의 장소 검색 — `RouteTab/RoutePlaceSearch.swift`

`GET /places?q=` 로 묻는다. 입력이 멎고 0.35초 뒤 한 번, 그 사이 또 치면 앞의 것을 취소한다. 빈 검색어는 기다리지
않고 인기순 첫 쪽. 재시도는 공통 계층(`RetryRules` 의 조회 규칙)이 한다 — 여기서 또 돌리지 않는다.
검색어를 바꿔 목록에서 사라진 곳도 고른 채로 남는다.

### 2-6. 낮은 것 셋 — `Models/Wording.swift`

- 배지: 걸린 표기가 있으면 그것, 아니면 **로마자로 적힌 첫 별칭**, 없으면 배지 없음(`AliasBadge`).
- 단수: `trCount("%lld곳", n)` — 하나일 때 번역 표의 `원문|하나` 줄(「1 place」). 고친 자리는 작품 줄·작품 상세·
  코스 요약·마이페이지 장바구니·장바구니 시트·홈 코스 카드. 그 밖의 「곳」 문구는 영어 번역이 수와 무관한 꼴이라 그대로다.
- 이름표: 28자를 넘으면 앞머리만(`PinCaption`), 폭 132pt 안에서 줄바꿈.

## 3. 유형 표

코드는 데이터 파이프라인의 표(`SceneTrip_flow/config/type_codes.json`, 2026-10-09 읽음)에 나오는 서른여덟 가지 전부다.
한국어 표시말은 그 표의 대표 라벨, 묶음은 앱이 전부터 쓰던 네 묶음을 따랐다(`theater`·`library` 는 새로 「건물·시설」).

| 묶음 | 코드 → 한국어 / 영어 |
| --- | --- |
| 음식점·카페 | `restaurant` 음식점 / Restaurant · `cafe` 카페 / Café · `bar` 바 / Bar · `market` 시장 / Market · `store_daily` 편의점·마트 / Store |
| 명소·자연 | `landmark` 명소 / Landmark · `nature` 자연 / Nature · `park` 공원 / Park · `beach` 해변 / Beach · `port` 항구 / Port · `viewpoint` 전망대 / Viewpoint · `temple` 사찰 / Temple · `church` 성당 / Church · `palace` 고궁 / Palace · `hanok` 한옥 / Hanok · `village` 마을 / Village · `theme_park` 테마파크 / Theme park · `experience` 체험시설 / Activity · `camping` 캠핑장 / Campsite |
| 거리·다리 | `street` 거리 / Street · `bridge` 다리 / Bridge · `station` 역·교통 / Station · `airport` 공항 / Airport |
| 건물·시설 | `building` 건물 / Building · `hotel` 호텔 / Hotel · `hospital` 병원 / Hospital · `school` 학교 / School · `museum` 박물관·미술관 / Museum · `bookstore` 서점 / Bookstore · `shop` 상점 / Shop · `mall` 쇼핑몰 / Shopping mall · `stadium` 경기장 / Stadium · `wedding_hall` 예식장 / Wedding hall · `funeral_hall` 장례식장 / Funeral hall · `set` 세트장 / Film set · `public_office` 관공서 / Public office · `theater` 극장·공연장 / Theater · `library` 도서관 / Library |
| 기타 | 표에 없는 값, 빈 값 |

로컬 DB 의 분포(2026-10-09): 코드 34가지 450곳, 한국어 값 15곳, 없음 21곳. 한국어 값 가운데 표가 아는 것은
`병원`·`항구`·`자연`·`근린공원` 넷이고, **표에 없어 숨기는 것**은 열한 가지 열한 곳이다 — `관광명소`·`보증보험`·`터널`·
`요트`·`곡물가공,제조`·`기업`·`노래방`·`방면정보`·`법률사무소`·`피아노`·`정류소,정류장`. 이 곳들과 유형 없는 21곳은
유형 글자 없이 그려지고 칩은 「기타」 다.

옛 라벨 표(`legacy`)는 파이프라인의 표를 그대로 옮겼다. 한 줄만 뺐다 — `세계문화유산 → restaurant`(잘못 적힌 것으로
보인다. §5).

## 4. 티켓 밖에서 같이 고친 것

| 자리 | 전 | 지금 |
| --- | --- | --- |
| 일정짜기 마법사의 작품 목록(`RouteStore.sortedWorks`) | 인기 상위 30편 안에서만 찜한 것을 앞으로 | 찜한 작품은 찜 목록에서 가져와 앞에 둔다 — 30편 밖의 찜도 나온다 |
| 코스 줄의 「어느 작품에 나온 곳」(`RouteEditorView.workTitles`) | 받아 둔 200곳에서 찾음 — 그 밖은 빈 줄 | 없으면 그 곳의 상세를 받아 **`scenes` 의 작품 제목**으로 채운다(`RouteStore.loadWorkTitles` · `PlaceWorks`). 한 곳에 한 번 — 「작품 없음」 도 답으로 기억하고, 못 받은 곳만 다시 묻는다 |
| 자동완성에서 고른 장소(`SearchTabView`) | 결과 첫 쪽에 없으면 그 장소가 안 열림 | 없으면 그 곳의 상세를 받아 연다(작품은 같은 `PlaceWorks`) |
| 홈 「지금 뜨는 작품」(`HomeTabModel`) | 서버 순서 앞 20편 안에서 정렬 | 끝까지 훑어(상한 500편) 촬영지 많은 순 20편 — 임시(§6) |
| 홈이 그려지는 순서(`HomeTabView.reload` · `HomeTabModel`) | 코스 목록 → 촬영지 200 → 작품 30 → 장바구니를 **차례로 다 기다린 뒤** 홈의 조회를 시작했고, 그 안에서도 작품 응답을 기다린 뒤 나머지를 대입 | 서로 기다리지 않는다 — 코스 카드는 코스 목록이 오는 대로(`RouteStore.refreshCourses` → `loadTrips`), 오늘의 성지·스탬프·선반은 각자 오는 대로(`loadRest`), 초안의 재료와 장바구니는 옆에서. 선반만 훑기가 끝난 뒤에 찬다 |
| 홈 코스 카드(`HomeTabModel.tripCard`) | 코스 목록이 오기 전에도 「여행을 시작해 볼까요? · 코스 만들기」 — 코스가 있는 사람에게 | 목록을 받아 보기 전에는 「내 여행을 불러오는 중…」, 못 받았으면 「내 여행을 불러오지 못했어요」, **받아 보고 정말 없을 때만** 「코스 만들기」 |
| 이어 받기를 그만뒀을 때(`PageFetch`) | 칩을 받는 도중에 끄면 취소가 실패로 적혀 「더 불러오지 못했어요 · 다시 시도」 가 남음 | 취소는 실패로 적지 않는다(작품·촬영지·코스 편집 검색 모두) |
| 직접 찍은 핀의 분류(`RouteBridge.pinCategory`) | 서버에서 읽은 값(`food`)을 몰라 다시 저장하면 전부 `building` | 계약의 값도 받는다 |
| 목록 줄의 번호 배지 | 세 자리면 「4…」 | 글자를 줄여 다 적는다 |

**상세의 작품은 `scenes` 가 정본이다.** 계약의 `PlaceDetail` 은 `PlaceSummary` 를 물려받아 `contents` 칸도 있지만
서버는 상세에서 그 칸을 빈 배열로 준다(2026-10-09 실측 `/places/49` → `contents: []`, `scenes: [Lovely Runner]`).
처음에는 `contents` 를 읽어서 이 표의 첫 두 줄이 고쳐지지 않았다(검증에서 발견).

홈의 선반은 훑다가 뒤쪽 쪽을 못 받으면 **받은 범위에서만** 고른다(`shelfIsPartial` — 화면에는 표시하지 않는다).
공통 계층이 이미 세 번 다시 보낸 뒤의 실패이고, 다음에 홈을 열면 처음부터 다시 훑는다.

마이페이지의 내 코스·담아 둔 곳과 홈의 내 기록은 각자의 API(`/courses`·`/cart`)가 필요한 것을 다 실어 줘서
이 꼴이 아니었다(확인만 했다).

### 4-1. 「앞쪽 N건」 이 아직 남은 곳

이번에 고치지 않았다. 데이터가 더 늘면 다시 틀리거나, 지금도 일부만 보인다.

| 자리 | 지금 | 틀리는 모습 |
| --- | --- | --- |
| 홈 「오늘의 성지」(`HomeTabModel.loadToday`) | 서버 순서 앞 60곳에서 날짜로 하나 | 나머지 426곳은 영영 안 나온다 |
| 일정짜기 마법사의 작품 목록(`RouteStore.works`) | 찜한 작품 + 인기 30편 | 그 밖의 98편은 찜해야 고를 수 있다(§5-6) |
| 빈 장바구니일 때의 예시(`RouteStore.cartSample`) | 받아 둔 200곳의 앞 6곳 | 늘 같은 여섯 곳 — 예시라서 틀린 것은 아니다 |
| 홈 선반의 훑기 상한(`HomeTabModel.scanLimit`) | 500편 | 작품이 500편을 넘으면 그 안에서만 고른다(§6 의 서버 정렬로 걷어낸다) |
| 코스 편집이 받아 두는 촬영지(`RouteStore.places`) | 인기 200곳 | 검색·작품 줄은 이제 서버에 묻지만 위 예시와 「받아 둔 목록에 있나」 판단은 이 200곳이다 |
| 분류 칩의 끝까지 받기 상한 | 열 쪽(2,000곳) | 넘으면 「12+」 로 남는다 |

## 5. 정해야 할 것

1. **핀 묶음(클러스터).** 전국 축척에서 핀 200개(목록을 끝까지 내리면 443개)가 겹쳐 읽기 어렵다. 묶음은 지도 SDK 의
   기능을 새로 쓰는 일이고 「번호 = 줄」 규칙과 부딪혀 따로 정해야 한다. 제안: 줌이 낮을 때는 시·도 단위 수만 보이고
   확대하면 번호 핀으로.
2. **「이 지역 검색」 을 켠 채 지도를 옮겼을 때.** 지금은 목록 위의 「이 화면 다시 검색」 을 눌러야 다시 받는다.
   지도가 멎으면 저절로 다시 받게 할지(호출이 는다), 단추가 「다시 검색」 으로 바뀌게 할지.
3. **표에 없는 한국어 값을 한국어 화면에서 그대로 보일지.** 지금은 언어와 무관하게 숨긴다(「보증보험」 같은 수집
   원본의 분류가 섞여 있어서). 데이터가 정리되면 볼 일이 없다.
4. **옛 라벨 표의 출처.** 파이프라인 표의 사본이 앱에 있다(iOS, 곧 Android). 파이프라인이 표를 바꾸면 앱은 모른다.
   그 표의 `세계문화유산 → restaurant` 는 파이프라인 쪽(태환)에 물어야 한다. `궁궐 → landmark`(「고궁」 은 `palace`)·
   `박물관 → landmark`(「박물관/미술관」 은 `museum`)도 같은 표에서 온 것이다 — 그대로 옮겼다.
5. **코스 편집 검색이 주소로는 안 걸린다.** 서버의 `q` 가 주소를 보지 않는다. 전에는 앱이 주소도 걸렀다.
6. **일정짜기 마법사의 작품 목록.** 찜한 것 + 인기 30편뿐이다. 그 밖의 작품은 찜해야 고를 수 있다 — 검색이나
   이어 받기를 붙일지.

## 6. 서버에 바라는 것

| 바라는 것 | 왜 | 그때 앱이 걷어낼 것 |
| --- | --- | --- |
| 작품 정렬 인자 — 촬영지 수(또는 실제 인기 점수) | 인기 점수가 전부 50 이라 순서가 「나중에 올린 순」 이다(티켓 「서버 쪽」) | 홈이 작품을 끝까지 훑는 것(`HomeTabModel.scanWorks`, 지금 두 번 호출) |
| `/places` 의 유형 묶음 인자(`group=food`)와 묶음별 수 | 칩이 받아 둔 것 안에서만 거른다 — 칩을 켜면 전부 받게 된다 | 칩의 이어 받기, 탭의 「12+」 |
| 유형의 표시말(`typeLabel`, 편의시설의 `categoryLabel` 처럼) 또는 닫힌 enum | 표가 앱마다 한 벌씩이고 파이프라인과 따로 논다 | `PlaceType` 의 표 |
| 여러 촬영지를 한 번에(`/places?ids=`) 또는 코스 아이템에 작품 | 코스 줄의 작품을 알려고 곳마다 상세를 부른다 | `RouteStore.loadWorkTitles` |
| `q` 가 주소도 보게 | §5-5 | — |
| 옛 이름 별칭(「수원 화홍마트」) | 티켓 「서버 쪽」 | — |

계약의 `PlaceSummary.type` 설명(「현재 37종의 자유 문자열」)은 낡았다 — 지금은 코드가 대부분이다.

## 7. 시험

`apps/scenetrip-ios/tests/` — `PagingTests`(끝까지 걷기·빈 쪽에서 멈춤·겹침·offset·취소는 실패가 아님), `HomeTripCardTests`(코스가 있는지 모르는
동안 「코스 만들기」 를 권하지 않음), `PlaceTypeTests`(코드와 옛 라벨의

못 받은 곳만 다시 묻기), `LikeSyncTests`(켜자마자 끄기 · 연달아 켜기에서 다시 읽기가 하트를 덮지 않음), `HomeShelfTests`(촬영지 많은 순), `RoutePlaceSearchTests`(검색어 다듬기·
기다림), `WordingTests`(이름표·배지·수), `ClientRulesTests`(칩 — 「기타」 로 바뀐 것).
