# 커뮤니티 신고·금칙어 거르기·차단 — App Store 심사 지침 1.2 (MZ2AZ-438)

리뷰·여행후기처럼 사용자가 글을 올리는 앱은 App Store 심사 지침 1.2 를 지켜야 한다 — **부적절한 글 거르기, 신고, 괴롭히는
사용자 차단, 연락처 공개**. 지금은 서버·앱 모두 하나도 없다(운영자가 내리는 칸 `removed_at` 만 있고 채우는 기능은 없다).
출시가 급해 **심사에 필요한 만큼만** 만든다.

## 1. 결정 (2026-10-15, 권호)

| 항목 | 결정 | 이유 |
| --- | --- | --- |
| 이번 범위 | **신고 · 금칙어 거르기 · 차단** | 심사관이 앱에서 직접 보는 것들이다 |
| 운영자 처리 도구(글 내리기·되돌리기·커뮤니티 정지) | **이번에 하지 않는다** | 심사는 앱 안의 기능을 보고 서버 운영 도구는 보지 않는다. 신고가 쌓이면 SQL 로 볼 수 있다(§3). 신고가 늘면 그때 만든다 — 운영자 비밀 키(ADR 0023 의 서비스 비밀값과 같은 방식) + `just` 명령이 안이다 |
| 자동 숨김(신고 N 건) | 이번에 하지 않는다 | 처리 도구와 함께 |

| 앱 | 신고·차단 버튼, 차단 목록, 금칙어 안내, 연락처 — 정승길(MZ2AZ-461) | |

## 2. 금칙어 거르기

- 리뷰 본문, 여행후기 제목·본문(문단 블록 포함), 닉네임을 **저장할 때** 금칙어 목록에 걸리면 400 으로 거절한다(새 오류 코드).
- 목록은 **설정 파일**(서버 리소스) — 한국어·영어. 공개된 비속어 목록을 시작점으로, 운영하며 늘린다. 코드를 고치지 않고 파일만 바꾼다.
- 비교 전에 정규화한다 — NFKC(전각·풀어 쓴 자모를 보통 글자로), 소문자, 글자·숫자·띄어쓰기만 남김. 띄어쓰기는 낱말 경계로 남기고,
  **한 글자씩 띄운 것만** 붙인다(「씨 발」·「s h i t」 은 잡고 「아가씨 바다」 는 안 잡는다).
- **잘못 걸림을 조심한다** — 낱말 안에 비속어 글자가 들어가는 경우(「시발점」, 「아저씨빨리」, 「shitake」)는 예외 목록
  (`moderation/allowed-words.txt`)으로 먼저 지운다. 「시발」 처럼 띄어 쓴 다른 말(「도착 시 발 아파요」)과 겹치는 것은 목록 줄 끝의
  `!` 로 「붙여 쓴 낱말 안에서만」 잡는다. 「7시발 KTX」 같은 시각은 뺀다.
- 일부러 잡지 않는 것 — 글자 사이에 숫자·다른 글자 끼우기, 키릴 문자 섞기, 「7시발놈」. 목록 파일 머리말에 적었다. 빠진 것은 신고로 잡는다.
- 이미 올라간 글은 건드리지 않는다(고칠 때 다시 검사된다).

## 3. 신고

- **API**: 리뷰·여행후기를 신고한다. 이유는 정해진 값(스팸 · 욕설·혐오 · 성적인 내용 · 개인정보 노출 · 부적절한 닉네임 · 기타)과 선택 설명.
- **누가**: 로그인하지 않은 사용자도 신고할 수 있다(설치 id 로 계정을 찾는다) — 글은 누구나 읽으므로.
- **표**(V35): 신고한 사람, 대상(리뷰·후기와 그 번호), 이유, 설명, 시각. **같은 사람이 같은 글을 두 번 신고하면 한 번으로** 센다. 자기 글은
  신고할 수 없다. 대상 글이 지워져도 신고 기록은 남는다(무엇이 신고됐는지 나중에 알 수 있게 작성자와 본문 일부를 함께 적는다).
- **알림**: 신고가 들어오면 서버가 정해진 모양의 로그를 남기고, SigNoz 알람 규칙이 **Slack 채널**로 보낸다. 신고가 쌓이기만 하고
  아무도 모르면 안 된다 — 채널이라 여럿이 함께 받는다. 메일이 아닌 이유: SigNoz 에 메일 발송(SMTP) 설정이 없다(2026-10-15 확인).
- **SigNoz 알람 규칙(사람, PRD)**: Slack 들어오는 웹훅을 SigNoz 알람 채널(종류 Slack)로 넣고, 로그 알람 — 서비스 `scenetrip-scene-api`(SigNoz 의 service.name),
  본문에 `[신고] 접수` 가 들어간 로그가 5 분 안에 1 건 이상이면 그 채널로. 코드가 아니라 SigNoz 설정이다(웹훅 주소는 저장소에 적지 않는다). 로그 모양은 `ModerationController` 가 정한다 — 바꾸면 알람도 고친다.
- **게이트웨이**: PRD 앞단 nginx 가 정해진 경로만 통과시킨다(`platform/helm/scenetrip/templates/config.yaml`) — `reports` 를 더했다.
  차단은 이미 허용된 `/me/` 아래(`/me/blocks`)라 더할 것이 없다.
- **보관**: 접수 후 **1 년**이 지나면 지운다(권호 2026-10-15 — 처리방침에 적는다). 매일 새벽 3 시 50 분 서버가 지운다
  (`ReportStore.purge`, 설정 `scenetrip.moderation.report-retention-days`).
- **보기**: 처리 도구가 없는 동안은 SQL 로 —
  `SELECT * FROM content_report ORDER BY created_at DESC;`

## 4. 차단

- **표**(V36): 차단한 사람, 차단당한 사람, 시각. 같은 쌍은 한 줄.
- **차단하기**: 「이 리뷰의 작성자」·「이 후기의 작성자」 를 차단한다 — 서버가 작성자를 찾는다. 자기 자신은 차단할 수 없다. 탈퇴한
  작성자(글쓴이 없음)는 차단할 수 없다.
- **풀기 · 내 차단 목록**: 목록에는 닉네임과 차단한 때. 풀기는 그 줄의 번호로.
- **걸러내기**: 로그인한 사람이 볼 때, 그 사람이 차단한 사용자의 글을 **목록에서 뺀다** — 장소·편의시설 리뷰 목록, 사진첩, 여행후기
  목록. 여행후기 상세도 열지 않는다(404). **장소 평균 별점은 그대로**(모두에게 같은 값). 차단당한 사람은 차단한 사람의 글을 그대로 본다.
- **차단은 로그인해야 한다**(401 `SIGN_IN_REQUIRED`) — 비회원까지 받으면 목록 창구들이 보는 사람을 알려고 설치 id 를 새로 받아야 한다. 비회원은 신고로.

## 5. 계약

- 버전: **1.19.0** — 1.18.0 은 MZ2AZ-451(PR #291) 몫이다. #291 이 먼저 머지되면 이어진다.
- 신고 창구, 차단 창구(차단하기·풀기·내 목록), 새 오류 코드(금칙어, 자기 글 신고·자기 차단 등). 목록 창구들의 설명에 「로그인했으면
  차단한 사용자의 글은 빠진다」 를 적는다.

  (`ModerationFlowIntegrationTest` — 신고·중복·자기 글·차단·목록 걸러내기·풀기·탈퇴).
- `just check` 통과, scene-api 단위 794/794. 통합은 이 변경과 무관하게 원래 실패하던 POI 5 건(MZ2AZ-432, 로컬 DB 에 POI 전체가 있어서)만
  실패. 계약·게이트웨이 경로·마이그레이션 테스트 통과.
- 로컬 kind 클러스터(V36)에 올려 두 사용자로 실제 요청 — 금칙어 400, 신고 204·중복·자기 글, 차단 뒤 리뷰·사진첩·후기 목록과 후기 상세에서
  빠짐, 풀면 다시 보임. 시험 데이터는 지웠다.
- 테스트가 찾아 고친 잘못 걸림: 「7시발 KTX」, 「도착 시 발 아파요」, 「병신년」, 「shitake」, 「sniggering」, 「아저씨빨리요」·「아가씨팔찌」.
