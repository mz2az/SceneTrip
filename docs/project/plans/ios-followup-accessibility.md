# iOS 이관 후속 검증 — MZ2AZ-387

## 문제와 범위

2026-10-10, iPhone 17 시뮬레이터의 `accessibility-extra-large`에서 길찾기 한도
안내를 재현했다. 떠 있는 해태 말풍선이 안내 문구와 지도 앱 넘기기 단추를 가린다.
안내가 커져도 글과 단추를 덮지 않고 가이드 입구가 남도록 iOS 배치를 고친다.

사진 업로드의 429·401·저장소 PUT 실패도 확인한다. 이미 있는 코스·리뷰를 저장하거나
지우지 않는다. 자동화로 가이드·길찾기 유료 API를 부르지 않고 시험 응답을 쓴다.
Android·서버·계약은 이 변경의 범위 밖이다.

## 검증과 완료 조건

1. 실제 겹침을 화면과 접근성 틀로 기록하고, 안내 중 가이드 배치의 회귀 시험을 작성한다.
2. 보통/큰 글자, 일정 시트 높이, 가이드 열기·닫기와 기존 정보 카드 배치를 확인한다.
3. 업로드 한도·로그인 오류는 명확한 문구, 저장 차단, 실패 사진 제거를 확인한다.
   저장소 PUT 실패는 서버 토큰을 싣지 않는 요청과 실패 상태를 함께 검사한다.
4. `just check`, 독립 검토, PR CI 로그 확인 뒤 main에 머지한다.
5. 시뮬레이터 글자를 원래 `large`로, 앱은 시험 응답 없는 일반 실행으로 되돌린다.
   기존 코스·리뷰·찜 데이터의 적재 전후 요약을 비교하고 HTML 보고서·인덱스를 갱신한다.

## 구현 선택

안내 중에는 제목 옆에 46pt 얼굴 단추를 배치하고 떠 있는 해태를 숨긴다. 가이드 서랍을
열거나 핀을 찍을 때는 두 입구 모두 숨긴다. 목적지가 없거나 안내가 끝나면 기존 떠 있는
해태를 쓰며, 저장된 드래그 위치는 바꾸지 않는다. `RouteGuideEntry`가 이 배치를 함께 결정한다.
장소 카드가 떠 있으면 안내 중에도 기존 카드 위 회피 입구로 전환한다. 카드가 배너를 덮어도
가이드 입구가 남도록, 떠 있는 카드 상태를 배너보다 먼저 판단한다.

배너의 틀을 재서 해태를 위로 옮기는 방식은 채택하지 않았다. 큰 일정 시트에서는 지도
공간이 좁고, 기존 화면 밖 이동 제한이 회피한 위치를 다시 잘라 제목과 겹칠 수 있다.
본문과 단추가 같은 레이아웃 안에서 자리를 나누게 하는 쪽이 시트 높이에 덜 의존한다.

실제 결과는 [후속 검증 기록](../../qa/ios-followup-verification.md)에 적는다.

영어 큰 글자에서는 지도 앱 넘기기 단추의 내용이 44pt 틀 밖으로 그려지는 문제도 재현했다.
`ViewThatFits` 전체가 선택된 자식의 자연 높이를 부모에 전달하게 세로 `fixedSize`를 적용한다.
글자 크기를 제한하거나 단추 높이를 고정하지 않고, 기존 가로/세로 선택과 44pt 최소 터치 높이는 유지한다.
