# iOS 챗봇 코스 항목 보존 (MZ2AZ-425·434)

scene-api 1.15.0의 `GuidePlanStop.poiId`·`customPinId`를 생성 모델로 소비한다.
두 티켓은 같은 iOS·Android 요구이며 이 변경은 iOS만 담당한다.

1. 서버에서 읽은 개인 핀 ID를 화면 모형에 보관하고 챗봇 요청에 싣는다.
2. 응답의 촬영지·편의시설·핀을 정확히 하나의 양수 ID로 분류한다. 없거나 충돌한
   번호는 이름으로 추정하지 않고 기존의 저장 불가 표시를 유지한다.
3. 편집 응답은 기존 코스와 종류·ID로 대조해 유일한 항목의 서버 항목 ID·방문 여부·
   분류·표시말을 보존한다. 같은 ID가 여러 번 나오면 임의로 짝짓지 않는다.
4. 개인 핀 저장은 기존 `CourseItemInput.customPin` 계약을 따른다. 핀 ID 자체는
   PUT 필드가 아니며 기존 항목 ID와 핀 본문으로 저장한다.
5. 혼합 코스 왕복·순서/일차 변경·삭제·잘못된 ID·요청 JSON 회귀와 `just check`로 검증한다.

유료 챗봇 호출·운영 DB 변경은 하지 않는다. Android 동기화와 실제 모델 대화 E2E는 별도다.

## 검증 결과 (2026-10-14)

- 기존 코드에서 POI·핀 응답 왕복 시험의 단언 6개가 실패하는 것을 먼저 확인했다.
- 수정 후 iOS 단위 시험 721개가 통과했다. 혼합 대상의 요청 직렬화와 응답,
  `plan.draft/revise/move`, 삭제·일차 이동, 기존 항목·방문·핀 분류 보존,
  충돌·음수·0·미지정·중복 ID 처리를 검증했다.
- `just gen` 통과. `just check`의 포맷·린트·122개 빌드·22개 테스트 대상 통과.
  새 작업트리에서 Android SDK 환경변수가 없어 첫 전체 빌드가 실패했고,
  기존 개발 환경의 SDK 경로를 지정한 뒤 전체 게이트를 통과했다.
- 다른 작업 에이전트의 읽기 전용 코드 리뷰에서 차단 결함을 발견하지 못했다.
- 실제 유료 모델 대화·서버 PUT·시뮬레이터 조작 E2E는 이 검증에 포함하지 않는다.
  아직 저장하지 않은 핀은 서버 번호가 없어 챗봇 왕복 시 복원하지 못하며,
  동일 대상 중복 행은 기존 항목 번호를 임의로 배정하지 않는다.
