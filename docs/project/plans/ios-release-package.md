# iOS 배포 패키지 준비 (MZ2AZ-440·416)

## 목표와 경계

Apple 로그인 구현(415)과 배포 서명(440)을 분리한다. 시뮬레이터용 `:bin`은 유지하고,
수동 `:ipa`와 `just ios-package`로 운영 HTTPS 주소의 실기기 패키지를 만든다.
업로드·인증서 발급·개발자 계정 로그인은 자동 실행하지 않는다.

## 구현 순서

1. 프로파일의 만료·팀·번들·Apple 로그인·키체인·배포 종류를 로컬에서 검사한다.
2. 명시한 프로파일만 임시 로컬 입력으로 사용하고 버전·빌드 번호를 필수로 받는다.
3. Bazel arm64 실기기 빌드에 프로파일·실기기 권한·운영 API를 적용한다.
4. 인증서 없는 CI는 잘못된 프로파일의 거부와 기존 시뮬레이터 회귀를 검증한다.
5. 실제 프로파일·서명 키가 준비되면 서명/설치 및 TestFlight 검증을 이어간다.

## 역할

- 정승길: 빌드 명령·운영 설정·버전·제출 자료·iPad 기능 검증.
- 김태환: 개발자 팀의 인증서·프로파일·App Store Connect 권한 제공, iPhone 검증.
- 정권호: 운영 Apple 인증 설정·사진 저장소·공개 API 상태.

개인 명의 가입의 App Store Connect 초대는 개발자 팀 인증서 권한과 다르다.
계정 암호를 공유하지 않고 담당자 측 서명 또는 적절한 권한으로 진행한다.
iPad는 iPhone 호환 모드에서 로그인·사진·게시 기능을 확인하며 iPhone 화면/GPS
검증을 대체하지 않는다. 현재 iPad 네이티브 레이아웃 지원 확대는 범위 밖이다.

## 완료 기준

자동 검사 통과와 실제 서명 성공을 별도로 기록한다. 인증서 없는 상태에서 만든
시뮬레이터 IPA를 스토어 업로드용으로 보고하지 않는다. 실기기 설치·로그인·사진 게시,
TestFlight 업로드가 끝나기 전 440/416 전체를 완료 처리하지 않는다.

2026-10-14 사용자 제공 멤버십 화면으로 개인 가입·팀 PZA39D74D2를 확인했다.
검증 기기는 승길님의 iPad Air 13인치 M2이며 iPadOS 버전은 설치 전에 확인한다.
프로파일 일반 보관 위치에 파일이 없고 현재 연결 목록은 시뮬레이터뿐이었다.
