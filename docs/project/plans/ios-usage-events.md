# iOS 이용 기록 전송 (MZ2AZ-408)

## 범위와 계약

`scene-api` 1.11.0의 생성 `EventsAPI`·`UsageEvent`를 사용한다. 작품·촬영지 상세와
편의시설 정보 카드를 실제로 열었을 때만 조회를 전송한다. 작품·촬영지 상세는
`ContentDetailView`·`PlaceDetailView`, 지도 카드는 `RoutePlaceCard`·`RouteStopCard`의
실제 열림에 연결한다. 자동완성 포스터·가이드 추천
사전 조회·코스 이름 보정·리뷰 목록용 상세 조회는 기록하지 않는다. 연결된 POI의 대표
대상이 촬영지이면 촬영지 조회로 기록하며 두 종류로 중복 기록하지 않는다.
홈 인기순 전환은 서버 계산과 후속 알림 이후의 별도 작업이다. Android·서버·계약은
이번 변경에 포함하지 않는다.

## 전송과 실패 경계

생성 `EventsAPI.recordEventWithRequestBuilder`가 URL·본문·헤더를 만든다. 생성 빌더의
공개 `buildHeaders()`와 요청 속성을 전용 `UsageEventRequestBuilder`에 그대로 전달한다.
전용 빌더는 일반 URLSession을 사용하고 `AuthRequestBuilder`·`RetryingSession`의 실행을
호출하지 않는다. 통계 전송 직전 설치 ID·앱 언어·현재 액세스 토큰을 캡처한다.
401은 토큰 갱신·로그아웃·로그인 창을 만들지 않고, 429·5xx·연결 실패도 재전송하지 않는다.
타임아웃은 10초이며 캐시·쿠키·연결 기다림은 사용하지 않는다. 응답 성공 여부를 화면에
노출하지 않고, 통계의 완료를 화면 동작이 기다리지 않는다. 요청을 저장하거나 다음 실행에
재전송하는 큐를 만들지 않는다. 하루 중복 제거는 서버가 담당한다.

## 검색의 의미와 순서

검색 확정 시 Firebase에는 길이·갈래만 즉시 한 번 기록한다. 데이터 저장소의 일반 검색과
재시도에서 Firebase 기록을 제거한다. 검색 원문은 Firebase·메타로 보내지 않는다.

`SearchTabView.commit`이 확정한 검색에만 이용 기록 intent를 붙인다. 해당 검색의 첫 성공
응답으로 작품·장소 목록을 갱신한 뒤, 확정 때 선택한 탭의 표시 수를 캡처하여 전송한다.
작품은 서버 총수, 장소는 칩을 초기화한 검색이므로 서버 총수다. 페이지의 받은 행 수나
화면 픽셀 안에 보이는 행 수가 아니다. 새 검색 전의 전국 목록·이전 검색 총수와 새 검색어를
짝짓지 않는다. 결과 0도 성공 응답에서만 기록한다. 실패를 0으로 기록하지 않는다.

재시도·첫 목록·지도 범위·칩·이어 받기에는 intent가 없다. 취소·실패한 검색의 intent는
버린다. 요청 세대를 확인해 빠른 다음 검색이나 지도 검색 이후 도착한 옛 응답은 목록과
이용 기록 모두 갱신하지 않는다. 검색어는 공백을 정리하고 계약의 1~100자 범위만 전송한다.
통계 수집이 검색 응답을 추가로 요청하거나 그 성공을 기다리게 하지 않는다.

## 시험과 확인

실제 생성 요청을 가짜 URLSession에서 실행해 URL·POST 본문·설치 ID·언어·선택 토큰을
검사한다. 204·503·401·429·연결 실패·타임아웃 각각 전송 한 번이며 토큰과 로그인 상태가
그대로인지 확인한다. Firebase의 `view_poi`는 `poi_id`만 포함하고 원문·좌표를 보내지 않는다.

실제 SceneData 검색에 가짜 응답을 주어 새 검색의 총수·0건·빠른 다음 검색·실패 후 재시도·
지도 검색으로 바뀐 뒤 옛 응답을 검증한다. 일반 조회와 확정한 검색을 구분해 기록 횟수를
확인한다. 먼저 실패하는 시험을 확인하고 구현 후 `just test`·`just check`를 통과한다.
실제 로컬 DB 확인과 화면 확인은 부모 세션이 수행하고 결과를 따로 기록한다.

## 로컬 자동 검증 결과

기존 `SceneData.search`와 `retry()`에서 Firebase 검색 두 번이 발생하는 회귀 시험의 실패를
먼저 확인했다. 수정 후 신규 이용 기록·검색 시험 14개와 기존 시험을 포함해 iOS 638개가
통과했고 전체 `just check`의 19개 대상이 통과했다. 조회의 생성 본문·설치/언어/토큰 사본,
비회원의 토큰 제외, 응답 대기 없는 반환, 401·429·503·연결 끊김·타임아웃 각각 한 번 전송과
로그인 상태 보존을 확인했다. 이 결과는 실제 단말·Firebase 콘솔 수신·로컬 DB의 행 생성
확인을 대신하지 않으며, 해당 확인 결과는 별도 QA 기록으로 남긴다.
