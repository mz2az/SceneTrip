# 담은 촬영지로 AI 일정 — 마법사가 담은 촬영지를 받는다 (2026-11-27)

내 지도의 「이 N곳으로 계획 짜기」(`MyMapCover`)를 「직접 짜기」 대신 **AI 일정 짜기**로 바꾼다. AI 가 작품을 고르는 것이 아니라
**사용자가 담은 곳을 날짜별로 나누고 순서를 정한다.** 「작품으로」·「도시로」(MZ2AZ-548, [city-ai-course.md](city-ai-course.md))가 쓰는
창구(`POST /guide/plan`)와 에이전트(`agents/trip-guide`)에 세 번째 입력을 더한다.

티켓: MZ2AZ-601.

## 지금

| | 작품으로 | 도시로 | 담은 곳으로 (지금) |
| --- | --- | --- | --- |
| 입력 | `titles` | `city` | — 창구가 장소 목록을 받지 않는다 |
| 누가 짜나 | 모델(`llm_planner.py`) | 모델(`city_planner.py`), 못 하면 가까운 곳 잇기 | 사람이 직접(직접 짜기 마법사, 담은 곳이 전부 골라진 채로) |

- 내 지도 버튼 → `useTabRouter().openPlanFromSaved()` → 경로여정 → `RouteWizard kind='manual'`, `pickAllSaved`.
- AI 일정의 한 줄(`GuidePlanStop`)은 이미 촬영지(`placeId`)·편의시설(`poiId`) 둘 다 담을 수 있다(1.15.0). **출력 쪽은 바꿀 것이 없다.**
- 챗봇의 「담은 걸로 동선 짜 줘」 는 앱이 담은 목록을 보내지 않아 동작한 적이 없어 도구째 뺐다(`agents/trip-guide/docs/design/contract-1.2.0.md` §1).

## 사용자가 정한 것 (2026-11-27)

1. **담은 촬영지가 하루 몫 × 일수보다 많아도 전부 넣는다.** 마법사가 처음 일수를 「담은 수 ÷ 하루 곳 수」 올림(최대 7일)으로 맞춰 두고,
   사용자가 줄이면 하루에 더 많이 넣는다.
2. **이번엔 촬영지만.** 담은 편의시설(식당·카페·숙소)은 보내지 않는다 — 나중에 따로(`poiIds`). 내 지도 버튼의 숫자(촬영지+편의시설)와
   AI 일정의 곳 수가 다를 수 있으므로 마법사 확인 화면에 「담은 촬영지 N곳」 을 적는다.
3. 마법사 질문은 기간·떠나는 날·속도·확인 네 단계. 작품 고르기는 뺀다(작품은 담은 곳이 정한다).
4. 에이전트 파일 두 곳(`internal_server.py`·`sceneapi.py`)에 짧게 더하는 것을 진행한다.
5. **고른 일수는 최대한 채우되 억지로 나누지 않는다.** 나눔이 고른 일수보다 적으면 하루 곳 수(`stops_per_day`)를 넘는 날만
   지리적으로 둘로 나눠 채운다. 나눈 두 날은 각각 2곳 이상이어야 하고, 하루 곳 수 안의 날은 나누지 않는다. 고른 일수를 넘지 않는다.
   **1곳짜리 날은 만들지 않는다** — 모델이 1곳만 넣은 날은 가장 가까운 날에 합친 뒤 위 채우기를 한다(로컬 실측: 서울 12곳·3일에
   모델이 7·4·1 로 나눴다, 2026-11-27).

## 1. 계약 (`contracts/openapi/scene-api-v1.yaml`, 1.32.0 → 1.33.0)

`GuidePlanRequest` 에 더한다.

- `placeIds`: integer 배열, maxItems 40 — 담은 촬영지 id. 빈 목록은 보내지 않은 것으로 본다(`titles` 와 같은 규칙).
- **`titles`·`city`·`placeIds` 중 정확히 하나.** 어기면 400 `INVALID_PARAMETER`.
- 400 설명에 더한다: 좌표 있는 곳이 하나도 없음(없는 id·숨긴 촬영지는 빼고 센다).
- 응답은 그대로.

## 2. 서버 (`services/scene-api`)

- `GuidePlanTarget.check` 를 세 갈래로 넓힌다. 에이전트의 `POST /plan` 에 `placeIds` 를 그대로 넘긴다.
- 사용자 확인은 하지 않는다 — id 는 공개 데이터의 번호이고, 담은 목록 자체를 서버가 읽지 않는다(앱이 보낸 것으로 짠다).

## 3. 에이전트 (`agents/trip-guide`)

- 새 파일 `saved_planner.py`(「도시로」 의 `city_planner.py` 와 같은 자리). `plan_target` 이 세 번째 갈래를 돌려준다.
- **받기:** `GET /places/{id}` — 서비스를 거친다(DB 직접 금지). 못 받은 id(없음·숨김)는 빼고 `dropped` 에 이유를 적는다.
- **나누기:** 모델에게 곳 목록(id·이름·구역·좌표·작품)과 일수를 주고 「전부 쓰되 하루는 가까운 동네끼리」 를 묻는다. 새 프롬프트 `prompts/plan_saved.txt`.
  모델이 빠뜨린 곳은 코드가 가장 가까운 날에 넣는다 — **담은 곳은 하나도 버리지 않는다**(좌표 없는 곳만 `dropped`).
- **순서:** 날마다 가까운 순(`city_planner.reorder_day` 재사용).
- **모델이 못 주면:** 좌표로 일수만큼 묶고(`zones`) 가까운 순으로 잇는다 — 「도시로」 의 대체 경로와 같다.
- **빈 날 채우기:** 위 「정한 것」 5 — 과밀한 날(가장 큰 날부터)을 둘로 나누기를 고른 일수가 될 때까지 또는 나눌 날이 없을 때까지.
- `llm_planner.py`(커밋 작성자 대부분이 SETGEE)는 손대지 않는다. 진입점 분기(`internal_server.py`)와 조회 클라이언트(`sceneapi.py`)에
  id 로 받는 함수 하나(`place_by_id`)만 더한다.

## 4. 웹 (`apps/scenetrip-web`)

- 내 지도·홈 카드·담은 뒤 시트의 「담은 곳으로 계획 짜기」 → AI 마법사(`aiPlan`)를 **담은 곳 모드**로 연다(`openPlanFromSaved`, `pendingStore`).
- 마법사: 기간(처음 값 = 담은 촬영지 수 ÷ 하루 곳 수 올림, 최대 7일)·떠나는 날·속도·확인. 확인 화면에 「담은 촬영지 N곳」.
- 담은 촬영지가 0곳(편의시설만 담음)이면 지금처럼 직접 짜기 마법사를 연다.
- `guideDraft` 가 `placeIds` 를 보낸다(`useCart` 의 담은 촬영지, 목록에서 빠진 것 제외). 받은 초안은 지금처럼 편집 화면에 그린다.
- 버튼 글자: 「이 N곳으로 AI 일정 짜기」/「Plan a trip with these N spots」 그대로 두고 AI 띠(`AIBanner`)를 마법사에 띄운다.
- iOS·안드로이드는 이번 범위 밖(웹 시연 먼저). 계약은 함께 바뀌므로 앱의 생성 클라이언트는 다시 만든다(`just gen`).

## 5. 시험

- 계약: `just gen` 뒤 차이 커밋. scene-api 단위(`@WebMvcTest`): 세 갈래 검증 — 하나만 200, 둘 이상·없음 400, 빈 목록은 없는 것.
- 에이전트 단위(모델은 가짜): 담은 곳이 전부 들어간다 · 모델이 빠뜨리거나 지어낸 id 를 바로잡는다 · 좌표 없는 곳은 `dropped` · 모델 실패 시 대체 경로.
- 웹 vitest: 내 지도 버튼이 AI 마법사(담은 곳 모드)를 연다 · 작품 단계가 없다 · 요청 몸체에 `placeIds` · 촬영지 0곳이면 직접 짜기.
