# 빈 코스 첫 안내와 지도 주변 촬영지 (MZ2AZ-444)

## 범위

- iOS 직접 짜기의 새 빈 코스에서 장바구니 안내를 기기당 한 번 표시한다.
  장바구니 버튼이 나타나면 안내하고, 2.5초 강조·닫기·VoiceOver·동작 줄이기를 지원한다.
  장바구니 조회 중에는 테두리만 즉시 강조한다. 조회 성공 후 실제 내용에 맞는 문구를
  표시·낭독하고 seen을 기록한다. 실패하면 일반 안내를 쓰며, 문구 표시부터 2.5초 유지한다.
- 가이드의 지도 주변 촬영지 조회는 생성 PlacesAPI만 사용한다. 현재 지도 중심을
  클릭 시점에 고정하고, GPS에서 자동 맞춘 지도는 MZ2AZ-472의 출처와 동의를 유지한다.
  사용자가 이동한 지도는 위치 동의 없이 조회한다. 「내 위치로」는 별도 위치 동의 뒤 조회한다.
- AI 요청·오류와 독립된 목록에서 원하는 장소를 현재 일차에 추가한다.
  가이드 대화가 있거나 실패해도 장바구니와 주변 조회 입구를 유지한다.
- AI 추천 장소는 직접 담지만 일정 변경 요청은 초안에 바로 반영될 수 있다.
  AI 버튼 아래에 이 차이와 별도 저장을 설명한다. 기존 AI 동의를 유지한다.

## 검증

- 가짜 저장소로 최초 조건·재생성 후 한 번만 표시·장바구니 문구를 시험한다.
- 지연된 장바구니의 비어 있지 않은 응답·빈 응답·실패를 가짜 조회로 제어한다.
  응답 전에는 강조만 켜지고 문구·낭독·seen·노출 타이머가 시작되지 않는지 검증한다.
  힌트 task는 `RouteEditorView`에 유지하고 조회 상태와 표시 수명을 분리한다.
- 가짜 조회로 현재 지도 중심·좌표 출처·기기 위치 동의 허용/취소/철회,
  늦은 응답·검색 실패·AI 실패 후 비AI 조회와 장바구니 사용을 시험한다.
- 새 소스·시험은 BUILD에 정렬해 등록하고 KO/EN 문자열과 README를 갱신한다.
- 사용자 제한에 따라 네트워크, 실제 guide/navigation API, Bazel·just, 빌드·시험
  실행과 커밋은 하지 않는다. 변경 Swift만 SwiftFormat 적용 후 정적 검사한다.
  단위 시험 실행과 한·영/큰 글자/VoiceOver/동작 줄이기 화면 확인은 후속 검증이다.

## 정적 검증 결과

- 단위 시험 13개를 추가했다. 실행하지 않았으므로 컴파일·시험 통과를 의미하지 않는다.
- 변경 Swift 11개만 SwiftFormat을 적용했다. SwiftLint 오류 0개, 기존 파일 경고 10개다.
- KO/EN 문자열 plutil 검사, BUILD 명시 등록·정렬 검사, diff 공백 검사를 통과했다.
  buildifier 실행과 Bazel·just·네트워크·실제 API 호출·커밋은 하지 않았다.

## 코스 생성 실패 안내 회귀 수정 계획

- 수동 마법사의 마지막 버튼은 빈 초안을 열며 서버 저장은 편집 완료 때 수행한다.
  편집 화면이 공용 `RouteStore.failure`를 저장 실패로 표시하므로 이전 목록·재료 조회
  오류만 있어도 저장 요청 없이 「저장하지 못했습니다」가 뜰 수 있다.
- 저장·여행 상태 변경 오류를 조회 오류와 분리하고 편집 화면은 해당 오류만 표시한다.
  저장 성공 뒤 목록 재조회가 실패해도 저장 실패로 표시하지 않는다.
- 생성 CoursesAPI → RetryingSession → 실제 위치 게이트 → 가짜 전송으로 미동의 수동
  저장을 검증한다. AI 초안의 선택 좌표 제거·허용 시 좌표 유지, 장바구니·리뷰·후기·
  사용자 선택 bbox 전송도 함께 검증한다. AI 기능 동의는 별도로 계속 요구한다.
- 기존 미커밋 `RouteNearbySearchTests.swift`는 보존한다. Bazel·just·네트워크·커밋과
  빌드·단위 시험 실행 없이 변경 Swift만 SwiftFormat 적용하고 정적 검사한다.

## 코스 생성 경로 조사 결과

- `RouteWizardView.advance`의 수동 분기는 `emptyCourse`로 초안만 만든다. `RouteStore.create`는
  현재 소스에 없으며 실제 저장은 `RouteStore.save`의 생성 CoursesAPI 호출이다.
- `CourseCreate` 계약에는 좌표가 없다. `RetryingSession`의 AI 동의는 두 guide POST만,
  위치 게이트의 차단은 navigation·GPS 출처 places/pois·기기 위치 guide/chat에만 적용한다.
  따라서 현재 코드에서 위치 미동의가 `POST /courses`를 차단하는 경로는 발견하지 못했다.
- 편집 화면은 기존에 공용 `failure`를 저장 경고에 연결했다. `refreshCourses`·`refreshMaterials`에서
  기록한 조회 오류로도 진입 즉시 경고가 뜨며, 저장 성공 뒤 재조회 오류도 저장 실패처럼 보였다.
  `saveFailure`를 분리해 이 오류 표시 경로를 수정했다. 여행 상태 저장 실패도 재조회 후 유지한다.
- 장바구니 추가·촬영지/편의시설 리뷰 저장·후기 게시에는 기기 좌표가 없으며 두 동의로 차단하지 않는다.
  사용자 선택 출처의 places/pois bbox와 목적지 guide/chat도 위치 동의 없이 통과한다.
  guide/chat·guide/plan의 AI 동의와 GPS 출처 조회·navigation의 위치 동의는 계속 필요하다.
- `RouteCreationTests` 8개를 추가하고 BUILD에 등록했다. 생성 클라이언트와 실제 RetryingSession·
  위치 게이트를 거쳐 가짜 전송의 요청/본문을 확인하도록 작성했다. 수동·AI 코스 저장,
  AI 초안의 미동의/동의 좌표 처리, 조회와 저장 오류 분리, 다른 쓰기와 사용자 선택 bbox를 다룬다.
- 시뮬레이터 재현·테스트 실행은 하지 않았다. 제보 당시 공용 `failure`를 채운 원래 조회 요청과
  HTTP 상태는 현재 자료만으로 확정할 수 없다. 변경 Swift 포맷과 정적 검사를 수행한다.

## 수동 초안의 장바구니 안내 누락 수정

> 아래는 이전 수정 기록이다. 조회 중 빈 상태 문구를 먼저 표시하던 동작은 다음 보완으로 대체했다.

- 기존 `RouteEditorView`는 `await cart.refresh()` 뒤에만 `cartHintReady`를 켰다.
  `RouteCartHint`의 task가 이 값을 요구해, 응답·재시도가 끝나기 전에는 안내도 seen 기록도 없었다.
  task는 표시 전 내용이 없는 안내 VStack에 붙어 있어 목록 행의 뷰 생명주기에도 의존했다.
- 트리거를 실제 장바구니 버튼의 task로 옮기고 조회 완료 조건을 제거한다.
  저장 ID가 없는 새 수동 빈 초안이면 바로 표시하고, 장바구니 응답은 문구만 갱신한다.
  표시 시 한 번 기록·닫기·2.5초 강조·VoiceOver 알림·동작 줄이기 고정 테두리를 유지한다.
- 단위 시험은 마법사와 같은 `emptyCourse(span: .sameDay, startDate: nil)`로 표시 조건을 검증한다.
  저장 ID·날짜·장소가 없는 초안, 조회 완료 없이 표시, seen 기록과 재생성 후 중복 방지를 다룬다.
  기존 코스·AI 초안·다른 일차에 장소가 있는 코스의 제외 조건도 실제 모델로 검증한다.
- 사용자 제한에 따라 Bazel·just·네트워크·커밋·빌드·단위 시험·시뮬레이터 실행은 하지 않는다.
  이번 변경 Swift 4개만 SwiftFormat과 정적 린트를 적용하며 실행 검증은 별도로 남는다.
- SwiftFormat 적용 완료, SwiftLint 오류 0개·기존 경고 6개, diff 공백 검사 통과다.

### 수동 마법사 경로 재점검

- 현재 소스의 빈 탭 「직접 짜기」는 `wizard = .manual`로 시트를 열고,
  `RouteWizardView.advance()`가 `emptyCourse(span: .sameDay, startDate: nil)`를 만든다.
  같은 시트가 `RouteEditorView(course: draft, isNew: true)`로 바뀐다. 초안은
  `serverId == nil`, `madeByAI == false`, 장소 0개다. 별도의 수동 편집기는 없다.
- `openPlannerIfAsked()`는 닫힘 뒤 `pendingPlanner`가 있을 때 AI 마법사를 다시 여는 경로다.
  저장된 코스를 여는 덮개만 `isNew: false`를 전달한다.
- 위 값은 기존 `claim` guard도 통과한다. seen 키가 없다는 사실만으로 guard 실패나
  장바구니 버튼 task 실행 여부를 확정할 수 없다. 현재 소스와 시뮬레이터 관찰 사이의
  불일치는 실행 당시 값·실행 바이너리 확인이 필요하며, 이번 작업에서는 재현하지 않았다.
- 안내 조건은 표시 방식인 `isNew` 대신 `serverId == nil`로 판정한다. task는
  `List`의 버튼에서 편집기 자체로 옮겨 목록 행의 생명주기에 의존하지 않게 한다.
  AI·기존 코스·장소가 있는 초안 제외와 최초 기록·중복 방지는 유지한다.
- 회귀 시험은 실제 마법사와 같은 초안·편집기를 구성해 claim 성공과 seen 기록을 검증한다.
  미저장 초안의 표시 플래그가 달라도 안내하고, 저장된 빈 코스는 상세 조회 여부와 무관하게 제외한다.
- 사용자 제한에 따라 Bazel·just·네트워크·커밋 없이 수정한다. 빌드·단위 시험·
  시뮬레이터 실행 결과로 간주하지 않는다.
- 변경 Swift 4개는 SwiftFormat 검사 통과, SwiftLint 오류 0개·기존 경고 6개다.
  `git diff --check`도 통과했다.

### 장바구니 지연 조회 시 첫 문구 보완 (P2)

- `CartStore`에 미조회·조회 중·성공·실패 상태를 추가해 초기 빈 배열과 조회 결과를 구분한다.
  힌트는 즉시 테두리를 강조하고 성공·실패까지 문구 표시를 기다린다.
- 성공한 조회의 장소가 0개일 때만 빈 상태 문구를 사용한다. 조회 실패에는
  「담아둔 장소로 코스를 시작해 보세요」를 표시한다. 표시 시에만 seen·VoiceOver를 처리하고
  그때부터 2.5초 동안 문구를 유지한다. 편집기의 힌트 task 위치는 유지한다.
- 지연된 비어 있지 않은 응답·빈 응답·실패 회귀 시험 3개를 추가했다. 가짜 조회와 가짜 대기로
  응답 전 강조·문구 미표시·seen 미기록, 응답 후 올바른 문구·한 번 낭독·2.5초 노출을 검증한다.
- 이번 변경 Swift 5개만 SwiftFormat을 적용했다. SwiftLint 오류 0개·기존 경고 6개와
  diff 공백 검사를 확인했다. 사용자 제한에 따라 빌드·단위 시험·Bazel·just·네트워크·커밋은
  수행하지 않았다. 테스트 통과를 의미하지 않는다.

## 기존 코스 상세 조회 실패의 데이터 손실 방지

- 목록 선택과 홈에서 넘어온 코스 모두 상세 조회 성공 후에만 편집기를 연다.
  실패하면 목록에 「코스를 불러오지 못했어요」·「다시 시도」를 한국어·영어로 표시한다.
  재시도는 실패한 코스를 다시 조회하며, 목록·재료 재조회로 이 오류를 지우지 않는다.
- 코스 사본에 상세 조회 여부를 기록한다. 서버 ID가 있지만 상세를 받지 않은 사본은
  편집기의 저장 버튼과 공용 저장 경로에서 모두 차단해 빈 일정 PUT을 방지한다.
- 가짜 전송 회귀 시험으로 조회 실패 후 편집 미진입·저장 거부, 재시도 성공 후 진입,
  상세를 받은 뒤의 정상 저장과 의도적으로 모든 장소를 뺀 저장을 확인한다.
- 기존 미커밋 변경을 보존한다. 사용자 제한에 따라 Bazel·just·네트워크·커밋과
  빌드·단위 시험 실행 없이 이번 변경 Swift만 SwiftFormat 적용하고 정적 검사한다.
- 회귀 시험 4개를 추가했다. AI 일정 변경 뒤에도 상세 조회 기록을 유지하며,
  같은 서버 ID의 상세를 받아도 예전 목록 사본의 저장은 계속 차단한다.
- 이번 변경 Swift 9개에 SwiftFormat을 적용했다. SwiftLint 오류 0개·경고 7개,
  KO/EN 문자열 plutil 검사·diff 공백 검사 통과다. 빌드·시험 통과를 의미하지 않는다.
