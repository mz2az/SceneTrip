# iOS 관광공사 편의시설 안내 (MZ2AZ-470)

## 범위와 계약

`scene-api-v1.yaml` 1.21.0과 [poi-source.md §6-1](poi-source.md#6-1-결정과-실측-2026-10-15-권호)을
기준으로 기존 `RoutePlaceCard`에 안내를 붙인다. 생성 Swift 클라이언트의 `PoiDetail.info`,
`PoiInfoText`, `Photo.thumbnailUrl`·`license`를 소비한다. 계약·서버·생성 코드는 수정하지 않는다.

## 구현 순서

1. 단위 시험으로 info 및 개별 필드의 누락·null, 언어 태그, 줄바꿈, 홈페이지 경계,
   KO/EN 출처, 썸네일 폴백·원본 선택, Type3 비율 보존을 고정한다.
2. 안내를 선택 행으로 변환하고 기존 카드에 연결한다. 긴 안내는 카드 안에서 스크롤한다.
   서버 문장을 그대로 표시하며 영업 여부를 계산하지 않는다. 홈페이지는 공통 HTTP(S)
   검사를 통과한 주소만 브라우저로 연다.
3. 기존 앱 문자열 표로 행 제목·언어 태그·관광공사 출처를 번역한다. 시스템 번역 사용 패턴이
   없어 언어가 다른 필드에만 태그를 둔다. 언어별 내용 폴백은 서버가 맡는다.
4. 사진 모델에 썸네일·라이선스를 보존한다. 작은 줄·격자는 썸네일, 상세·확대는 원본을
   사용하고 썸네일이 없으면 원본을 사용한다. Type3는 aspect-fit, 필터·문구 덮기·자르기 없이
   표시한다. 출처·페이지 조작은 사진 바깥에 둔다. 기존 credit도 보존한다.
5. BUILD의 새 파일 목록을 정렬하고 README를 갱신한다. 변경 Swift 파일만 swiftformat한다.

## 검증과 인계

사용자 지시로 이 작업에서는 빌드·단위 시험·`just check`를 실행하지 않는다. 네트워크와
커밋도 사용하지 않는다. 로컬 생성물의 프로퍼티·생성자 및 diff를 확인한다.
안내·사진 단위 시험 13개를 추가했고, 기존 카드 필드 검사에 `info`를 반영했다.
변경 Swift 12개에만 swiftformat을 적용했다. 문자열 파일 문법과 diff 공백 검사는 통과했다.
변경 파일 SwiftLint는 오류 없이 종료했다. 기존 세 파일의 경고 13개는 기준 버전과 동일하며,
엄격 모드는 이 기존 경고 때문에 통과하지 않는다.
인계 후 `just check`와 iOS 시뮬레이터에서 KO/EN, 작은 화면·큰 글자, 긴 개요 스크롤,
홈페이지 브라우저 열기, 세로 Type3 사진의 카드·격자·확대 표시를 확인한다.

인계 후 단위 시험에서 영어 행 제목과 홈페이지 문구가 한국어로 남는 실패를 확인했다.
문자열 키와 호출 시점의 `tr()` 사용은 맞았으나, 공통 `AppLanguage.bundle(for:)`가
`Bundle.main`만 조회해 호스트 없는 XCTest의 테스트 번들에 실린 번역 표를 찾지 못했다.
앱 코드가 속한 `Bundle(for: AppLanguage.self)`에서 요청한 언어의 표를 찾도록 수정했다.
기존 POI 언어 전환 시험과 `tr("홈페이지")` 검증은 그대로 두었으며, 수정 후 단위 시험과
`just check` 재실행은 사용자가 진행한다.
