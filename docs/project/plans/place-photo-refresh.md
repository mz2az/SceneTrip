# 촬영지 사진 편집본 적용

- **상태**: 적용(2026-10-22) — 로컬·DEV. PRD 는 앱 심사가 끝난 뒤 다음 PRD 배포 묶음에 함께(데이터 파일에 들어 있어 PRD 적재 때 반영된다)
- **권리**: 멘토 확인 — 사람이 없는 정물·풍경 사진은 괜찮다(2026-10-22). 그래서 모든 사진에서 사람을 지웠다

## 범위와 기준

- 대상: 촬영지 사진(`place_image`, 데이터 파일의 `place_image_url`). 작품 장면 스틸(`place_content_image`)과 사용자 후기 사진은 대상이 아니다.
- 편집: 사람을 지우고 가려졌던 곳만 채운다. 실제 지형·건물·간판은 그대로, 구도는 소폭 크롭만. 장마다 원본을 보고 프롬프트를 따로 썼다(내장 이미지 생성).
- 검수: 723 장 중 1 장은 장소 사진이 아닌 모바일 화면 캡처라 **뺐고**, 2 장은 사람이 남아 다시 만들었다(더화이트베일 — 다시 만든 판에서 사람이 지워진 것 확인).

## 적용 방식 — 데이터 파일의 주소를 바꾼다

처음 계획은 DB 의 주소만 SQL 로 바꾸는 것이었다. 그런데 데이터 적재(`candidates.sql`)는 촬영지 사진을 **지우고 데이터 파일에서 다시 넣는다**
(`DELETE FROM place_image … INSERT …`) — SQL 로 바꾼 주소는 다음 적재 때 원본으로 돌아간다. 그래서 데이터 파일의 주소를 바꿨다(포스터와 같은 방식).

| 단계 | 결과 |
| --- | --- |
| 원본·편집본 짝 | 편집본 이름 = 원본 주소의 SHA-256. 로컬 DB 723 장 전부, 데이터 파일 사진 주소 736 개 중 719 개가 짝이 맞는다 |
| 크기 | 편집본 PNG(약 1535px)가 한 장 중간값 2,588KB(원본 네이버 사진 854KB 의 3 배)라 **JPEG 긴 변 1280px·품질 82** 로 바꿨다 — 중간값 368KB, 최대 874KB, 722 장 269MB |
| 올린 곳 | 공용 사진 버킷 `scenetrip-media-prod` 의 새 경로 `place/edited-2026-10-22/<원본 주소 SHA-256>.jpg`(덮어쓰기 없음, 기존 객체는 그대로). 722 장 모두 공개 주소로 받아 해시가 같음을 확인 |
| 데이터 파일 | `place_image_url` 830 곳을 새 주소로, 화면 캡처 1 곳은 뺐다. 다른 칸은 바뀌지 않았다 |
| 그대로 둔 것 | 짝이 없는 원본 주소 17 곳 — 편집 목록을 만들 때 쓴 로컬 DB 에 없던 사진이라 편집본이 없다. 로컬 DB 에만 있던 4 장(학암포·섭지코지)은 데이터 파일에 없다 |

## 되돌리기

- 데이터 파일을 이 PR 이전 판으로 되돌리고 데이터 적재를 다시 돌리면 원본 주소로 돌아간다(git 기록이 원본 주소 목록이다).
- 원본·편집본 PNG·프롬프트·검수 기록은 저장소 밖 `.cache/place-photo-refresh/` 에 둔다(`review.jsonl`·`review-actions.json`·`originals/`·`pending/`).
