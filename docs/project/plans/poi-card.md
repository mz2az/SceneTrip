# 편의시설 카드 — 사진·영업시간·평점 (바깥 출처)

- **에픽**: [MZ2AZ-107](https://mz2az.atlassian.net/browse/MZ2AZ-107) "코스"
- **작성일**: 2026-09-05
- **상태**: 구현 완료(§8). **2026-10-05 부터 iOS·Android 둘 다 이 카드 엔드포인트를 부르지 않는다(§12, MZ2AZ-354).** 서버 스위치는 MZ2AZ-355
- **결정**: [ADR 0011](../../architecture/adr/0011-naver-place-unofficial-for-demo.md) — 비공식, 데모 한정
- **실측**: 볼트 「2026-09-03 네이버 매칭 거리 실측」

---

## 1. 무엇을 만드는가

경로 탭에서 편의시설 핀을 누르면 뜨는 카드. 우리 자료([poi.md](./poi.md))에 없는
사진·영업시간·별점·리뷰 수를 네이버 장소에서 가져온다. 프로토타입 `apps/navi_proto` 의
`/api/place-card` 를 서버로 옮긴 것이다.

## 2. 프로토타입이 하던 것 — 두 층

```
A  매칭   「이 가게가 네이버에 있나」   공식 지역검색(API HUB). 24 시간 배치. id 를 못 준다
B  상세   id → 사진·평점·영업시간       비공식 GraphQL(검색) + summary(상세). 폰 브라우저 위장
```

A 는 안 옮긴다 — B 의 검색이 id·좌표·이름을 다 주어 A 가 할 일이 없다. 챗봇 순위(베이지안)도
안 옮긴다. 옮기는 것은 B 와, A·B 가 같이 쓰던 **판정 규칙 `match_ok`** 다.

## 3. 결정된 것

| 결정 | 근거 |
| --- | --- |
| 핀은 우리 표, 카드는 누를 때 그 한 곳만 | 30 곳을 미리 조사하면 10 초(프로토타입의 8 초 예산). 누른 곳 하나는 0.35 초 |
| 여럿 조회는 「있는 것만 즉시 + 없는 것은 뒤에서」 | 목록 화면(미래)이 30 개 사진을 기다릴 수 없다. `pending` + `retryAfterSeconds` |
| 결과는 표 `poi_naver`, 못 찾은 것도 저장 | 다시 묻지 않는다. 「못 받음」(타임아웃·차단)은 저장하지 않아 다음에 다시 묻는다 |
| 판정 규칙은 프로토타입 그대로, 좌표는 건물 좌표 | 건물 좌표로 재니 명소 중앙값 33 m — 계단이 그대로 맞고 입구 좌표 컬럼이 필요 없다 |
| 시군구 재검색 | 결과의 30% 가 같은 이름의 다른 동네 지점. 「이름 지역 시군구」로 한 번 더 → +6~11p |
| 일꾼 하나, 초당 3 건, 막히면 쉬고 세 번이면 내림 | 한 IP 에서 두드리는 것이라 스스로 속도를 죈다 |
| 못 찾아도 200 | 「없다」도 답. 404 는 POI 자체가 없을 때뿐. 여럿에서는 없는 id 도 그 자리에 `found:false` |
| 재확인 안 함 | 데모. `checked_at`·`rule_version` 만 두어 나중에 TTL 을 붙일 때 계약이 안 바뀐다 |

## 4. 흐름

```
앱  GET /pois/{id}/card                       앱  GET /pois/cards?ids=1,…,30
      │                                              │
PoisController → PoiCardService.card            PoiCardService.cards
      │  표에 있나 → 즉시                              │  있는 것 → 카드 / 없는 것 → pending + 줄
      │  없으면 PoiCardFetcher.fetch (지금)             │  retryAfterSeconds = 줄 × 최근 평균
      │                                              ▼
      │                                        PoiCardFiller (일꾼 1)  줄에서 꺼내 fetch → 저장
      ▼
PoiCardFetcher.fetch
  NaverPlaceClient.search(이름) → NaverMatcher.pick → (헛돌면 search(이름 시군구)) → detail → NaverCard
      │
PoiNaverStore.save (UPSERT, RETURNING)
```

## 5. 표 — `poi_naver` (V14)

`poi_id` 가 기본키, 행 하나 = 한 POI 를 찾아본 결과 전부. 상태 셋 — 행 없음(안 물어봄·못 받음),
`found=false`+`why`, `found=true`+상세. `CHECK (found = (naver_id IS NOT NULL))`. `rule_version`
현재 판만 조회. 자세한 것은 마이그레이션 주석.

## 6. 계약

`GET /pois/{poiId}/card` → `PoiCard`, `GET /pois/cards?ids=` → `PoiCardBatch`. 명세 본문에 앱 규칙
(pending 이 있으면 힌트만큼 자고 pending 만 다시, 최대 3 회)이 적혀 있다.

## 7. 앱에 생기는 일

`RouteGuide.card(for:)` 가 `127.0.0.1:8899/api/place-card` 대신 생성 클라이언트의 `getPoiCard` 를
부른다. `Card` 구조체의 칸은 `PoiCard` 와 이름만 다르다(`review_count` → `reviewCount`).
`tmap_name`·`limited` 는 없어졌다.

## 12. 앱이 네이버 데이터를 걷어냈다 (2026-10-05, MZ2AZ-354)

ADR 0011 이 정한 「정식 출시 전에 대체」의 앱 쪽이다. 10월 베타(20~30명)도 외부 배포라
스토어 제출을 기다리지 않고 그 전에 걷어낸다(정승길 결정).

- **iOS·Android 둘 다 `GET /pois/{id}/card` 와 `GET /pois/cards` 를 부르지 않는다.** 카드는
  `GET /pois/{id}`(우리 공공데이터 — 이름·분류·주소·전화)로 그린다. 상세를 못 받아도 목록이
  준 이름·분류·주소로 카드가 선다
- 사진·별점·리뷰 수·영업시간은 보여 주지 않는다. 「네이버 지도에서 보기」가 이름으로 검색한
  네이버 지도 화면(`https://map.naver.com/p/search/<이름 시군구>` — 같은 이름의 다른 지점이 뜨지 않게 시군구를 붙인다)으로 **넘긴다** — 가져오지 않는다
- iOS 는 챗봇 목록의 「네이버」 딱지, 연결된 곳을 위로 올리던 정렬, 지도 핀의 초록 테를 지웠다
  (MZ2AZ-327 의 이름 맞추기는 할 필요가 없어졌다). **Android 는 그 셋을 처음부터 구현한 적이
  없어** 지울 것이 없었다 — AI 장소 점은 갈래 없는 단색 점뿐이다
- 촬영지(성지) 카드는 그대로다 — 처음부터 우리 상세(`GET /places/{id}`)에서 왔다
- Android 쪽은 `routetab/NaverMapLink.kt`(검색 링크)·`routetab/RoutePlaceCard.kt`(카드)가
  바뀌었다. 좁은 카드에서 이름 밑으로 링크를 내리는 iOS `ViewThatFits` 는 Compose에 없어
  `SubcomposeLayout`으로 다시 짰다(`PlaceCardHeader`)
- 서버의 스위치(`scenetrip.naver.enabled`)·표 `poi_naver`·계약의 카드 엔드포인트를 어떻게 할지는
  MZ2AZ-355(정권호)

나중에 정할 것: 명소 사진은 관광공사 TourAPI(운영 계정 대기), 평점이 꼭 필요하면 공식 API.

## 13. 서버 쪽 데이터 — 우리 자료로 (2026-10-04, MZ2AZ-358)

편의시설은 우리가 직접 정보를 모으는 쪽으로 간다([poi-i18n-image.md](./poi-i18n-image.md)).
모은 카드 13 행은 `just poi-naver-backup` 으로 저장소 밖에 떠 두었다. 표·코드·카드 API 는 아직
그대로이고, 서버 쪽을 걷어내는 일은 MZ2AZ-355 다.

## 14. 편의시설을 앱 언어로 적는다 (2026-10-07, MZ2AZ-360)

서버가 편의시설 응답에 새 칸을 싣는다(MZ2AZ-358, 계획은 [poi-i18n-image.md](./poi-i18n-image.md)) —
`displayName`·`displayAddress`·`categoryLabel`·`nameRoman`. 기존 `name`·`address`·`category` 는 언제나
한국어 원본이다. **§12 와 MZ2AZ-346 에 적힌 「편의시설은 언제나 한국어」는 이제 화면에는 해당하지 않는다.**

iOS 의 규칙(`RouteTab/PoiLabel.swift`, 계약 그대로):

| 자리 | 한국어 화면 | 그 밖(영어) |
| --- | --- | --- |
| 제목 | `name` | `displayName ?? name` |
| 제목 아래 | — | 영어 이름이 있으면 한국어 `name`(간판과 맞춰 본다), 없으면 `nameRoman`(읽는 법). 같은 글자면 생략 |
| 분류 | `category` | `categoryLabel ?? category` |
| 주소 | `address` | `displayAddress ?? address` |
| 지도 이름표(한 줄) | `name` | 영어 이름, 없으면 읽는 법 |
| 리뷰 시트·사진첩 머리줄(한 줄) | `name` | 제목 · 제목 아래 — 「트로 · Teuro」, 「Jeonju Restaurant · 전주식당」 (`PoiLabel.heading`, MZ2AZ-367) |
| 리뷰 쓰기 머리줄·「내 리뷰」 줄(좁은 자리) | `name` | 카드처럼 두 줄 — 제목 / 작은 아랫줄 (`PoiLabel.lines`, MZ2AZ-367) |

카드의 다듬기 (2026-10-08, MZ2AZ-367):

- **거리는 기준에 뜻이 있을 때만 적는다**(`RouteGuide.Place.shownMeters`). 지도 범위 조회(`GET /pois`)의
  `distanceMeters` 는 화면 중심에서 잰 값이라 카드에 적지 않는다. 가이드가 찾아 준 곳의 거리는 답이 밝힌
  기준에서 잰 것이라 그대로 둔다.
- **「내 리뷰」 의 편의시설 이름**은 서버(`target.name`)가 한국어 원본만 준다. 영어 화면에서는 줄이 보일 때
  `GET /pois/{id}` 를 한 번 물어 카드와 같은 두 줄(제목 / 작은 아랫줄)로 바꾼다 — 못 받으면 원본 그대로다.
  리뷰 쓰기 머리줄도 같은 두 줄이다 — 이름이 한 줄이면 높이(52pt)와 자리가 전과 같다.
- **해태 동그라미**는 카드가 화면 바닥에 떠 있는 동안 말풍선을 접고 카드 윗변 위로 비킨다
  (`RouteGuideFloatingChip.cardTop`). 사용자가 더 위로 옮겨 둔 자리는 그대로다. 카드가 뜬 채 끌면 비켜 선
  자리에서부터 따라오고, 놓은 자리가 저장된다. 꾹 눌렀다 그대로 떼면(6pt 미만) 저장하지 않는다.

- 적용한 곳: 편의시설 카드(머리줄·분류·주소), 가이드 챗봇의 장소 목록, 지도의 편의시설 점과 챗봇 핀 이름표
  (코스 편집 화면과 길찾기 화면 둘 다)
- **가이드 챗봇이 찾아 준 곳은 지금 목록과 핀 이름표가 한국어로 보인다** — 서버가 가이드 응답의 장소에는
  새 칸을 싣지 않는다(2026-10-07 실측, 계약도 「없을 수 있다」). 줄을 펼친 카드는 상세(`GET /pois/{id}`)를
  받아 제목·읽는 법·분류·주소를 앱 언어로 다시 적는다. 목록까지 영어로 하려면 서버가 가이드 장소에도 새 칸을
  실어야 한다
- **한글 이름을 지우지 않는다** — 간판이 한글이다. 영어 이름은 확실한 것(체인 브랜드·흔한 낱말)에만 있어
  대부분의 가게는 「한글 이름 + 읽는 법」으로 보인다
- 「네이버 지도에서 보기」는 여전히 한국어 이름으로 찾는다 — 영어 이름으로는 가게가 안 나온다
  (2026-10-09 부터는 이름으로 찾지 않는다 — §15)
- 코스에 담은 편의시설의 이름은 한국어 그대로 저장되고 코스 화면에도 한국어로 보인다(계약이 저장을
  한국어 `name` 에 묶었다) — 코스 화면의 영어 표시는 이 범위 밖
- Android 는 아직 한국어 원본을 보인다 — iOS 를 따라 바꾼다

## 덧붙임 (2026-10-08) — 비공식 호출을 내렸다 (ADR 0020, MZ2AZ-355)

베타(외부 배포) 전에 네이버 비공식 호출을 내렸다. `scenetrip.naver.enabled` 는 기본값까지 false, 이미 모은 `poi_naver` 행은
V23 이 비웠다(스위치만 끄면 카드 창구가 표의 행을 계속 내준다). 카드 창구 둘은 계약에서 deprecated — 꺼진 채 늘 「못
찾음」 이고, 코드와 함께 다음 메이저에서 뺀다. 앱은 이미 부르지 않는다(MZ2AZ-354). 카드는 `GET /pois/{poiId}`(공공데이터 +
우리 리뷰의 `rating`·`photos`)로 그리고, 더 볼 것은 네이버 지도 **링크**로 넘긴다 — 앱이 `map.naver.com/p/search/<이름>
<시군구>` 를 만든다. 이 문서의 나머지(매칭 규칙·채우는 일꾼)는 기록으로 남는다.

## 15. 네이버 버튼은 그 가게 화면으로, 없으면 숨긴다 (2026-10-09, MZ2AZ-373·374)

§12 와 위 덧붙임의 「앱이 `map.naver.com/p/search/<이름> <시군구>` 를 만든다」 는 **iOS 에서는 더 이상 참이 아니다.**

**왜 바꿨나.** 이름 검색 링크(MZ2AZ-354)는 약했다 — 같은 구에 같은 이름이 여럿이면 함께 뜨고, 사용자가 검색 결과에서
그 가게를 다시 골라야 한다. 서버가 편의시설 상세를 열 때 네이버 장소 번호 하나만 찾아
`PoiDetail.naverPlaceUrl`(`https://map.naver.com/p/entry/place/{번호}`, 선택)로 싣게 됐다(MZ2AZ-373, 계약 scene-api
1.6.0, [ADR 0021](../../architecture/adr/0021-poi-naver-link-by-place-id-lookup.md)). 사진·평점·영업시간은 여전히 가져오지
않고, 카드 창구(`/pois/{id}/card`·`/pois/cards`)도 계속 부르지 않는다.

iOS 의 규칙(`RouteTab/NaverMapLink.swift`, `RouteGuide.card(for:)`):

| 편의시설 상세의 `naverPlaceUrl` | 카드의 「네이버 지도에서 보기」 |
| --- | --- |
| 있다 | 그 주소를 연다 — 그 가게의 네이버 장소 화면 |
| 없다(네이버에 없음·스위치 꺼짐·막힘·느림·옛 서버) | **버튼이 없다** |
| 상세를 못 받았다(카드는 목록이 준 것으로 선다) | 버튼이 없다 |
| `https` 가 아니거나 호스트가 네이버(`naver.com`·그 아래·`naver.me`)가 아니다 | 버튼이 없다 — 「네이버 지도에서 보기」 라고 적고 다른 데로 보내지 않는다 |

- **이름 검색 링크로 넘기지 않는다.** 엉뚱한 가게로 보내느니 없는 편이 낫다(정권호 결정 2026-10-09). `NaverMapLink.search`
  는 쓰는 곳이 없어 지웠다 — 같은 타입에 서버 주소를 추리는 `NaverMapLink.place(_:)` 가 들어섰다.
- **버튼은 상세가 온 뒤에 선다.** 카드가 뜨고 상세를 받는 동안에는 없다 — 처음 여는 곳은 서버가 그때 번호를 찾느라 상세
  응답이 늦을 수 있다(로컬에서 서버 응답 0.2~0.4 초, 화면에서는 '불러오는 중' 이 0.4~0.6 초 — 계약 「최대 1.5 초」). 넓은 카드에서는 이름 옆, 닫기 단추 높이 안에 서서 줄이 밀리지
  않는다. 좁은 카드(가이드 시트 안)에서는 이름 아래 한 줄이 생기는데 그때 분류·주소 표도 함께 들어온다.
- 버튼이 없는 카드는 머리줄에 이름과 닫기만 남는다 — `ViewThatFits` 가 한 줄 배치를 고르고 빈 줄은 생기지 않는다.
- **떠 있는 카드를 다시 읽다 실패하면 가진 것을 둔다**(`RouteGuide.Card.keeps`). 리뷰 시트·사진첩을 닫으면 상세를 다시
  받는데, 그 요청이 실패했다고 떠 있던 버튼·전화·사진·별점을 지우지 않는다.
- 주소 검사는 퍼센트 인코딩을 풀기 전의 호스트 글자를 본다 — `%` 가 든 호스트, 끝 점, 포트가 붙은 주소는 열지 않는다.
- **가이드 챗봇이 찾아 준 편의시설**도 같은 카드(`RoutePlaceCard` → `RouteGuide.card(for:)` → `GET /pois/{id}`)라 같은
  규칙이다. 챗봇 응답 자체에는 링크가 없다.
- **촬영지는 그대로다** — 성지 카드와 촬영지 상세는 전부터 `PlaceDetail.naverPlaceUrl` 을 있을 때만 썼다.
- Android 는 MZ2AZ-374 의 Android 몫에서 따라온다.

실측(2026-10-09, 로컬 kind): 편의시설 7 곳(수원 화홍문 주변 6, 부산 1)을 열어 5 곳에 장소 화면 주소가 왔고 2 곳은 비어 왔다.
