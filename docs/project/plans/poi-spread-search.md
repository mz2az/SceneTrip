- **상태**: 구현·로컬 확인 끝(2026-11-09). DEV 실측 남음
- **앞선 문서**: [web-proto-apply.md](./web-proto-apply.md) §3 B3·B4, [poi.md](./poi.md)

## 1. 왜

코스 편집 지도의 편의시설은 지금 「화면 가운데에서 가까운 순 N곳」 이다. 넓게 보면 가운데에 뭉친다. 웹 시안은 이름순 200곳 표본을 받아
앱이 칸으로 솎는데, 칸의 진짜 1등이 빠질 수 있고 지도를 옮겨 다시 찾으면 바뀐다. 편의시설 이름으로는 아예 찾을 수 없다(`q` 가 없다).

## 2. 무엇 — 계약에 더하는 것

### 2-1. `sort=spread` + `spreadZoom` (MZ2AZ-540)

구글 지도처럼 **지도에 고정된 칸마다 순위 1등부터** 돌려준다.

- `spreadZoom`(0~22, `sort=spread` 일 때 필수): 지금 지도 확대 단계(정수). 칸은 웹 메르카토르 타일 `spreadZoom + 2` 단계 —
  타일 한 장(256px)을 4×4 로 나눈 64px 칸이다. 칸이 지도에 고정이라 지도를 옮겨도 같은 곳이 같은 칸에 든다.
- 순위(칸 안): `popularity_score` 큰 순 → 갈래(교통 0 · 명소 1 · 숙소 2 · 식당·카페 3) → `id` 를 섞은 값(Knuth 곱셈 해시) → `id`.
  하나의 줄이라 넓을 때 칸 1등은 확대해 쪼갠 칸에서도 1등이다 — 확대하면 점이 늘기만 한다.
- 돌려주는 순서: 모든 칸의 1등(칸 안 순위로) → 모든 칸의 2등 → … 에서 `limit` 만큼. 그래서 `limit` 이 칸 수보다 작으면 가장 순위 높은 칸 1등만 온다.
- 항목마다 `spreadRank`(칸 안 순위, 1 이 칸 1등). 앱은 1 을 큰 점, 나머지를 작은 점으로 그린다. 다른 정렬에서는 없다.
- `bbox` 가 있어야 한다(칸은 화면 기준). 반경과는 함께 쓸 수 없다(지금 규칙 그대로). `lat`·`lng` 는 받지만 순서에 쓰지 않는다
  (`distanceMeters` 를 채우는 데만).

### 2-2. `q` (MZ2AZ-283)

- 이름(한국어 원본)·영문 이름(`poi_i18n`)·읽는 법(`name_roman`)에 부분 일치. 정규화는 촬영지 검색과 같은 `search_normalize`
  — 색인(`poi_name_trgm_idx`, `poi_i18n_name_trgm_idx`)과 같은 식이라 색인을 탄다.
- 2자 이상(앞뒤 공백 제거 후). 그보다 짧으면 400 `INVALID_PARAMETER` — 1자는 47만 행 거의 전부에 걸린다.
- **`q` 가 있으면 영역 조건 없이도 된다**(「이 지역 밖에서도 찾기」). 영역이 있으면 그 안에서만.
- 정렬 규칙은 지금 그대로(기준점이 있으면 거리순, 없으면 이름순). `q` 와 `spread` 는 함께 쓸 수 있다.

### 2-3. 바뀌지 않는 것

기존 앱(iOS·Android·웹)이 보내는 요청의 답은 한 글자도 바뀌지 않는다 — 새 값은 새 파라미터를 줄 때만.

## 3. 어떻게

- `PoiStore.Sort.SPREAD`: 화면 네모 안 행에 칸 번호(`cx`, `cy`)와 칸 안 순위(`ROW_NUMBER() OVER (PARTITION BY cx, cy ...)`)를 매기고
  `ORDER BY rank, 칸 안 순서` 로 자른다. 칸 번호는 SQL 로 계산한다:
  `cx = floor((lng + 180) / 360 · 2^z)`, `cy = floor((1 − ln(tan(lat) + sec(lat)) / π) / 2 · 2^z)`.
- `q`: `matched` 부분 질의(이름·번역 이름·읽는 법)로 id 를 먼저 모으고 본 질의는 `p.id IN matched`. 목록·개수가 같은 조건을 쓴다.

## 4. 시험

| 갈래 | 무엇 |
| --- | --- |
| 단위(`@WebMvcTest`) | `sort=spread` 에 `spreadZoom` 없음 → 400, `bbox` 없음 → 400, 범위 밖 → 400. `q` 1자 → 400. `q` 만(영역 없음) → 200 |
| 통합(실제 PostgreSQL) | 같은 칸 두 곳 중 순위 높은 쪽이 `spreadRank=1`, 다른 칸 1등이 다음 칸 2등보다 먼저. 교통이 식당보다 먼저(인기도 같을 때). 두 번 물어도 같은 답. `q` 가 한국어 이름·영문 이름에 걸리고 폐업은 빠진다. 기존 거리순·이름순 답은 그대로 |
| 실제 요청 | 로컬 `just update scene-api` 뒤 curl — 정상과 400 들. DEV 배포 뒤 넓은 범위 시간 실측 |

## 5. 위험

- 넓은 화면은 네모 안 행을 다 본다(칸마다 고르기). 수도권 넓게 47만 행 이름순 0.85초가 기준(DEV, 2026-11-08). 느리면 확대 단계 몇 개의
  칸 번호를 미리 계산해 색인한다 — 실측 뒤 정한다. **DEV 에서 전체 요청 분포로 잰다**(메모: 한국어만 재고 정했다가 처리량이 13% 나빠진 사례).
