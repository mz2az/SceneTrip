# 홈 탭 — 4탭을 3탭으로 재편하고 홈을 첫 화면으로 (iOS)

> 목업: [`docs/product/canvas/home/`](../../product/canvas/home/) (`Main.dc.html` 첫 화면,
> `HomeFull.dc.html` 피드 이어짐, `AltMagazine.dc.html` 기각 대안). 정승길이 2026-09-01
> 그린 시안을 드롭박스 `SceneTrip_design/home` 에서 옮겨 왔다.

## 1. 무엇을 바꾸나

지금 앱은 하단 탭 넷(작품검색·경로여정·커뮤니티·마이페이지)이고 첫 탭이 검색이다.
목업은 **탭 셋** — 왼쪽 작품검색, 가운데 동그란 홈(해태 얼굴), 오른쪽 커뮤니티 — 이고
홈이 첫 화면이다. 없어지는 두 탭은 사라지는 게 아니라 **홈 안으로 들어간다**:

| 없어지는 탭 | 새 입구 |
| --- | --- |
| 경로여정 | 홈 맨 위 고정 카드 「내 여행 이어가기」 (+ 「여행자들의 코스」 절의 「둘러보기」) |
| 마이페이지 | 홈 오른쪽 위 프로필 단추 (+ 「내 기록」 절) |

두 화면의 **코드는 그대로 둔다.** 탭 대신 홈에서 전체 화면(`fullScreenCover`)으로 띄우고,
닫기 단추 하나만 얹는다. 지금까지 만든 API 연동·화면은 전부 살아 있다.

**「코스마켓」은 「둘러보기」로 개명한다**(2026-09-02 사용자 결정). 마켓은 돈이 오가고
보기 전에 산다는 뜻을 풍기는데, 이 화면은 유저·운영진이 짠 코스를 구경하고 마음에 들면
내 코스로 담는 곳이다. 세그먼트는 「내 코스 ｜ 둘러보기」, 홈의 절 제목은 「여행자들의
코스」. 운영진 코스에 「SceneTrip 추천」 배지를 달려면 마켓 API 에 그 사실을 알려 주는
필드가 필요하다 — 지금 `MarketCourseSummary` 에는 없어 후속 티켓이다. 코드 식별자
(`RouteMarketView`, `/market/courses`)는 계약이라 그대로 둔다.

목업에서 **빼는 것 하나** — 맨 윗줄 검색칸. 사용자 지시(2026-09-01)로, 검색은 작품검색
탭이 맡는다.

## 2. 홈의 절과 데이터 출처

위에서부터. 숫자·문구는 목업이 "배치용 예시" 라고 못 박았으므로 전부 서버·기기 값이다.

| 절 | 내용 | 데이터 | 누르면 |
| --- | --- | --- | --- |
| 인사 | 해태 얼굴 + "해태가 기다렸어요 / 오늘은 어느 장면으로 갈까요?" + 프로필 단추 | — | 프로필 → 마이페이지 화면 |
| **내 여행 이어가기** (고정 카드, 그러데이션) | 여행 중인 코스(없으면 최근 코스): 제목·기간·곳수, 스탬프 진행바 `방문/전체`, 「이어서 길찾기」「코스 보기」. 코스가 하나도 없으면 「여행을 시작해 볼까요?」 + 「코스 만들기」 | `RouteStore.courses` + `CoursesAPI.getCourse`(방문 `visitedAt`·`currentDayNo`) | 길찾기 → 오늘 일차의 다음 미방문 정지점으로 `RouteNavView` · 코스 보기 → 경로여정 화면(편집 열림) |
| 지금 뜨는 작품 | 포스터 가로 스크롤, "촬영지 N곳" | `ContentsAPI.listContents` 를 `placeCount` 내림차순 | 작품 → 작품검색 탭의 작품 상세 · 「전체 보기」 → 작품검색 탭 |
| 오늘의 성지 | 매일 한 곳 — 작품 배지, 장소명 + 장면 설명, 주소, 「길찾기」 | `PlacesAPI.listPlaces`(인기순) 에서 **연중 일수(day-of-year) 로 하나** 고른다 — 하루 동안은 같은 곳 | 길찾기 → 그 장소로 `RouteNavView` |
| 여행자들의 코스 | 카드 둘 — 작품·제목·곳수·담기·♥ | `RouteStore.marketCourses`(담기 많은 순) | 카드·「둘러보기」 → 경로여정 화면(둘러보기 세그먼트) |
| 커뮤니티 지금 | 최근 글 둘 — 게시판 배지·제목 | `CommunityStore.posts` | 행·「더 보기」 → 커뮤니티 탭 |
| 내 기록 | 방문 스탬프 셋 + 「+N」, 찜한 작품 수 | `VisitStamp`(코스 상세의 `visitedAt`) · `LikeStore` | 마이페이지 화면 |

목업의 「지금 나에게서 1.9 km」 는 **첫 판에서 뺀다.** 홈에서 위치 권한을 묻고 싶지
않다 — 길찾기 화면이 이미 그 일을 한다. 주소만 보여 준다.

## 3. 구조

```
RootTabs                         탭 셋 + 전체 화면 덮개(경로여정·마이페이지)
├── SearchTabView                (그대로, 항상 살려 둠)
├── HomeTab/HomeTabView          홈 — 아래 절들을 세로로
│   ├── HomeTabModel             서버 호출과 「내 여행」 계산
│   ├── HomeCards                인사 · 내 여행 카드 · 작품 선반 · 오늘의 성지
│   └── HomeFeed                 여행자들의 코스 · 커뮤니티 지금 · 내 기록
└── CommunityTabView             (그대로)

TabRouter                        selected(3탭) + cover(.route(market:) | .profile)
                                 + pendingCourseId(기존) + pendingContentId(신설)
```

- **홈도 검색 탭처럼 항상 살려 둔다**(opacity 전환). 탭을 오갈 때마다 서버를 다시 부르지
  않기 위해서다. 커뮤니티는 값이 싸서 만들고 버린다.
- `TabRouter.cover` 가 덮개 하나를 든다. 마이페이지에서 「경로여정에서 열기」 를 누르면
  `cover` 가 `.profile` → `.route` 로 바뀌고 SwiftUI 가 덮개를 갈아 끼운다 — 덮개 둘을
  겹치지 않는다.
- `RouteTabView`·`ProfileTabView` 는 `onClose` 를 받으면 닫기 단추를 그린다. 안 받으면
  예전과 같다(탭 루트로도 쓸 수 있게 남겨 둔다).
- 확인용 뒷문 `-initialTab` 은 유지한다: `search`·`community` 는 탭, `route`·`profile`
  은 홈 + 덮개로 푼다. 인자가 없으면 **홈**이다(예전엔 검색).
- 탭바는 56 pt. 가운데 홈 단추(62 pt 원, 핀 그러데이션 `#8FCCF7→#7A68ED`, 4 pt 바탕색
  테)가 26 pt 위로 솟는다. 고른 홈 글자색은 목업의 `#5B49D6`.

## 4. 지키는 것

- 검색 탭의 바텀시트 스냅은 탭바 높이(52→56)에 걸려 있다 — 4 pt 차이는 시트 최대 높이만
  살짝 줄이고 비율은 그대로다. 눈으로 확인한다.
- 이미지는 있는 것을 쓴다 — 해태 얼굴은 `Images.xcassets/haetae-face`(목업의 PNG 와 같은
  컷). 새 그림을 넣지 않는다.
- 아이콘은 SF Symbols. 이모지를 아이콘 자리에 쓰지 않는다(`_ios.md`).
- 서버가 꺼져 있으면 절이 비거나 「불러오지 못했습니다」 한 줄 — 홈이 죽지 않는다.

## 5. 검토한 대안

| 선택지 | 채택하지 않은 이유 |
| --- | --- |
| 경로여정·마이페이지를 숨은 탭으로 남기고 `selected` 만 바꾼다 | 돌아올 길(뒤로)이 없다. 탭바에 없는 화면은 덮개가 맞다 |
| 홈의 `NavigationStack` 에 두 화면을 push | 둘 다 자기 `NavigationStack` 을 든다 — 중첩 스택은 SwiftUI 가 지원하지 않는다 |
| 매거진형(`AltMagazine`) | 절 구분이 없어 「내 여행」 이 여행 중일 때만 나타난다 — 경로여정 입구가 사라졌다 나타나는 건 첫 판에 위험 |

## 6. 완료 조건

- 시뮬레이터 첫 화면이 홈이고, 탭 셋이 목업 배치와 같다.
- 홈의 모든 단추가 기존 화면으로 이어진다(작품 상세·길찾기·경로여정·마켓·커뮤니티·마이페이지).
- `-initialTab route`·`profile` 뒷문이 여전히 그 화면을 연다.
- `just check`(Android 제외) 초록.
