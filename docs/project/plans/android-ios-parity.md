# Android 최신 iOS 기능 맞추기

## 기준과 범위

2026-10-10의 iOS 소스와 현재 작업 트리의 관광공사 사진 표시 변경을 대조군으로 삼는다.
기존 iOS·디자인 작업 파일은 보존한다. Android Studio 없이 `just`·Bazel로 빌드한다.
서버 계약은 이미 마련돼 있어 새 API를 만들지 않고 생성된 Kotlin 클라이언트를 소비한다.

| 영역 | Android에 반영할 동작 | 기준 |
| --- | --- | --- |
| 장소·편의시설 | 연결된 촬영지가 대표, POI 다국어 표기, 공식 네이버 장소 링크 | `place-poi-link.md`, iOS `PlacePoiLink`·`PoiLabel` |
| 코스 | 촬영지·POI·개인 핀 구분, `poiId` 왕복 보존, 가이드의 `placeId` 사용 | `course-poi-item.md`, iOS `RouteStopKind`·`RouteBridge` |
| 리뷰 | 요약·정렬·페이지, 작성·수정·삭제, 로그인·닉네임, 내 리뷰 | `review-app.md`, iOS `Reviews/` |
| 사진 | 공식·리뷰 사진첩, 출처·전체 비율 표시, 10장 업로드와 EXIF 제거 | `review-app.md`, `tour-photo-display.md` |
| 네트워크 | 읽기 요청의 제한된 재시도, 취소·늦은 결과 보호, 유료 호출 자동 재전송 금지 | `app-retry.md`, iOS `RetryRules`·`RetryingSession` |
| 여행 가이드·길찾기 | 같은 멱등 키로 명시적 재시도, 사용 한도 안내·차단, 지도 앱 연결 | `app-retry.md`, iOS `RouteGuideLimit`·`RouteNavLimit` |
| 검색·홈·프로필 | 최신 데이터·사진·리뷰 입구 연결, 기존 탭 동선 유지 | 현재 iOS 소스 |

## 작업 순서와 검증

1. 기존 Android APK 빌드를 확인한다.
2. 순수 규칙과 계약 왕복을 검증하는 Android 단위 테스트 타깃을 추가한다.
3. 코스·POI 규칙을 먼저 맞추고 리뷰·사진 UI와 저장을 연결한다.
4. 공통 요청 재시도와 가이드·길찾기 한도 상태를 연결한다.
5. 변경한 소스를 BUILD 파일에 명시하고 모듈 README를 현행화한다.
6. Android 단위 테스트·APK 빌드·`just check`를 실행한다.
7. 에뮬레이터에서 화면을 확인하고 검증 범위·남은 제약을 문서에 기록한다.

실서버 리뷰 작성·유료 가이드 호출·공유 환경 변경은 검증에 사용하지 않는다.
자동 GPS 시연은 Android 에뮬레이터 기능으로 처리하며 iOS 전용 실행 인자는 이식하지 않는다.

## 반영 결과

리뷰·사진·닉네임과 프로필 입구, 촬영지·POI·개인 핀 구분 및 저장 왕복, 코스 저장 실패 시
편집 유지·취소 확인, 가이드 계획·화면 명령 적용, 요청별 재시도·취소·한도 안내,
지도 앱 연결과 최신 영어 문구를 구현했다.
가이드의 같은 결과도 매 응답마다 적용하며 계획을 먼저 바꾼 뒤 날짜·카메라 명령을 적용한다.
GPS 안내는 계정·대상 변경 뒤 늦은 결과를 무시하고 백그라운드에서는 위치 수집·도착 판정을 멈춘다.
