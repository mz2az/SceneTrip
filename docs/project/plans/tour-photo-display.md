# 관광공사 사진 표시 (MZ2AZ-385)

## 문제와 범위

관광공사 원본은 긴 변이 5,000px를 넘는 경우가 있다. 검색 목록의 `RemoteImage`는
`AsyncImage`로 원본을 풀고, 대표·카드 사진은 채우기로 잘라 하단 출처를 가린다.
사진첩에는 출처가 내려오지만 크게 보기에서만 보였다.

- 공식 사진 호스트 `tong.visitkorea.or.kr`의 HTTPS URL만 기존 `PhotoLoader`의
  360px 표시용 디코딩 경로로 보낸다. 파일은 다시 만들거나 저장하지 않는다.
- 관광공사 공식 사진은 credit 없는 옛 URL도 전체 비율로 맞춘다. 방문자 사진과
  일반 포스터는 현재 표시를 유지하며 서명 사진의 메모리·ephemeral 정책을 바꾸지 않는다.
- 대표 사진 아래에는 현재 사진의 `credit`, 지도 카드 사진 줄 아래에는 중복을 뺀
  credit를 원문 그대로 적는다. 사진에 표기를 덮어 원본을 가리지 않는다.
- 대표 사진 영역만 180pt로 제한하고 출처에는 필요한 높이를 준다. 격자의 출처는
  사진과 함께 스크롤되어 긴 표기가 사진 목록을 가리지 않는다.
- 대표·카드의 밝은 배경에서도 진행·실패가 보이도록 사진 위젯의 배경 표시를 분리한다.

## 구현·검증 순서

1. 기존 사진 규칙 시험에 공식 호스트 경계, 원본 비율 보전, credit 중복 제거,
   서명 리뷰 구분을 추가하고 실패를 확인한다.
2. `RemoteImage`의 관광공사 경로와 대표·카드·격자의 표시만 수정한다.
3. 로컬에서 만든 큰 JPEG로 360/1600px 디코딩을 시험하고 `just check`를 실행한다.
4. 시뮬레이터에서 대표·카드·크게 보기와 출처, 일반·방문자 사진을 확인한다.

API·DB·계약·라이선스 문자열은 변경하지 않는다. 작은 관광공사 URL을 별도로 내려주는
서버 작업과 Type3 약관의 해석은 MZ2AZ-376 범위에 남는다.
