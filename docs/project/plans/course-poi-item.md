# 코스에 편의시설을 편의시설로 담는다 — `course_item.poi_id` (MZ2AZ-377)

지금 코스 항목은 촬영지(`place_id`) 아니면 개인 핀(`custom_pin_id`)이다. 앱은 편의시설을 담을 때 **개인 핀**(이름·좌표·분류
사본)으로 저장한다 — 불러와도 지도에는 보이지만 「편의시설 277819」 라는 정체가 사라져 코스에서 그 가게의 상세(리뷰·네이버 링크·
전화)로 갈 수 없다. [poi.md](./poi.md) §3-2·§4-2 가 잡아 두었던 「코스 항목 세 갈래」 를 이제 한다(그때 잡은 V15 는 로그인이
가져갔다 — V26).

## 1. 결정 (2026-10-09)

| 담는 것 | 저장 | 이유 |
| --- | --- | --- |
| 촬영지 | `place_id` | 그대로 |
| 촬영지와 같은 곳인 편의시설(`placeId` 가 있다, MZ2AZ-371) | **`place_id`** — 서버가 바꿔 저장한다 | 「어디서든 촬영지가 대표」 ([place-poi-link.md](./place-poi-link.md)). 앱이 놓쳐도 서버가 막는다 |
| 그 밖의 편의시설 | **`poi_id`** — 참조 | 우리가 관리하는 자료다. 이름·주소가 갱신되면 코스에도 반영되고, 코스에서 상세로 갈 수 있다 |
| 사용자가 지도에 찍은 점 | `custom_pin_id` — 사본 | 그 사람만의 것이다(숙소 위치 등) |

- **셋 중 정확히 하나** — `CHECK (num_nonnulls(place_id, poi_id, custom_pin_id) = 1)`. `<>` 로 쓴 배타적 논리합은 셋에서는
  읽을 수 없다(poi.md §4-2).
- **편의시설을 지우면(`seed-poi --prune`, 출처를 통째로 바꿀 때만) 그 항목도 지워진다**(`ON DELETE CASCADE`) — 촬영지·리뷰와
  같은 규칙. 분기 갱신(`--update`)은 지우지 않고 폐업 표시(`closed_at`)만 하므로 코스 항목은 남는다.
  (2026-10-09 덧붙임: `--prune` 은 없앴다 — POI 는 어떤 경우에도 지우지 않고 `closed_at` 으로 숨긴다. [ADR 0022](../../architecture/adr/0022-poi-multiple-source-ids-and-never-delete.md))
- **폐업한 편의시설 항목**은 코스에 남고 이름·좌표도 그대로 보인다(상세는 404). 사용자가 직접 뺀다.

## 2. 마켓 사본 — 이번에는 편의시설을 빼고 올린다

`MarketItem.placeId` 가 계약에서 **필수**다. 편의시설을 실으려면 그것을 선택으로 바꿔야 하는데, 생성된 앱 클라이언트의 타입이
바뀌어(`Int64` → `Int64?`) 앱 빌드가 깨지는 **파괴적 변경**이다. 그래서 이번에는 직접 찍은 핀과 같이 **편의시설 항목도 마켓
사본에서 빠진다** — 지금 개인 핀으로 저장된 편의시설이 빠지는 것과 같은 동작이라 사용자가 보기에 나빠지지 않는다. 마켓에 편의시설을
싣는 것은 다음 메이저(카드 창구를 빼는 것과 함께)에 한다.

## 3. 계약 (scene-api 1.8.0)

| 자리 | 바뀜 |
| --- | --- |
| `CourseItemSource` | `poi` 가 더해진다 |
| `CourseItem.poiId` | 새 칸(선택) — 편의시설일 때만. 상세는 `GET /pois/{poiId}` |
| `CourseItem.address`·`category`·`imageUrl` | 편의시설이면 편의시설의 주소·분류(「카페」)·첫 사진 |
| `CourseItemInput.poiId` | 새 칸(선택) — `placeId`·`poiId`·`customPin` 중 **정확히 하나**. 같은 곳으로 연결된 편의시설이면 서버가 촬영지로 저장해 돌려준다 |
| `CourseItemInput.dwellMinutes` | 비우면 편의시설은 갈래별 기본값(§4) |
| `createMarketCourse` | 「직접 찍은 핀과 편의시설은 빠진다」 |

**`source: poi` 는 낡은 앱을 깨뜨린다 — 그래서 언제 생기는지를 막는다.** 생성된 앱 클라이언트는 모르는 enum 값을 받으면 디코딩이
실패한다(Swift: `String` Codable enum, Kotlin: Moshi 에 기본값 처리 없음 — 2026-10-09 생성물 확인). `source: poi` 항목이 든
코스를 낡은 앱이 받으면 **그 코스 전체를 못 연다.** 그래서

- 서버는 `poiId` 를 **받았을 때만** 편의시설 항목을 만든다. 낡은 앱은 `poiId` 를 보내지 않는다(개인 핀으로 저장) — 낡은 앱만 쓰는
  사용자의 코스에는 `source: poi` 가 생기지 않는다.
- 마켓 사본에는 편의시설이 실리지 않는다(§2) — 남의 낡은 앱으로 퍼지지 않는다.
- 이미 저장된 개인 핀을 편의시설로 바꾸는 일(§5)은 **앱(MZ2AZ-380)이 배포되고 낡은 판이 충분히 줄어든 뒤에** 돌린다.
- 남는 틈: 한 사람이 새 앱과 낡은 앱을 두 기기에서 같이 쓰면 낡은 쪽이 그 코스를 못 연다. 베타(20~30 명)에서 감수한다.
- 앞으로를 위해: 생성기에 「모르는 enum 값은 기본 case 로」(`enumUnknownDefaultCase`)를 켜는 것을 앱 티켓에 제안한다 — 켜면 앱의
  `switch` 가 새 case 를 다뤄야 해서 앱 쪽 일이다.

## 4. 서버

- **V26**: `course_item.poi_id` + 셋 중 하나 제약 + 인덱스.
- **`CourseController.validate`**: 셋 중 정확히 하나. 없는 편의시설·폐업한 편의시설이면 400(`POI_NOT_FOUND` 와 같은 꼴로).
- **`CourseStore`**
  - 저장(`insertItem`·`moveItem`): `poiId` 가 같은 곳으로 연결돼 있으면 `place_id` 로 바꿔 넣는다.
  - 조회(`ITEMS_SQL`): `poi` 를 붙여 이름·주소·분류·좌표·첫 사진. `source`·`poiId` 를 싣는다.
  - 길찾기 목적지(`findItemLocation`): 편의시설 좌표도.
  - 체류 기본값(`dwellMinutes`): 편의시설은 `category_group` 별 — `scenetrip.course.dwell.by-poi-group`
    (food 60 · sight 60 · stay 30 · transit 15). 숙소는 짐 맡기기·체크인 정도로 짧게 둔다.
- **`MarketStore.publish`**: 지금처럼 `place_id IS NOT NULL` 만 — 편의시설이 자연히 빠진다(§2).
- **같은 곳 연결(`place_poi_link.sql`)**: 연결된 편의시설을 가리키는 코스 항목도 촬영지로 바꾼다 — 리뷰를 옮기는 것과 같은 자리.

## 5. 이미 개인 핀으로 저장된 편의시설 옮기기

`just course-pin-to-poi [--dry-run]` — 개인 핀 중 **이름이 정확히 같고 1 m 안**에 영업 중인 편의시설이 있으면 그 편의시설 항목으로
바꾼다(같은 곳으로 연결된 편의시설이면 촬영지로). 앱은 편의시설의 이름·좌표를 그대로 복사해 핀을 만들었으므로 이 기준이면 맞는다.
못 찾으면 핀으로 둔다. 바꾼 뒤 아무 항목도 가리키지 않는 핀은 지운다.

마이그레이션이 아니라 명령으로 두는 이유: 낡은 앱이 그 코스를 다시 저장할 때 `source: poi` 항목을 어떻게 다루는지 앱 배포 전에는
보장할 수 없다(§3). **앱(MZ2AZ-380)이 배포된 뒤에 돌린다.**

## 6. 앱 (정승길 — MZ2AZ-380)

- 편의시설을 담을 때 개인 핀이 아니라 `poiId` 로 저장한다(`placeId` 가 있으면 촬영지로 — MZ2AZ-378).
- `source: poi` 항목을 받아 그린다 — 누르면 편의시설 상세, 편의시설 표시(분류).
- iOS 는 지금 챗봇이 보여 준 **촬영지까지** 핀으로 담는다(`RouteGuideSheet.swift`, `pinned: true`) — 촬영지는 `placeId` 로 담아야
  한다. Android 는 `source == poi` 만 핀으로 담는다.

## 7. 순서

1. 계약 PR(1.8.0) → 머지, 앱 티켓 MZ2AZ-380.
2. 서버: V26 · 검증 · 저장(연결 바꾸기) · 조회 · 길찾기 · 체류 기본값 · 같은 곳 연결이 코스 항목도 바꾸기 · `just course-pin-to-poi`.
   시험은 새 컨텍스트가 명세로.
3. 로컬에서 실제로 — 편의시설로 담아 저장·불러오기, 연결된 편의시설은 촬영지로 저장되는지, 여행 모드 길찾기 목적지, 마켓에 올리면
   빠지는지, `course-pin-to-poi --dry-run`.

## 8. 하지 않는 것

- 마켓 사본에 편의시설 싣기 — 다음 메이저(§2).
- 커뮤니티 여행후기의 코스 사본 — 앱 기기 안에만 있다. 앱 티켓에서 같이 본다.
