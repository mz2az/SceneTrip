# 사용자가 담은 것이 목록에서 빠졌을 때 알린다 — 숨긴 촬영지·작품, 폐업한 편의시설 (MZ2AZ-451)

적재 CSV 에서 빠진 촬영지·작품은 지우지 않고 숨긴다(`hidden_at`, V20 — [place-key-seed.md](./place-key-seed.md) §2-2).
폐업한 편의시설도 지우지 않는다(`poi.closed_at`). 숨긴 것은 지도·목록·검색에서는 빠지지만 **사용자가 담아 둔 것에는
그대로 남는다** — 사용자가 담은 것을 서버가 말없이 지우지 않으려는 결정이고, 그대로 둔다.

빈틈: 응답에 그 사실을 알리는 칸이 없어 **앱이 숨긴 장소·폐업한 가게를 다른 것과 똑같이 보여 준다.** 「촬영지가 아니었다」 는
이유로 빠진 곳이나 문 닫은 식당을 사용자가 믿고 찾아갈 수 있다.

## 1. 결정 (2026-10-15, 권호)

| 항목 | 결정 | 이유 |
| --- | --- | --- |
| 처리 | 지우지 않고 **표시**한다 — 사용자가 직접 뺀다 | 자동으로 지우면 사용자가 담은 것이 말없이 사라진다. 다시 CSV 에 들어오면 숨김이 풀리는데 그때는 이미 없다 |
| DB | **바꾸지 않는다** — `place.hidden_at`·`content.hidden_at`·`poi.closed_at` 이 이미 있다 | 서버는 이 값으로 이미 목록·검색에서 거른다. 응답에 실어 주기만 하면 된다 |
| 칸 | 촬영지·작품은 `delisted`, 편의시설은 `closed` — 둘로 나눈다 | 앱이 보여 줄 문구가 다르다(「더 이상 소개하지 않는 장소예요」 · 「폐업했어요」). 하나로 합치면 이유를 가릴 수 없다 |
| 범위 | **장바구니, 내 코스, 찜한 작품** | 사용자가 담아 둔 것이다 |
| 범위 밖 | 후기·마켓의 코스 사본 | 모두가 보는 공개 글이다 — 거기 든 숨긴 장소를 어떻게 보일지는 다른 결정(글쓴이 몫인지 등). 필요하면 따로 |
| 편의시설 폐업 | 함께 한다 | 같은 화면(내 코스)·같은 문제·같은 해결 — 따로 하면 앱을 두 번 고친다 |

## 2. 계약 (더하기만)

| 응답 | 항목 | 더하는 칸 |
| --- | --- | --- |
| 장바구니(`GET /cart`, `POST /cart/items`) | `CartItem` — 촬영지 | `delisted` |
| 내 코스(`GET·PUT /courses/{id}` 등) | `CourseItem` — 촬영지·편의시설·직접 찍은 핀 | 촬영지 줄 `delisted`, 편의시설 줄 `closed` |
| 찜한 작품(`GET /favorites/contents`) | 작품 | `delisted` |

- 값은 `true`/`false`(필수 아님 — 없으면 `false` 로 읽는다). 해당 없는 줄(핀, 편의시설 줄의 `delisted` 등)은 없다.
- 찜한 작품은 `ContentSummary` 를 쓴다. `ContentSummary` 는 작품 목록·검색에도 쓰이는데 거기서는 숨긴 작품이 애초에 빠지므로
  늘 `false` 다 — 칸의 뜻은 「목록에서 빠졌는가」 로 같다.
- 다시 CSV 에 나오면 `hidden_at` 이 비워지고 칸은 `false` 로 돌아온다.

## 3. 서버

장바구니·코스·찜 조회가 각각 `place.hidden_at IS NOT NULL`, `poi.closed_at IS NOT NULL`, `content.hidden_at IS NOT NULL` 을
그 칸으로 싣는다. 지금처럼 거르지는 않는다(담은 것은 계속 나온다).

## 3-1. 새로 담는 것은 막는다 (2026-10-15 추가, 권호)

로컬 실측에서 숨긴 촬영지도 **새로** 담을 수 있었다 — 숨긴 촬영지·작품도 상세는 열리고(§2-2), 상세의 「담기」 가 통한다.
이미 담은 것은 남기고 알리되(위), **새로 들어오는 것은 막는다.**

| 경우 | 동작 |
| --- | --- |
| 장바구니에 새로 담기(`POST /cart/items`) — 숨긴 촬영지 | 409 거절(새 오류 코드) |
| 작품 새로 찜하기(`POST /favorites/contents`) — 숨긴 작품 | 409 거절 |
| 코스 편집(`PUT /courses/{id}`)에 **새 줄**(`id` 없음)로 숨긴 촬영지·폐업 편의시설 | 409 거절 |
| 코스 편집에 **이미 있던 줄**(`id` 있음)이 숨김·폐업 | **그대로 통과** — 앱은 코스 전체를 다시 보낸다. 막으면 숨긴 장소가 하나라도 든 코스를 아무것도 못 고친다 |
| 이미 장바구니·찜에 있는 것을 다시 담기 | 지금처럼 — 장바구니는 409 `DUPLICATE_CART_ITEM`, 찜은 204. 새로 들어오는 것이 아니다 |
| 상세(`GET /places/{id}`·`GET /contents/{id}`) | `delisted` 를 실어 앱이 「담기」·「찜」 버튼을 미리 숨기거나 막게 한다. 편의시설은 폐업하면 상세가 404 라 그대로 |

오류 코드는 계약에서 정한다(예: `PLACE_DELISTED`·`CONTENT_DELISTED`·`POI_CLOSED`). 후기·마켓에서 코스를 「내 코스로 담기」 할 때
사본에 숨긴 촬영지가 있으면 어떻게 할지(빼고 담을지)는 이번 범위 밖 — 공개 글 쪽 결정과 함께.

## 4. 앱 (iOS·Android, 정승길 — MZ2AZ-458)

칸이 `true` 면 그 줄에 안내 문구와 빼기 쉬운 동선. 상세에서 `delisted` 면 담기·찜 버튼을 숨기거나 막고, 409 를 받으면 안내. 길찾기·코스 거리 계산에서 어떻게 다룰지(폐업한 곳을 건너뛸지)는 앱 쪽에서
정한다.

## 5. 검증

1. 테스트 — 명세만 본 새 컨텍스트: 숨기기 전·후, 숨김이 풀린 뒤, 폐업, 핀·남의 데이터.
2. `just check`.
3. 로컬 실측 — 로컬 DB 의 숨긴 촬영지(학암포해수욕장·섭지코지·우이빌라)를 장바구니·코스에 담아 응답을 본다.

### 결과 (2026-10-15)

- 테스트 46 개(명세만 본 새 컨텍스트) 통과 — 표시 25(`CartDelistedIntegrationTest` 7·`CourseDelistedClosedIntegrationTest` 11·
  `FavoriteDelistedIntegrationTest` 7), 막기 21(`DelistedNewItemFlowIntegrationTest`, 컨트롤러를 거쳐 상태·코드까지): 이미 있는
  것은 원래 답이 먼저, 남의 장바구니와 섞이지 않음, 뺐다 다시 넣으면 막힘, 409 면 같은 요청의 다른 편집도 반영 안 됨. 명세가 바뀌어
  기존 테스트 2 개(폐업 편의시설 새 줄 `POI_NOT_FOUND` → `POI_CLOSED`)를 맞췄다. scene-api 통합의 다른 실패 5 개는 POI 표본
  테스트(로컬 전량 POI, MZ2AZ-449).
- 로컬 실측(kind): 장바구니 — 숨긴 섭지코지 `delisted: true`·송광사 `false`(표시), 숨긴 섭지코지 새로 담기 409
  `PLACE_DELISTED`(막기). 코스 — 숨긴 촬영지·보이는 촬영지·편의시설·핀을 섞자 섭지코지만 `delisted: true`, 편의시설을 잠깐 폐업
  처리하자 `closed: true`, 숨긴 촬영지 새 줄 409 `PLACE_DELISTED`, 없는 편의시설 400 `POI_NOT_FOUND`. 찜 — 작품을 잠깐 숨기자
  `delisted: true`, 숨긴 작품 새로 찜 409 `CONTENT_DELISTED`. 상세 — 섭지코지 `delisted: true`. 바꾼 숨김·폐업은 되돌렸다.
