## 1. 다른 서비스는 어떻게 하고 있나

만들기 전에 조사했다. **결론부터 — 순수 LLM 으로 일정을 짜는 대형 서비스는 사실상 없다.**

### 해외

| 서비스 | 일정을 누가 짜나 | 배울 점 |
| --- | --- | --- |
| **Expedia** | LLM — 그리고 **AI 컨시어지(Romie)를 폐기했다** | 원인이 *"답이 실제 재고에서 떠 버린 것"*. 모델이 아니라 **데이터 결박** 문제였다 |
| **Booking.com** | LLM (최적화기 언급 없음) | 환각을 막을수록 **대화가 지루해진다**고 자사 블로그가 인정 |
| **Trip.com** | LLM | **부분 수정** + 협업 편집을 UI 로 증명 |
| **Mindtrip** | LLM + 에이전트 | 채팅으로 고치면 지도 핀·가격이 즉시 갱신 |
| **Airbnb** | **안 만들었다** | CEO 가 *"AI 여행 계획은 아직 이르다"*며 고객지원부터 함 |

두 가지가 특히 중요했다.

- **「일정 최적화기를 쓴다」고 밝힌 상용 서비스가 하나도 없다.** 순서·동선을 알고리즘으로
  푼다는 언급이 어느 1차 출처에도 없다.
- **위치 기반으로 현장에서 먼저 말 거는 서비스도 없다.** 능동 제안은 전부 날씨·결항·가격
  알림이다. MZ2AZ-201 이 요구한 그 기능은 **아직 아무도 안 한 자리**다 (우리도 아직 안 만들었다).

### 국내

| 서비스 | 구조 |
| --- | --- |
| **트리플**(놀유니버스) | **자체 알고리즘이 일정을 계산하고 GPT 는 설명만** ← 우리와 같다 |
| 마이리얼트립 | ChatGPT 를 얇게 감싼 것. 자사 DB 가 아니라 GPT 일반 지식으로 답한다 |
| 여기어때 | 숙소 검색 한정. 무결과 검색의 42% 해소, 그중 32.3% 예약 전환 |

**국내 최대 사업자가 우리와 같은 구조를 쓴다.** 설계를 방어할 때 이 사례를 든다.

### 경쟁 — K-드라마 촬영지

AI 를 쓴 성지순례 서비스는 **아직 없다.** 다만 **문체부가 2026 년 R&D 로 착수했다** —
촬영지 자동 인식 · 개인화 추천 · 경로 안내 · AR · 예약까지, 우리와 범위가 거의 겹치는
3 년 과제이고 결과물 API 20 종이 지역 기업에 무상 배포된다. **선점 창은 열려 있지만
시계는 이미 돌아간다.**

## 2. 그래서 왜 이렇게 만들었나

### 결정 ①  일정 계산에서 LLM 을 뺀다

```
①  이해 [LLM]  →  ②  계획 [알고리즘]  →  ③  설명 [LLM]
                     ↑ 여기에 모델이 없다
```

**근거** — 순수 LLM 일정의 실현 가능률이 약 **4%** 다(MIT 통제 실험, 복잡한 일정에서
GPT-4 는 0.6%). LLM+알고리즘 결합은 97%. 거리·시간 계산은 창의력이 아니라 산수라
모델에게 시킬 이유가 없다.

**얻은 것** — 실현 가능률 100% · 같은 질문에 같은 답 · **모델 없이 시험이 돈다**(99 개).

### 결정 ②  도구가 준 것 밖은 말하지 않는다

Expedia 가 죽은 자리다. 못 찾으면 **빈 목록 대신 이유**를 돌려준다.

```python
def _refuse(reason):
    return {"결과없음": reason, "할 일": "목록을 지어내지 말고 이 이유를 그대로 전해라"}
```

빈 목록을 주면 모델이 채워 넣는다. **지어낼 재료 자체를 안 주는 것**이 요점이다.

### 결정 ③  일정을 고칠 때 통째로 다시 짜지 않는다

**근거** — 부분 수정이 전체 재생성 대비 품질 차이 5% 이내, 토큰 31% 절감, 지연 31~42%
단축(arXiv 2510.04717). 게다가 여행 일정에서는 품질 외의 이유가 더 크다 — **통째로 다시
짜면 사용자가 손대지 않은 1·3일차까지 조용히 바뀐다.**

### 결정 ④  제약을 넘어도 코드가 멋대로 자르지 않는다

**근거 둘** —

- 검사 → 자동 재조정 루프는 **2 라운드에서 정점을 찍고 6 라운드에 87%→12% 로 붕괴**한다
  (arXiv 2607.17641). 오래 돌릴수록 나빠진다.
- 위반을 알릴 때 **「허용 가능한 대안」을 함께 주면 수정 성공률이 28%→72%** 로 오른다
  (arXiv 2607.14167).

그래서 넘치면 자르지 않고 **"미림분식 빼면 96분 준다"** 처럼 후보를 주고 사용자에게 묻는다.

## 3. 무엇을 만들었나

### 코스 추천 엔진 — `src/planner.py`

`plan_course(titles, days, pace)` 를 받아 5 단계를 돈다.

| 단계 | 하는 일 | 왜 |
| --- | --- | --- |
| ① 후보 점수 | 대표성(1.0)+언급량(0.6)+등급(0.4)+**작품 커버리지(0.8)** | 두 작품에 다 나오는 곳이 하루 예산을 아낀다 |
| ② 지역 좁히기 | 반경 25km 안에 가장 몰린 덩어리만 | 없으면 **2일차가 제주도 한 곳**이 된다(실측) |
| ③ 날짜 배분 | k-means, 결정적 초기화 | 하루에 도시 둘을 오가지 않게 |
| ④ 순서 | 최근접 이웃 → **2-opt** | 지도에서 X 자로 꼬인 동선을 편다 (평균 6.9% 단축) |
| ⑤ 시간표·잘라내기 | 9시 출발, 체류·이동·식사. 넘치면 **「아낀 시간 ÷ 잃는 점수」**가 큰 곳부터 | 점수만 보면 *예산을 혼자 다 먹는 한 곳*이 안 보인다 |

### 챗봇 — 도구 9 개

| 도구 | 언제 |
| --- | --- |
| `search_places` | 무엇을 찾는지 불분명할 때 |
| `list_title_places` | 작품을 콕 집었을 때 |
| `places_near` | 「이 근처」 |
| `place_detail` | 「거기 무슨 장면이야」 |
| `update_cart` | 「그거 담아줘」 |
| `draft_course` | 담은 것을 하루 동선으로 |
| `plan_course` | 작품+기간 → 일정 |
| `revise_plan` | 「2일차에서 개뿔 빼줘」 |
| `move_stop` | 「그건 1일차로 옮겨줘」 |
| `poi_nearby` | 「근처 카페」 — **편의시설**. 촬영지와 다른 표 |

도구가 부수효과를 낼 때는 **화면 지시도 함께 내보낸다** — 챗봇은 시트 안에 있고
지도·코스는 바깥에 있기 때문이다. 계약은 `schemas/effects.json`,
설계는 [design/backend-agent-contract.md](design/backend-agent-contract.md) §5.

계약은 `schemas/tools.json` **한 벌뿐**이다 — 모델에게 내미는 것과 돌아온 인자를 검증하는
것이 같은 파일이라 어긋날 수가 없다.

## 4. 실제로 돌려보고 고친 것

실제 모델·실제 데이터 주행에서 결함 두 개가 나왔다(2026-09-03).

| 결함 | 증상 | 고친 방법 |
| --- | --- | --- |
| 모델이 도구를 안 부름 | "1일차에 넣어줘" 에 상한을 스스로 계산해 **미리 거절**. 시킨 일이 실행되지 않음 | 프롬프트에 *"넘칠지 미리 재지 마라. 일단 도구를 불러라"* |
| 섞여 온 빼기가 날아감 | `remove=[A], add=[이미 있는 B]` → B 때문에 **전체 거절**, A 도 안 빠짐 | 이미 있는 것은 오류가 아니라 **이미 원하는 상태**. 건너뛰고 나머지 적용 |

둘 다 회귀 시험을 붙였다. **주행하지 않았으면 둘 다 못 찾았다.**

## 5. 안 되는 것 — 다른 분들과 맞춰야 할 자리

여기가 이 문서에서 제일 중요한 절이다.

| 안 되는 것 | 지금 상태 | 누가 |
| --- | --- | --- |
| **장바구니·일정 저장** | 파이썬 메모리에만 있다. 대화 끝나면 사라진다 | **권호님이 만든** `/cart` · `/courses` 가 이미 있다. `src/sceneapi.py` 에 쓰기 메서드가 없을 뿐 — 내가 붙이면 된다 |
| **앱↔챗봇 연결** | 없다. `web/server.py`(:8765)는 브라우저 시험용 | 창구를 백엔드에 둘지 **권호님과 상의**. 앱 쪽 호출은 승길님 |
| **영업시간** | 데이터에 없어 목적함수에 못 넣는다 | POI 파이프라인에 실리면 추가 |
| **Bazel 타깃** | `rules_python` 이 `MODULE.bazel` 에서 꺼져 있어 `BUILD.bazel` 을 못 만든다. 지금 넣으면 **팀 전체 빌드가 깨진다** | 켜는 것은 의존성 추가라 **팀 결정 사항**. 초안은 `design/build-draft.md` 에 있다 |

`region_pool` 의 **반경 25km 는 승길님 iOS `RoutePlanner` 의 실측값**을 그대로 쓴다.
두 구현이 다른 값을 쓰면 **앱과 챗봇이 서로 다른 코스를 낸다** — 한쪽을 바꾸면 알려 주세요.
