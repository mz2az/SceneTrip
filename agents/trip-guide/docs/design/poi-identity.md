# 편의시설과 촬영지 — 같은 곳, 그리고 일정 줄의 정체 (MZ2AZ-379 · MZ2AZ-382)

2026-10-13. 챗봇은 촬영지만 다루도록 만들어졌고, 편의시설(`GET /pois`)이 나중에 붙었다. 두 군데가 어긋나 있었다.

## 1. 같은 곳인 편의시설 (MZ2AZ-379)

계약 `PoiSummary.placeId` — 편의시설이 촬영지와 같은 가게·명소이면 그 촬영지 id 가 실린다(scene-api 1.7.0,
`docs/project/plans/place-poi-link.md`). 원칙은 「같은 곳이면 어디서든 촬영지가 대표한다」.

### 고치기 전 (실제 모델, 가짜 창구 — 촬영지 「수원 카페 몽테드」 45 · 편의시설 「몽테드」 `placeId: 45`)

| 물음 | 본 것 |
| --- | --- |
| 「그 해 우리는 촬영지 알려줘」 → 「근처 카페도 알려줘」 | 방금 소개한 촬영지를 「1. 몽테드 – 카페」 로 새 장소처럼 다시 소개(2 회 중 2 회) |
| 「몽테드 담아 줘」 | 2 회 중 1 회 「그런 촬영지가 없어 담을 수 없다」 — 모델이 이름을 촬영지 이름으로 바꿔 넣었을 때만 담겼다 |
| 응답의 `places` | 편의시설 줄에 `placeId` 가 없다 — 앱이 촬영지 상세로 보낼 수 없다 |

### 고친 것

| 어디 | 무엇 |
| --- | --- |
| `src/tools.py` `_linked_place` | 편의시설 줄의 `placeId` 가 가리키는 촬영지를 찾는다 — 이번 대화에서 보여 준 것 먼저, 없으면 그 자리 곁 150 m 의 촬영지 중 id 가 같은 것. **이름으로 맞추지 않는다.** 못 찾으면 연결되지 않은 줄로 다룬다 |
| `poi_nearby` | 연결된 줄은 「이름」 자리에 **촬영지 이름**을 두고 「편의시설 이름」·「촬영지이기도 하다」(작품) 를 붙인다. 그 촬영지를 보여 준 장소에 넣는다 |
| `update_cart` | 보여 준 편의시설의 이름이면 그 줄부터 본다 — 연결돼 있으면 그 촬영지로 `cart.add`, 아니면 「편의시설이라 담지 못한다」 |
| `web/server.py` | 응답 `places` 의 편의시설 줄에 `placeId` 를 싣는다(scene-api 는 이 목록을 그대로 넘긴다) |
| `prompts/system.txt` 3 장 | 「같은 곳이면 촬영지 이름으로 소개한다」 |

도구 결과의 모양은 한 번 바꿨다. 처음에는 편의시설 이름을 앞에 두고 「같은 곳인 촬영지」 를 덧붙였는데, 모델이 그 딱지를
그대로 옮겨 적었다(「같은 곳인 촬영지: 수원 카페 몽테드」). 「이름」 자리에 촬영지 이름을 두니 사라졌다.

### 고친 뒤 (같은 대화 5 회)

- 「근처 카페도 알려줘」 — 5 회 모두 「수원 카페 몽테드 … ‘그 해 우리는’ 촬영지이기도 합니다」 로 한 번만.
- 「몽테드 담아 줘」 — 5 회 모두 `cart.add` `placeId: 45`. 모델이 「몽테드」 로 넣든 「수원 카페 몽테드」 로 넣든 같다.

## 2. 일정 줄의 정체 (MZ2AZ-382)

코스 항목은 세 갈래다 — 촬영지(`placeId`)·편의시설(`poiId`)·직접 찍은 핀(`customPinId`). `GuidePlanStop` 에는
`placeId` 뿐이었다.

### 고치기 전 (실제 모델, 다섯 줄짜리 일정에 「1일차에서 수원 방화수류정 빼 줘」)

| 보낸 줄 | 돌려준 줄 |
| --- | --- |
| 행궁다방 `poiId: 9002` | `placeId`·`poiId` 모두 없음 — 앱에서 「저장 안 됨」 |
| 우리 숙소 `customPinId: 7` | 없음 — 「저장 안 됨」 |
| 수원 카페 몽테드 `poiId: 9001`, `placeId: null` | **`placeId: 45`** — 이름이 같은 촬영지의 id 를 대신 넣었다 |

셋째 줄이 더 나쁘다. `plan_from_api` 가 `placeId` 없는 줄을 이름으로 찾아 그 촬영지의 id 를 넣고 있었다 — 계약은
「없으면 null 이고 이름으로 대체하지 않는다」 고 적어 두었는데 되읽는 쪽이 어겼다.

### 고친 것

| 어디 | 무엇 |
| --- | --- |
| `schemas/effects.json` (에이전트 쪽 사본) | `poiId`·`customPinId` (int64, nullable) |
| `src/places.py` `Place` | `poi_id`·`custom_pin_id` |
| `src/planner.py` `plan_from_api` | 받은 정체를 그대로 든다. `placeId` 없는 줄에 이름으로 찾은 id 를 넣지 않는다. 촬영지 자료(장면·등급)는 `placeId` 가 있고 그 id 가 같을 때만 붙인다 |
| `src/planner.py` `plan_to_api` | 두 칸을 그대로 내보낸다(촬영지 줄은 null) |
| `src/tools.py` `revise_plan` | 고친 일정에서 촬영지인 줄만 「보여 준 장소」 에 넣는다 |

고친 뒤 같은 물음 — 행궁다방 `poiId: 9002`, 수원 카페 몽테드 `poiId: 9001`(`placeId` null), 우리 숙소 `customPinId: 7`.

### 아직 앱까지 닿지 않는다

**계약은 아직 고치지 않았다.** `contracts/openapi/scene-api-v1.yaml` 의 `GuidePlanStop` 과
`contracts/schemas/guide/effects.schema.json` 에 두 칸이 없어, scene-api 가 생성된 모델로 받아 넘기면서 두 칸을
버린다 — 계약 담당(권호)의 몫이다. **앱도 아직 두 칸을 보내지도 읽지도
않는다**(iOS `RouteGuidePlan.swift`·`RouteBridge`, Android 같은 자리) — 계약과 앱이 맞출 때까지 화면의 「저장 안 됨」 은 그대로다.
그 사이에 달라지는 것은 하나다: 편의시설 줄이 이름이 같은 촬영지로 바뀌어 저장되는 일은 이제 없다.

## 띄운 서버로 본 것 (2026-10-13)

로컬 클러스터의 scene-api(`place_poi_link` 31 건)에 에이전트(`:8899`)를 붙여 `POST /guide/chat` 을 보냈다.
촬영지 「채석장전망대 카페낙타」(289) ↔ 편의시설 「카페낙타」(406686).

| 물음 | 결과 |
| --- | --- |
| 촬영지 소개 뒤 「근처 카페도 알려줘」 | 4 회 중 4 회 촬영지 이름으로 한 번, 응답 편의시설 줄에 `placeId: 289` |
| 「카페낙타 담아 줘」 | 5 회 중 5 회 `cart.add placeId 289` |
| 「테르트르 담아 줘」(연결 없음) | 2 회 중 2 회 편의시설이라 못 담는다고 안내, effects 없음 |
| 일정에 `poiId`·`customPinId` 줄을 넣어 「방화수류정 빼 줘」 | 433299·406686·7 그대로 |
| 같은 일정을 번호 없이(지금 앱이 보내는 모양) | 번호 없는 줄은 null 그대로 — 이름이 같은 촬영지 289 로 바뀌지 않는다 |
| `POST /v1/guide/plan` (scene-api 경유) | 200. 정지점에 `poiId`·`customPinId` 가 없다 — 계약에 칸이 없어 서버가 버린다 |

처음 묻는 대화에서는 같은 곳이 응답 `places` 에 촬영지 줄과 편의시설 줄로 두 번 실렸다 → `web/server.py` 가 편의시설
줄(`placeId` 있음) 하나만 남긴다.

## 재지 못한 것

- 앱 화면에서의 확인. `/v1/guide/chat` 은 가입한 사용자만 부를 수 있어 에이전트에 직접 보냈다.

- 일본어·영어 물음에서의 「같은 곳」 소개.
- 답에 `*…*` 기울임 기호가 한 번 남았다(5 회 중 1 회) — `plain_text` 는 `**` 만 걷는다.
