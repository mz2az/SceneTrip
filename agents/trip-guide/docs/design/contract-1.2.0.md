## 1. 왜 정본이 둘이면 안 되는가

에이전트의 메모리 목록 하나가 **번호 핀**으로도 **장바구니**로도 쓰였다. 앱에는
그 둘이 따로 있다.

| | 장바구니 | 코스 정지점 |
| --- | --- | --- |
| 무엇 | 검색 탭 ➕ 로 모은 것, 순서 없음 | 일차별 순서, 지도의 번호 핀 |
| 정본 | DB `cart_item` | 편집 중 앱 / 저장 뒤 DB |
| 에이전트에 오나 | **안 온다** | `context.stops` 로 **매 턴 온다** |

그래서 두 가지가 깨져 있었다.

```
지도:  📍1 서울중앙고  📍2 북촌  📍3 경복궁
사용자: 「2번 근처 카페 있어?」
   → 우리 목록의 2번(덕수궁) 주변을 찾아 주고 그것을 「2번 주변」이라 부른다
```

```
사용자: 앱에서 ➕ 로 5곳 담음  →  DB 에 저장
사용자: 「담은 걸로 동선 짜 줘」
   → 우리 목록은 비어 있다 → 「담은 곳이 없다」
```

뒤쪽은 **앱이 장바구니를 안 보내므로 동작한 적이 없다.** 마법사(`POST /guide/plan`)와
겹치기도 해서 도구째 뺐다. 계약 도구 목록에서도 이미 빠져 있다(10 → 9).

되살리려면 `context.cart` 를 계약에 더하고 scene-api 가 DB 에서 채우면 된다.

### 번호는 몇 번째가 아니다

`context.stops[i]` 가 아니라 `stop.number` 로 찾는다. 다녀온 곳을 접어 두면 화면에
1·3 만 남는데, 그때 3 번은 목록의 **두 번째**다. 몇 번째로 세면 여기서 어긋난다
(`tests/test_contract_120.py`).

### 「담았다」고 단정하지 않는다

목록을 모르므로 이미 담겨 있었는지도 모른다. 도구는 「담으라고 요청했다」만
돌려주고, 프롬프트가 **담긴 목록을 읊지 말라**고 못 박는다 — 읊으면 그것은
지어낸 것이다.

## 2. 편의시설이 지도에 안 찍히던 것

```
「근처 카페 알려줘」
  → 답: "스타벅스 한국프레스센터점이 있어요"   ✅
  → places: []                                ❌ 핀이 없다
```

`poi_nearby` 가 `map.focus` 만 내보내고 응답 목록에는 안 실었다. 이제 싣되
**촬영지와 섞지 않는다** — 두 표는 id 가 따로 매겨져 있어 같은 숫자가 다른 곳을
가리킨다. 항목마다 `source: "place" | "poi"` 를 붙인다(계약 `GuidePlace`).

이름 지목(`find_shown`)에는 편의시설을 넣지 않는다. 넣으면 「그거 담아 줘」가 카페를
코스 항목으로 담고, 그 id 는 다른 촬영지를 가리킨다.

## 3. 시간 예산 — 안쪽이 먼저 포기해야 한다

```
       앱 50초  >  scene-api 40초  >  에이전트 30초
```

예전에는 「모델 호출 하나 60 초」뿐이라 **턴 전체에는 상한이 없었다.** 도구를 네 번
부르면 모델 호출이 다섯 번이다. 앱이 이미 끊은 뒤에도 우리는 계속 모델을 불렀다.

이제 턴 시작에 마감을 정하고(`turn_budget_seconds: 30`) 호출마다 남은 시간만
준다. 재시도 대기도 예산 안에서만 한다. 넘기면 `503 GUIDE_UNAVAILABLE`.

값은 실제 모델로 턴 시간 p95 를 재서 그 1.5~2 배로 고친다. 전부 `config/model.json`.

## 4. 세션 만료

이 서버가 요청 사이에 들고 있는 것은 이제 **대화 이력과 「보여 준 장소」뿐**이다.
일정·번호·장바구니는 전부 앱이 매 요청에 보내 준다.

그런데 앱은 챗봇 시트를 열 때마다 **새 sessionId** 를 만들고, 우리는 지운 적이
없었다. 하루 100 명이 다섯 번씩 열면 500 개가 남고 그중 쓰이는 것은 없다.
마지막 요청에서 30 분 지난 세션을 버린다(`Desk._sweep`).

## 5. 경계의 이름

백엔드는 프록시라 **옮겨 담지 않는다.** 여기서 나간 이름이 그대로 앱까지 간다.

| 무엇 | 전 | 후 |
| --- | --- | --- |
| 거리 기준 | `"straight_line"` | `"straight-line"` (계약 `TravelBasis`) |
| 도구 인자 | `radius_m` · `to_day` | `radiusMeters` · `toDay` — **응답에 실을 때만** |
| `/plan` 오류 | `{"error": …}` | `{"code": "INVALID_PARAMETER", "message": …}` |
| `/plan` 출발점 | `start: [위도, 경도]` | `latitude` · `longitude` |

인자 이름은 **응답에서만** 바꾼다. 모델과 주고받는 `schemas/tools.json` 은 그대로다 —
계약이 정하는 것은 밖으로 나가는 이름뿐이고, 안쪽 이름을 따라 바꾸면 프롬프트와
시험까지 함께 흔들린다.

출발점을 배열에서 필드 둘로 바꾼 이유는 형만으로는 순서를 못 지키기 때문이다.
위경도를 뒤집어 보내도 배열은 통과하고, 그러면 인천 코스가 몽골에 생긴다.

## 7. 남은 것

- **대화 이력도 앱이 보낸다.** 계약 `messages` 에 「서버는 이력을 저장하지 않는다」고
  적혀 있는데 우리는 아직 `self.history` 를 쓴다. 권호님 8 개 항목에는 없어 이번에는
  손대지 않았다 — 같이 할지 확인이 필요하다.
- **「보여 준 장소」만 계약에 칸이 없다.** 이것까지 `context` 로 오면 세션이 아예
  없어지고 §4 도 필요 없어진다.
