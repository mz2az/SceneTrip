# scene-api 시드 데이터

`just seed` 가 읽는 것들. 스키마는 Flyway 가 만들고(`src/main/resources/db/migration/`),
데이터는 여기서 온다.

| 파일 | 내용 |
| --- | --- |
| `v6.csv` | V6 수집분 **전량 164 행** — 정예 4 작품(도깨비·눈물의 여왕·케이팝 데몬 헌터스·이태원 클라쓰), 장소 155 곳. 볼트 `01_Raw/정승길/(1주차)data/result/촬영지_TOP_v6_정예4작품.csv` 의 스냅샷(BOM 만 뗐다) |
| `v6.sql` | CSV 를 14 개 테이블로 옮기는 변환. 어느 CSV 에도 같이 쓴다 |

```bash
just seed                          # 저장소의 기준 데이터 164 행 (stack-up 도 이것을 넣는다)
just seed <CSV 경로>               # 다른 판을 넣을 때
```

## 왜 전량이 저장소에 있나 (ADR 0009)

**저장소만 클론하면 팀 전원이 같은 화면을 봐야 한다.** 2026-09-01 까지는 표본 12 행만
두고 전량은 볼트에서 받게 했는데, 볼트 경로를 모르는 팀원은 작품 4 · 장소 10 인 화면을
보고 "데이터가 왜 적나" 부터 물었다. 4 작품으로 확정된 지금 전량은 150 KB 라 저장소에
두는 비용이 없다. 수집 산출물의 **정본은 여전히 볼트**고, 여기 있는 것은 스냅샷이다 —
볼트의 CSV 가 바뀌면 이 파일을 갈아 끼우고 같은 커밋에 적는다.

## 이 데이터로 검증되는 것

| 들어 있는 것 | 검증하는 것 |
| --- | --- |
| 4 작품 전부 | `category` 가 `drama` 와 `movie` 둘 다 나온다 |
| 도깨비 | `도깨비`·`Goblin` 다국어 검색 |
| 케이팝 데몬 헌터스 | 별칭 5 개(`케데헌`·`KPDH`…)와 `movie` 카테고리 |
| 북촌한옥마을 · 일월수목원 | **한 장소가 두 작품에 겹친다** — N:M 이 실제로 동작하는지 |

## 적재는 지우고 다시 넣는다

`v6.sql` 의 첫 동작이 `TRUNCATE` 다. `content` 와 `person` 에는 자연키가 없어 — 같은
작품을 두 번 넣어도 DB 는 그것이 같은 작품인지 알 방법이 없다 — `ON CONFLICT` 로는
멱등을 만들 수 없다. 로컬 개발 DB 의 기준 데이터라서 성립하는 방식이고,
`seed.sh` 가 kind 컨텍스트가 아니면 실행을 거부한다.

## 정제 전이라 감수한 것

| 무엇 | 지금 |
| --- | --- |
| 같은 장소의 `place_type` 이 행마다 다름 | 일월수목원이 `자연`·`공원` 둘로 수집됐다. `ORDER BY` 로 어느 행이 이기는지 고정만 해 뒀다 |
| `place_type` 이 한국어 라벨 37 종 | 코드 매핑표가 아직 없다. 값 그대로 넣는다 |
| 장소 이름·주소가 한국어뿐 | `place_i18n` 에 `ko` 만 있다. 영어 사용자도 장소명은 한국어로 본다 |
| `place_i18n.description` 이 비어 있음 | CSV 의 `scene_description` 은 "이 작품의 이 장면" 설명이라 장소 자체의 설명이 아니다 |
| `place_alias` 가 비어 있음 | CSV 에 장소 별칭 컬럼이 없다 |
| `popularity_score` 가 임의값 | `famous_rank` 를 뒤집은 값. `user_event` 가 쌓이면 배치가 계산한다 |
