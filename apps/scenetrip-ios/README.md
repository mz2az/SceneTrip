# scenetrip-ios

> 모듈 종류: `app` · 언어: `swift` · 경로: `apps/scenetrip-ios`

## 목적

사용법 네 장은 첫 실행의 언어 선택을 따른다. 현재 AI 생성의 방문 수를 고정 수로
약속하지 않고 초안을 편집할 수 있음을 설명한다. 이전·다음·건너뛰기·완료는 실제
페이지 범위를 지키며 완료는 한 번만 기록한다. 작은 화면·큰 글자에서는 본문을
스크롤하고 하단 버튼은 본문과 분리한다. 그림·순서는 기존 시안을 유지한다
([MZ2AZ-399 계획](../../docs/project/plans/onboarding-refresh.md)).

SceneTrip 의 iOS 네이티브 앱. 탭은 셋 — 작품검색 · **홈**(첫 화면) · 커뮤니티 — 이고 경로여정·마이페이지는 홈이 띄우는 전체 화면 덮개다(계획 `docs/project/plans/mobile-home-tab.md`, main 이식 2026-09-05). **작품검색 탭**(지도 + 바텀시트 + 검색)을
만든다 — 화면 구조·검색 규칙의 기준은
[검색 탭 네이티브 구현 계획](../../docs/project/plans/mobile-native-search-tab.md) §3 이다.

현재 구현된 동선:

- 검색 자동완성의 장소 행은 `장소 종류 · 대표 작품`을 표시한다(MZ2AZ-450, 계약 1.17.0 이상).
  종류는 기존 `PlaceType`의 한국어·영어 표시말을 쓰고 작품명은 서버 응답을 그대로 쓴다.
  둘 중 있는 항목만 표시하며 둘 다 없으면 기존 주소(`subtitle`)를 표시한다.
- 장바구니·내 코스·찜한 작품은 목록에서 빠진 촬영지·작품과 폐업한 편의시설을 지우지 않고
  안내와 빼기 버튼을 표시한다(MZ2AZ-458). 상세에서는 새 담기·찜을 막고 기존 항목 빼기는 허용한다.
  화면이 열린 사이 바뀐 상태의 409는 종류별 한국어·영어 안내를 보이며, 코스 저장이 거절돼도
  편집 내용과 기존 행 ID를 유지한다. 숨김·폐업 행은 다음 목적지·시작 안내·거리·계획선·동선 최적화에서
  건너뛰고 직접 누르면 안내와 정보를 보되 길찾기는 제공하지 않는다. 기존 이동 포함 시간은 숨기고
  방문 가능한 곳의 머무는 시간만 표시한다. AI 순서·일차 편집 뒤에도 이 상태를 유지한다.
  마이페이지 장바구니에서도 같은 행으로 안내·빼기를 제공하며 개수를 함께 갱신한다.
  선택한 일차에 숨김·폐업인 곳만 남으면 방문 완료와 구별해 알리고 코스를 시작하지 않는다
  ([구현 계획](../../docs/project/plans/ios-delisted-items.md)).
- 마이페이지 「약관 및 정책」 절과 로그인 시트의 동의 안내가 개인정보 처리방침·이용약관을 Safari로 연다.
  주소는 `src/Models/LegalLinks.swift` 한 곳에 둔다. 2026-10-15 기준 `https://scenetrip.io/privacy`는
  한국어 초안만 게시돼 있고 영어판 주소는 없으며, `https://scenetrip.io/terms`는 **404**다 — 출시 전에
  게시해야 한다(MZ2AZ-455, 게시는 MZ2AZ-437·418).

- 커뮤니티는 서버 후기와 이 기기에만 보관한 옛 글을 함께 보여 준다. 옛 글의 사진·첨부
  코스는 보존하며 서버에 자동 공개하지 않는다. 지역별 추천 가이드 20개는 같은 지역의
  1일 코스와 사진을 붙여 제공한다([MZ2AZ-423](../../docs/project/plans/community-regional-guides.md)).
- 코스 편집·여행 지도의 주변 편의시설은 각자의 실제 좌표에 개별 핀으로 표시한다.
  클러스터링·묶음 목록·격자 배치는 제거했다. 같은 좌표의 핀은 겹칠 수 있으며,
  겹침 UX는 [MZ2AZ-447](https://mz2az.atlassian.net/browse/MZ2AZ-447) 추후 보강으로 보류한다.
  기존 분류 필터·30건 조회 제한·상세 카드·코스 담기는 유지한다.
- 촬영지 상세의 장면 카드는 `sceneImageUrls`의 첫 장과 사진 수를 표시한다. 주소가 없거나 다운로드에 실패하면 카드의
  이미지 영역을 비워 두며 포스터로 대체하지 않는다(MZ2AZ-394). 실제 사진을 누르면 전체 화면에서
  원래 비율로 열고, 두 손가락·두 번 누르기·버튼으로 100~400% 확대·이동한다. 전체 화면의 다운로드
  실패는 안내와 수동 재시도를 제공한다. 여러 장은 이전·다음 버튼으로 서버 순서대로 넘기며
  전환할 때 확대를 100%로 되돌린다. 설명은 별도 시트에서 읽는다(MZ2AZ-420·430,
  [구현 계획](../../docs/project/plans/ios-scene-gallery.md)).
- 작품 상세의 포스터는 서버 `producerUrl`이 유효한 HTTP(S) 주소일 때 제작사 페이지로 연결된다.
  홈·작품 목록의 포스터는 기존 작품 선택 동작을 유지한다(MZ2AZ-392).
- 커뮤니티 상세는 대표 사진 한 장과 본문 문단 사이의 사진을 표시한다. 작성자는 사진별
  삽입 문단·설명·출처·AI 변환 표시를 정하고 미리보기에서 확인한다. 순서는 `bodyBlocks`로
  서버에 저장하며 옛 글은 기존 본문·사진을 다시 쓰지 않고 배치한다. 사진은 전체 화면에서
  100~400% 확대한다([MZ2AZ-428](../../docs/project/plans/community-blog.md)).
- 포스터는 홈·목록·자동완성·작품 상세의 고정 칸을 중심 정렬로 채운다. 비율이 다른 원본은
  가장자리가 잘릴 수 있으며 관광공사 장소 사진의 전체 비율 표시는 그대로다(MZ2AZ-431).
- 닉네임 정하기·변경은 이름 미리보기·글자 수·지우기·하단 저장/취소를 제공한다. 본문은
  스크롤하고 접근성 글자 크기에서는 큰 시트로 시작한다. 저장 중에는 입력·닫기를 잠그며,
  요청 중 계정이 바뀌거나 다른 회원의 응답이면 계정 상태와 질문 이력을 바꾸지 않는다(MZ2AZ-431).
- 홈 「지금 뜨는 작품」은 서버 인기순 첫 20편을 그대로 표시한다. 전체 목록을 훑거나 촬영지 수로
  다시 정렬하지 않는다(MZ2AZ-411). 작품 상세에서 담은 촬영지는 작품 출처도 함께 저장한다(MZ2AZ-262).
- 홈 「오늘의 성지」 사진 버튼의 터치 영역은 표시 높이로 제한한다. 잘린 원본 이미지가
  위의 작품 포스터 선택·가로 넘기기를 가로채지 않는다(MZ2AZ-431).
- 방문 기록은 서버 저장 성공 뒤에만 다녀옴으로 표시한다. 저장 중·실패·수동 재시도는 안내 화면과
  일정 행에 함께 표시해 안내를 닫아도 다시 저장할 수 있다(MZ2AZ-225).
- 지도 핀은 **번호 박힌 그라데이션 핀**(파스텔 하늘→보라, 흰 배지에 컬러 번호)이고,
  시트의 장소 목록이 같은 배열을 같은 순서로 그리므로 행 번호가 곧 핀 번호다
  (`NaverMapView.PinImage` — 색은 `light`/`deep` 상수 두 줄로 바꾼다).
- 장소를 고르면(목록 행·핀) 카메라가 그 장소로 **확대**되고, 검색을 확정하면 결과
  도착 시점에 결과 전체 범위로 fit 된다 — 확정 즉시 fit 하면 직전 결과에 맞는다(실측).
- 작품을 고르면 **작품 상세**(포스터·출연·별칭·촬영지 목록)로 드릴다운한다. 검색
  상태는 건드리지 않으므로 뒤로 가면 고르기 전 화면 그대로다.
- 자동완성은 검색창 바로 아래 붙는 드롭다운이고, 뜨는 동안 지도는 스크림으로
  덮인다(밖을 누르면 닫힘). 첫 작품은 포스터 카드로(누르면 작품 상세로 직행),
  장소는 장소 절로, 전체를 연관 검색어 칩으로 배치한다. 별칭으로 걸리면
  (`matchedTerm`) 그 표기를 배지로 보여 준다. **장소 제안을 누르면 장소 탭으로
  넘어가 그 장소를 바로 선택·확대한다** — 검색어 커밋만 하고 작품 탭에 남아
  있으면 고른 것과 무관한 작품이 보인다.

Flutter 프로토타입(`~/workspace/mobile`, 저장소 밖)이 화면 동작의 대조군이다 —
코드는 옮기지 않고 규칙만 가져온다 (ADR 0002).

## main 은 계약만 부른다 (MZ2AZ-297, 2026-09-02)

관광공사 공식 사진은 대표·카드·격자에서도 전체 비율로 보이고, API의 `credit`를 사진 바깥에
원문 그대로 적는다(MZ2AZ-385). 검색의 공개 관광공사 원본은 기존 `PhotoLoader`의 360px
표시용 디코딩을 재사용한다. 원본 파일과 일반 포스터·서명 리뷰의 캐시 정책은 변경하지 않는다.
구현·검증 범위는 [관광공사 사진 표시 계획](../../docs/project/plans/tour-photo-display.md)을 따른다.

### 관광공사 편의시설 안내 (MZ2AZ-470)

편의시설 상세 카드의 `info`에 값이 있는 개요·이용 시간·쉬는 날·주차·대표 메뉴·입장료만
표시한다. `info`와 개별 필드는 누락·null 모두 숨기며, 긴 안내는 카드 안에서 스크롤한다.
서버의 문장과 줄바꿈을 유지하고 영업 중 여부를 계산하지 않는다. 각 필드의 실제 언어가 앱 언어와
다르면 작은 언어 태그를 붙인다. 기존 앱에는 시스템 번역 패턴이 없어 태그만 제공한다.
홈페이지는 HTTP(S) 주소만 브라우저로 연다. 행 제목·태그·출처는 KO/EN 문자열 표를 따른다.

사진 줄·격자는 `thumbnailUrl`을 우선 사용하고 없으면 `url`로 폴백한다. 상세 대표·확대 화면은
원본 `url`을 쓴다. `kogl_type1`·`kogl_type3` 사진에는 앱 언어에 맞춰 「출처: 한국관광공사」 /
“Source: Korea Tourism Organization”을 사진 밖에 표시하며 추가 credit도 보존한다. Type3는
자르기·필터·문구 덮기 없이 전체 비율로 보이고 확대 화면의 조작도 사진 밖에 둔다.
규칙은 `RouteTab/PoiInfoRules.swift`·`Reviews/PhotoGalleryRules.swift`,
계획과 인계 검증은 [iOS 관광공사 안내 계획](../../docs/project/plans/ios-poi-tour-info.md)에 있다.

촬영지 상세·지도 카드와 편의시설 카드의 네이버 버튼은 `NaverMapLink.place` 로 주소를 검사한다
(MZ2AZ-374·383). `https`, 포트·사용자정보 없음, `naver.com`·그 하위 도메인 또는 `naver.me` 만 허용한다.
없거나 검사에 실패한 주소는 버튼을 숨긴다.

길찾기에서 연결이 끊기거나 서버에 닿지 못하면 한국어·영어로 인터넷 연결 확인과
잠시 뒤 재시도를 안내한다(MZ2AZ-366). 개발 서버 이름·포트는 화면에 표시하지 않는다.

**main 의 프론트는 백엔드 계약(`contracts/openapi/scene-api-v1.yaml`)에만
의존한다.** 백엔드가 없는 기능은 되는 척하지 않고 「준비 중」으로 표시된다 —
그 빈 화면이 곧 백엔드가 채울 자리다. 프론트 자체 시험용 직접 연결(카카오
직접 호출·프로토타입 :8899·로컬 LLM :8900)은 전부 **navi-proto 브랜치**에만
있다. 데모·발표는 navi-proto 빌드로 한다.

## 다른 맥에서 돌리기 — 백엔드 담당용 (MZ2AZ-288)

프론트는 전부 main 에 있다. 이 절의 목적은 **백엔드 담당이 앱을 직접 돌려
「어떤 API 가 비어 있는지」를 화면으로 보는 것**이다 — 빈 자리의 명세는 볼트
문서 [백엔드 부탁 목록](https://github.com/kyjii900098/mz2az/blob/main/01_Raw/Project/%EB%B0%B1%EC%97%94%EB%93%9C%20%EB%B6%80%ED%83%81%20%EB%AA%A9%EB%A1%9D%20%E2%80%94%20%EB%A1%9C%EC%BB%AC%20%EC%9E%84%EC%8B%9C%20%EA%B5%AC%ED%98%84%20%EC%A0%95%EB%A6%AC.md)
에 정리돼 있다.

### 절차

1. **준비물** — macOS + 정식 Xcode(시뮬레이터 포함), `brew install just bazelisk`.
   (`swiftformat`·`swiftlint` 는 `just check` 를 돌릴 때만 필요하다.)
2. **키** — 저장소 루트에 `.env` 를 만든다. **값은 팀 채널로 승길에게 받는다 —
   깃에 올리지 않는다.**
   ```
   NAVER_MAP_CLIENT_ID=<네이버 지도 키>
   KAKAO_REST_KEY=<카카오 REST 키>
   ```
3. **백엔드** — 앱은 `http://localhost:8081/v1` 을 부른다. 로컬 클러스터를
   띄워 둔다(`just cluster-up`, MZ2AZ-157 구성 그대로).
4. **실행** — `just ios-run`.
   원격 서버로 붙이려면 `just ios-run-cloud https://api-dev.scenetrip.io/v1`(DEV) · `just ios-run-cloud https://api.scenetrip.io/v1`(PRD).
   서버를 바꾸면 토큰이 맞지 않아 다시 로그인해야 한다.

### 이 기기의 기록 지우기 (MZ2AZ-471)

비회원 마이페이지에 「이 기기의 기록 지우기」가 표시된다. 확인 뒤 설치 UUID만 보내
기록을 삭제하며, 가입자에게는 기존 「회원 탈퇴」를 표시한다. 204 성공에서만 장바구니·코스·
방문 스탬프·찜의 화면 사본과 저장된 찜 ID를 비운다. 기존 탈퇴와 같이 기기 발자취를 지우고
발자취 기록 동의·지도 표시도 끈다. 설치 UUID는 유지하며 로그인·로그아웃을 수행하지 않는다.

기기 데이터를 보존한다. 삭제 전 조회가 늦게 도착해도 지운 사본을 되살리지 않는다.

**선행 조건:** scene-api 1.22.0과 해당 계약에서 생성한 Swift 클라이언트의 선택적
`deleteMe(xInstallId:)` 인자가 필요하다. 작업 시작 시 이 브랜치의 계약은 1.21.0이었다.
[구현·검증 계획](../../docs/project/plans/ios-delete-device-data.md)을 따른다.

### AI 기능 사용 동의 (MZ2AZ-468)

첫 가이드 질문(재시도 포함) 또는 AI 코스 생성 직전에 「AI 기능 사용 안내」를 표시한다.
입력·대화·관심 작품·여행 조건·코스 맥락을 Amazon Bedrock(AWS) 미국 오리건으로
보낸다는 안내와 이름·이메일 제외, 답변 오류 가능성, 개인정보 처리방침 링크를 제공한다.
「허용하고 계속」으로 두 기능에 함께 동의하며, 취소하거나 시트를 내려 닫으면 질문과
마법사 선택값은 그대로 남는다. 앱 시작이나 가이드 창을 여는 것만으로는 묻지 않는다.

AI·위치 동의 시트는 본문과 하단의 전체 너비 세로 버튼 높이를 측정해 240~480pt 범위로
열린다. 측정 전에는 중간 높이를 쓰며, 언어·글자 크기로 내용 높이가 바뀌면 시트 높이도
갱신한다. 긴 내용·큰 글자는 버튼까지 함께 스크롤하거나 시트를 크게 펼쳐 읽을 수 있다.

마이페이지 「이용 통계 수집」 바로 아래의 「AI 기능 사용」을 끄면 철회된다.
다음 AI 사용 또는 설정에서 다시 켤 때 같은 안내를 확인한다. 다른 앱 기능은 그대로다.
동의 버전을 UserDefaults에 저장하며 안내 버전이 바뀌면 다시 묻는다.
생성 클라이언트의 `RetryingSession`도 두 AI 창구의 매 전송 전에 검사하므로 UI를
거치지 않는 호출·인증 재전송·자동 재시도 역시 미동의 상태에서 나가지 않는다.
이미 전송한 요청을 철회하거나 서버에서 지우는 기능은 아니다.
[구현·검증 계획](../../docs/project/plans/ios-ai-consent.md)을 따른다.

### 위치기반서비스 이용 동의 (MZ2AZ-472)

「직접 짜기」의 「코스 만들기」는 빈 초안을 편집 화면에 연다. 실제 저장은 편집 완료 때
`POST /courses` → `PUT /courses/{id}`로 수행하며 AI·위치 동의 없이 이용할 수 있다.
`CourseCreate`에는 기기 좌표 필드가 없다. AI 초안의 `POST /guide/plan`은 AI 동의가 필요하고,
위치 동의가 없으면 선택 좌표만 제거해 전송한다. 편집 화면의 저장 실패 경고는 저장·여행 상태
변경 실패에만 표시하며 이전 목록·재료 조회 실패나 저장 뒤 재조회 실패로 표시하지 않는다.

기존 코스는 상세 조회에 성공해야 편집 화면을 연다. 실패하면 코스 목록에
「코스를 불러오지 못했어요」와 「다시 시도」를 표시하며 실패한 코스만 다시 조회한다.
서버 ID가 있어도 상세를 받지 않은 사본은 저장 버튼과 공용 저장 경로에서 차단한다.

시스템 위치 권한과 별개로 첫 좌표 전송 전에 위치 서비스 동의를 받는다. 주변 검색·AI 가이드·
길안내 목적, 요청 처리 뒤 삭제, 길안내 시 카카오 제공을 설명하고 위치 약관으로 연결한다.
마이페이지 「AI 기능 사용」 옆의 「위치기반서비스 이용」을 끄면 철회하며 다음 사용 때 다시 묻는다.
버전은 UserDefaults에 저장한다. AI 동의와 저장·시트 흐름을 공유하지만 허용 상태는 독립적이다.

기기 좌표를 쓰는 가이드 질문·재시도와 두 길안내 경로는 미동의 시 보내지 않는다. AI 코스 만들기는 동의를
취소해도 위치 없이 계속한다. `RetryingSession`은 인증 재전송·자동 재시도·실제 resume 직전에도
검사해 필수 기기 좌표 요청을 차단하고 선택 좌표는 제거한다. GPS로 이동하거나 내 위치를 포함해
자동 맞춘 지도 범위의 촬영지·편의시설 검색도 전송 전에 동의를 받으며 취소하면 보내지 않는다.
지도를 손으로 이동·확대하거나 검색 결과를 선택하면 사용자 선택 영역으로 바뀐다. 이 영역과
목적지 기준 AI 질문은 위치 동의 없이 이용하며 AI 기능 동의는 계속 필요하다. 질문 재시도와
촬영지 이어 받기도 최초 좌표 출처를 유지한다. 파란 점·기기 내 방문 판정·발자취는 그대로 쓴다.
외부 지도 앱에는 목적지만 넘기며 기기 좌표는 URL에 넣지 않는다.

길안내 성공 때 카카오 제공 알림을 4초 표시한다. 시작·다음 목적지·수동 재시도마다 한 번이고,
GPS 관찰은 이미 받은 경로를 다시 요청하지 않는다. 자동 재탐색 폴링은 현재 없다.
요청 중 목적지를 바꾸면 이전 응답은 버리고, 요청이 끝나는 즉시 최신 목적지로 다시 묻는다.
철회는 이후 좌표 전송을 막으며 이미 보낸 요청이나 서버 확인기록의 삭제를 수행하지 않는다.
[구현·검증 계획](../../docs/project/plans/ios-location-consent.md)을 따른다.

### 계정 전환과 사진 주소 갱신 (MZ2AZ-363·366·428·431)

로그인 갱신은 같은 세션의 요청끼리 공유한다. 로그아웃·다른 계정 로그인 뒤 도착한
이전 갱신 응답은 새 토큰과 계정 상태를 바꾸지 않는다. 닉네임 저장 뒤 도착한 옛
프로필 조회도 새 이름을 덮지 않는다. 리뷰 편집과 목록 응답은 연 계정·요청 세대를
확인하고 계정이 바뀌면 초안 업로드를 취소한다.

커뮤니티 대표·본문 사진, 리뷰·내 리뷰 썸네일이 실패하면 원래 글 또는 현재 읽은
리뷰 페이지를 다시 받아 사진 주소를 갱신한다. 커뮤니티 본문·출처·AI 표시는 같은
상세 응답으로 함께 바뀐다. 화면마다 자동 갱신은 30초에 한 번, 수동 재시도는
실패 뒤 다시 가능하며 동시 요청은 공유한다. 갱신 중 다음 리뷰 페이지 요청을
잠시 멈추고 새 순서가 적용된 뒤 이어 받는다. 서명 주소는 메모리에만 둔다.

[후속 검증 기록](../../docs/qa/ios-release-followup-verification.md)은 자동 시험과
실제 화면 확인, 실제 계정·실기기에 남은 동선을 구분한다.

### 영문 길안내 노선 표시 (MZ2AZ-250)

길안내 목적지명·언어 안내는 긴 문구를 줄바꿈하며, 소요 시간과 경로 요약은
가로 공간이 부족하면 세로로 배치합니다(MZ2AZ-117). 한·영 요약을 240pt/600pt
너비와 기본/접근성 큰 글자에서 SwiftUI 크기 계산으로 검증합니다.

카카오 영문 응답의 `Line 1` 같은 숫자 호선은 지하철로 분류합니다.
이때 차종에 남은 `일반`은 제목에서 제외하고, 안내문 앞의 중복 노선명을 제거합니다.
버스로 명시된 구간은 버스 분류를 우선합니다. 실제 경로의 안내문·지명은 서버
응답을 사용하므로 이 처리만으로 모든 안내문의 번역을 보장하지 않습니다.

### 메타 측정 설정 (MZ2AZ-391)

`resources/MetaService-Info.local.plist`에 `AppID`·`ClientToken` 문자열과
`MeasurementEnabled` 불리언을 넣는다. 파일은 Git에서 제외하며 클라이언트
토큰과 App Secret을 저장소에 넣지 않는다. App Secret은 앱에서 사용하지 않는다.
파일 없음·잘못된 값·활성화 값 생략은 모두 측정 비활성화로 처리한다.
AppID는 메타 개발자 콘솔의 앱 ID이며 App Store Connect의 숫자 Apple ID와 다르다.

첫 출시부터 ATT를 요청한다(MZ2AZ-402). 신규 사용자는 온보딩 완료·건너뛰기 뒤,
기존 완료 사용자는 실행 후 스플래시가 끝난 활성 화면에서 0.6초 뒤 묻는다.
비활성화되면 대기를 취소하고 다음 활성화 때 다시 확인한다. 시스템 상태가
`.notDetermined`일 때만 요청하며 같은 실행에서는 중복 요청하지 않는다.
기기 전체 추적 요청 OFF로 창 없이 거부된 경우도 Meta를 켜지 않는다.

운영 설정의 `MeasurementEnabled=true`·ATT `.authorized`·이용 통계 ON을
모두 만족해야 SDK를 초기화하고 이벤트를 전송한다. ATT 응답 직후와 포그라운드
진입, SDK 이벤트·flush 요청 전에 최신 조건을 확인한다. 동의 전/통계 OFF 이벤트는 보관하거나
나중에 재전송하지 않는다. ATT를 거부해도 Firebase 통계와 앱 기능은 유지한다.

**알려진 한계(MZ2AZ-402):** OFF 이후 새 이벤트는 SDK 에 넘기지 않고 flush 도 부르지 않는다.
다만 OFF 직전에 이미 SDK 에 넘긴 이벤트의 전송은 SDK 18.1.1 공개 API 로 취소할 수 없다
(큐 삭제·예약 전송 취소 없음). 넘기는 것 자체가 ATT 허용 + 통계 ON 일 때뿐이라 추적 동의 밖의 전송은 아니다.

마이페이지 도움·정책 사이의 「이용 통계 수집」은 기본 ON이며 UserDefaults에
저장한다. OFF로 시작하면 Firebase 초기화를 미루고, 실행 중 OFF로 바꾸면
자동 수집까지 끈다. ON으로 되돌리면 Firebase를 켜고 Meta는 위 조건을 다시
검사한다. 「광고 추적 허용」 행은 시스템 허용 상태를 표시하고 앱 설정을 연다.
허용 여부나 통계 선택으로 앱 기능을 제한하지 않는다. 권한 문구는 기존 위치
권한과 같은 한국어·영어 `InfoPlist.strings`를 사용한다.
[ATT·통계 설정 계획과 실기기 확인 항목](../../docs/project/plans/ios-att-statistics.md).

메타에 직접 보내는 이벤트는 이름만 있는 `save_place`·`create_course` 두 개다.
회원 속성·장소 ID·검색어·본문·좌표를 추가하지 않는다. SDK 표준 설치·활성화
기록은 별도로 발생할 수 있다. 자동 행동 수집과 정기 자동 전송은 끄고 동의가
확인된 호출에서 전송한다. SDK가 이미 전송한 데이터는 동의 철회로 회수되지 않는다.
실제 이벤트 관리자 수신·광고 귀속과 Android 구현은 별도로 확인해야 한다.
[구현 계획](../../docs/project/plans/meta-app-events.md)을 참고한다.

### 함정

**코스 표시 (MZ2AZ-389·390):** 편의시설 줄은 요청 언어의 이름·분류·주소를 쓰고 읽는 법은 제목 아래에 둔다.
번호 핀은 줄과 같은 제목이며, 새로 담은 곳과 다시 받은 곳의 카드에도 표시말이 이어진다. 저장된 일차는
서버 `totalMinutes`를 「약 N시간 M분(이동 포함)」으로 보여 준다. 머무는 시간만 고치면 그 차이를 반영하고,
장소·순서·좌표를 고치거나 아직 저장하지 않았으면 머무는 시간만 보여 준다. 저장 후 새 이동 어림을 받는다.

**큰 글자 코스 편집 (MZ2AZ-388):** 취소·저장 버튼은 한 줄 자연 폭과 44pt 터치 높이를 유지한다.
접근성 글자 크기에서는 제목을 다음 줄에 둔다. 일정 시트의 안내·필터·요약·동작·장소는 한 목록 안에서
스크롤되므로 medium 시트에서도 길찾기 한도 안내와 지도 앱에서 돌아오는 문구를 끝까지 읽을 수 있다.
접근성 크기에서는 거리·시간 요약과 하단 여행·길찾기 동작도 세로로 놓는다. 거리 문장과 목적지
번호·이름은 잘라 줄이지 않고 줄바꿈하며, 일반 글자 크기의 하단 동작은 가로 배치를 유지한다.
떠 있는 가이드 입구는 접근성 크기에서 말풍선을 접고 46pt 해태 얼굴과 접근성 이름을 유지한다.
길안내 중의 헤더 입구와 저장된 아이콘 위치·끌기 동작은 그대로다.

| 증상 | 처방 |
| --- | --- |
| 코드를 받았는데 화면이 옛것이다 | `just ios-run`으로 다시 덮어 설치한다. 기기가 여럿이면 `SCENETRIP_IOS_DEVICE=<UDID> just ios-run`으로 고른다. 설치·실행 오류는 [시뮬레이터 실행 안내](../../docs/ops/ios-simulator-run.md)를 따른다. 이 명령은 로그인·코스 데이터를 유지한다(MZ2AZ-386) |
| 길찾기가 「현재 위치를 찾는 중」에서 멈춘다 | 시뮬레이터에 가짜 위치가 없다. `xcrun simctl location booted set 37.5663,126.9779` (서울시청) |
| 백엔드는 떠 있는데 8081 이 connection refused | 시뮬레이터가 `localhost` 를 `::1`(IPv6) 로 먼저 푸는데 포트가 IPv4 전용일 때 난다 — IPv6→IPv4 프록시를 하나 띄우면 된다(실측) |

## 첫 실행 — 스플래시와 사용법

앱을 열면 `AppRoot` 가 **스플래시 → (첫 실행이면) 사용법 넉 장 → 앱** 순서를 든다.
진짜 앱은 처음부터 밑에 깔려 있고 스플래시는 그 위를 덮는다 — 1.9초 동안 지도 SDK
인증과 첫 서버 호출이 끝나므로 덮개가 걷힐 때 화면이 이미 그려져 있다.

마스코트는 **해태**다(피노→진도(MZ2AZ-286)→해태(MZ2AZ-289), 2026-08-28).

길안내 중에는 안내 제목 옆의 해태 얼굴 단추로 가이드를 연다. 큰 글자에서도 한도 안내와
지도 앱 넘기기 단추를 덮지 않는다. 안내를 끝내면 떠 있는 해태가 사용자가 두었던 위치로
돌아온다(MZ2AZ-387). [후속 검증 기록](../../docs/qa/ios-followup-verification.md)을 참고한다.
장소 카드가 떠 있으면 말풍선을 접고 카드 위로 피하는 기존 입구를 사용한다.
정본은 일러스트 컷(`resources/Images.xcassets/haetae-*`)이고, 앱은 포즈별
그림을 갈아끼우며 소품(반짝이·말풍선)과 모션(숨쉬기·갸웃)만 코드로 얹는다 —
`PinoMascot.swift` 머리말 참고. 코드 안 타입 이름(`Pino*`)은 첫 마스코트의
이름이 남은 것이다.

사용법 넉 장은 **영어가 본문**이고 한국어는 흐린 보조줄이다. 본체 UI 는 아직 한국어라
넷째 장을 넘기면 말이 바뀐다 — 별도 일감이다.

다시 보려면 **마이페이지 → 사용법 다시 보기**. 본 적 있는지는 `UserDefaults` 의
`scenetrip.onboarding.seenVersion` 에 판 번호로 남는다.

자세한 것은 [docs/product/prd/onboarding.md](../../docs/product/prd/onboarding.md).

회의에서 확정돼 코드가 지키고 있는 것:

- **시작 시각을 묻지 않는다.** 8/10 목업에는 있었으나 삭제 확정됐다.
- **날짜는 선택이다.** 안 고르고 넘어갈 수 있고, 종료일은 일차 수에서 계산한다.
- **작품은 찜한 것이 먼저, 나머지는 인기도순.**
- **계획 단계에서는 길찾기 API 를 부르지 않는다.** 지도는 직선으로 잇는다. AI 초안의
  하루 총계가 현재 동선과 일치하면 서버가 준 이동·체류 시간을 「어림」으로 표시한다.
  동선이 바뀌면 그 어림을 버리고 머무는 시간만 표시한다(MZ2AZ-390).
- **AI 결과를 바로 저장하지 않는다.** 편집 화면을 거쳐 「코스 만들기」를 눌러야 남는다.
- **AI 일정의 방문 수는 고정하지 않는다.** 현재 켜진 LLM 일정 생성은 빡빡/널널한
  여행 성격을 전달하고 가까운 장소를 고른다. 결정적 엔진으로 전환했을 때만 설정의
  하루 상한(빡빡 7 · 여유 3)을 쓰며, 시간 예산이 먼저 차면 그보다 적게 담는다.
  온보딩과 마법사는 방문 수를 약속하지 않는다(MZ2AZ-399).

아직 정해지지 않아 **일부러 비워 둔 것**:

- LLM의 「빡빡하게 / 널널하게」는 여행 성격이다. 초안을 받은 뒤 일차 안 순서는
  편집 화면의 동선 최적화(직선거리)로 조정할 수 있다.
- 「인기 코스」의 이름·정렬 기준, 그리고 진짜 코스 공유 API(MZ2AZ-232, 아직 백엔드 티켓
  없음 — 2026-08-24 결정: 당장은 만들지 않는다).
- 편의시설 조회는 프로토타입 서버를 빌려 쓴다. `/pois` 계약·구현(MZ2AZ-283·284)이 서면 갈아탄다.

## 여행 모드 — 편집 화면 안에서 길찾기·스탬프 (2026-09-04, MZ2AZ-307)

계획은 [trip-mode.md](../../docs/project/plans/trip-mode.md) §8·§9. navi-proto 의 2단계를 옮기되
경로는 **서버 계약**으로 받는다 — 카카오 직접 호출은 main 에 없다.

```
[코스 시작] / 행의 「길찾기」 / 목록 「이어서 길찾기」           startTrip → TripSession.start(to:number:courseId:)
  → 이 지도에 현재 위치 → N번 실제 경로 (직선 계획선 위에)       RouteMapView.legs · tripHere  ← POST /navigation/next-leg
  → 반경 100 m 안에 5분 머무르면 도착                              TripArrival (뒷문 -tripDwellSeconds 10)
  → 발바닥 스탬프(화면 가운데) · 핀은 발바닥 · 목록은 「다녀옴」      PawStampOverlay · PinoPin.pawPin · visitedAt
  → 아래 줄 「다음 · M번 ○○로 길찾기」를 사람이 누르면 그때 M번 경로
```

- **저장된 코스에서만** 열린다 — 계약이 목적지를 코스 항목(`itemId`)으로 받는다. 저장 전 코스는
  「저장된 코스의 장소에서만 길찾기를 부를 수 있어요」.
- 코스를 **시작**(`active`)해야 서버가 답한다. 시작 전에는 「코스를 시작한 뒤에…」(409).
- 실패한 뒤에는 걸어도 다시 묻지 않는다(유료 호출). 503·연결 실패에만 「다시 시도」.
- 「이어서 길찾기」는 **홈의 「내 여행 이어가기」 카드**에 있다(2026-09-05 홈 탭 이식).
- 다녀온 곳도 「다시 길찾기」가 된다. 도착하면 다음 갈 곳이 목록 맨 위로 올라온다.
- 안내 중에는 편의시설 점을 끈다 — 경로선이 주인공이다. 끝나면 다시 켠다.
- **발자취**: 안내 중 지나온 자리를 25 m 마다 기기에만 남기고(`FootprintStore`), 지도 오른쪽
  위 발자국 단추로 황금 발자국을 보인다(줌에 맞춰 솎는다). 지우기는 마이페이지.
  기록하기와 지도에 발자취 보기는 기본 OFF이며, 로그아웃·탈퇴·세션 소실 때 기록을 지우고
  두 설정을 모두 OFF로 되돌린다(MZ2AZ-348). 같은 계정으로 다시 로그인해도 삭제한 기록은 복원하지 않는다.
- 옛 별도 길찾기 창(`RouteNavView`)은 코스 여행에서 더 안 쓴다. 파일은 남겨 둔다.

### 시뮬레이터에서 보기

시뮬레이터는 진짜 GPS 가 없어 **가상 GPS 가 기본으로 켜진다**(`DemoDrive`, 실기기는 인자가
있을 때만). 안내가 켜지면 서울시청(마지막 자리)에서 경로선을 따라 걷고(도보 240 m/s ·
대중교통 두 배, 느리게 보려면 `-demoSpeed 12`), 핀 12 m 앞에서 멈춘다. 반경 100 m 에 **5초
머무르면** 스탬프가 찍히는데, 그 뒤에도 핀에 닿을 때까지 받은 길로 걷고 경로선도 그때까지
남는다. 코스 화면을 나가면 시청으로 되돌아간다.

```
xcrun simctl launch <UDID> com.mz2az.scenetrip                     # 이대로 다 된다
xcrun simctl launch <UDID> com.mz2az.scenetrip -demoDrive 0        # 가상 GPS 를 끄고 simctl location 으로
```

영상용 데모 코스는 `-demoCourse 1 -navStop 1 -demoDrive 3` 으로 — 저장소의
`resources/demo/demo-course.json` 을 코스로 만들고 1→3번까지 남쪽 250 m 에서 출발한다.

  (`PlaceType.label` 이 nil) 칩에서는 「기타」 다. 새 코드가 생기면 그 표에 한 줄을 더한다(`PlaceTypeTests`).

  영어를 적는다. `Text("…")` 처럼 글자를 바로 적는 자리는 그대로 번역되고, 문자열을 변수로 넘기거나 조립하면 `tr("…")` 로

  `tr("코스", at: "화면 제목")` + 열쇠 `코스|화면 제목`. 번역을 빠뜨리면 그 글자만 한국어로 남는다.

  `PhotoGalleryRulesTests` 가 지킨다.
- **누구나 읽는 창구에 「내 것」 표시가 실릴 때는 부르기 전에 토큰을 살핀다** (MZ2AZ-363): 리뷰 목록은 만료된 토큰에 401 을 주지 않고
  비회원처럼 답한다 — 갱신할 계기가 없어 「내 리뷰」 가 빠진 목록이 그려졌다. `AuthRefresher.refreshIfStale()` 가 받을 때 적어 둔
  만료 시각을 보고 먼저 갱신한다(`ReviewSubject.reviews`).
- **사진을 고르고 줄이는 코드는 한 벌이다** (MZ2AZ-363): `Models/PhotoPickParts.swift`(「사진 추가」 칸·「빼기」 단추·고른 것 읽기)와
  `Models/PhotoShrink.swift`(다시 그려 줄이기)를 여행후기 쓰기와 리뷰 쓰기가 같이 쓴다. 남에게 보이는 사진은 원본 파일을 그대로
  올리지 않는다 — 다시 그려야 위치(GPS) EXIF 가 빠진다(`PhotoShrinkTests` 가 지킨다). 고른 파일은 통째로 풀지 않고 ImageIO 로 긴 변까지만 푼다
  (`PhotoShrink.image(from:longest:)`) — 미리보기도 같은 길이라 투명 PNG 가 올라갈 파일처럼 흰 바탕으로 보인다. 고르는 창은 시스템 `PhotosPicker` 라
  사진 보관함 권한(`NSPhotoLibraryUsageDescription`)이 필요 없다.
- 로그인 코드는 `src/Auth/` 에 있다 (MZ2AZ-336). 구글 로그인은 GoogleSignIn SDK 로
  ID 토큰을 받는다(`GoogleOAuth.swift`, 의존성 선언은 `//:Package.swift`). 토큰 싣기와 401 처리(만료 → 갱신 한 번 → 재시도)는
  `AuthRequestBuilder.swift` 가 생성 클라이언트에 끼워 넣는다 — 화면 코드는 API 를 그냥 부른다.
  로컬에서 로그인하려면 `.env` 에 `SCENETRIP_AUTH_JWT_SECRET` 이 있어야 한다(`.env.example`).
- Apple 로그인(MZ2AZ-415)은 `AppleSignInButton`의 Apple 기본 버튼 → `AppleOAuth`의 시스템 인증 창 →
  `AppleSignInFlow`의 생성 `POST /auth/apple`을 따른다. 시도마다 보안 난수 32바이트를 만들고 Apple에는
  SHA-256 소문자 16진수, 서버에는 원문 nonce를 보낸다. identityToken·authorizationCode·첫 로그인 이름은
  메모리에서 서버로만 전달한다. 취소하면 로그인하지 않으며 인증 중에는 두 버튼과 시트 닫기를 잠근다.
  3초 안에 비회원 쓰기가 끝나지 않으면 병합을 진행하지 않는다(구글에도 동일 적용).
  Apple 인가 코드는 일회용이라 오류·한도 응답에서 자동 재전송하지 않는다.
  서버에 `.p8` 설정이 없으면 501 안내를 표시하고 해당 실행에서 Apple 버튼을 숨긴다(기존 계약).
  [Apple 로그인 계획](../../docs/project/plans/ios-apple-login.md)에
  단위·시뮬레이터 검사와 DEV 실기기 가입·재로그인·탈퇴 검사 절차를 구분했다.
- **실패한 요청은 공통 계층이 다시 보낸다** (MZ2AZ-366, 계획 `docs/project/plans/app-retry.md`). 빌더가 내주는 세션이
  `Models/RetryingSession.swift` 이고 규칙은 `Models/RetryRules.swift` 다(숫자는 `RetryRules.Tuning` 한 곳) — 조회는 끊김·502·503·504 에
  세 번(1·2·4초), PUT·DELETE 는 두 번, POST 는 서버에 닿지 않은 것이 확실할 때만, 분당 한도(429 `RATE_LIMITED`)는
  `Retry-After` 뒤 한 번. **길찾기·마법사·토큰 갱신은 다시 보내지 않는다.** 화면을 떠나면 쉬는 중에도 멈춘다. 응답의
  `RateLimit-*` 는 `Models/RateLimitLedger.swift` 가 적어 둔다(아직 화면에 보이지 않는다). 실패를 넣어 보는 뒷문은
  `simctl launch … -netFault "v1/places:status:503:2"`(`Models/NetFault.swift` — 개발 빌드의 시뮬레이터에서만 동작).
- **챗봇은 멱등 키를 실어 보낸다** (`Idempotency-Key`, MZ2AZ-366). 서버가 키를 아는 것이 확인된 때만(이번 실행에서 응답의
  `RateLimit-*` 를 봤다) 끊김·502·503·504·500 에 자동으로 한 번 다시 보내고(요청마다 50초, 턴 전체 110초), `409 처리 중` 은
  3초마다 같은 키로 다시 묻되 그 키를 처음 보낸 때부터 55초까지만(서버가 처리 중인 키를 1 분 뒤 새로 처리한다), 그래도 실패면 창에 「다시 시도」 가 뜬다 — 같은 키·처음 만든 요청 그대로라 모델을
  두 번 부르지 않는다. 확인되지 않았으면 전처럼 한 번만 보내고 단추도 없다. 가이드 창을 닫으면 기다리던 다시 보내기·되묻기를
  끊는다(처음 보낸 요청은 끊지 않는다). 뒷문 `-netFault "guide/chat:cut:2"` 는 보낸 뒤 2초에 끊는다.
- 설치 식별자는 **키체인**에 둔다(`Keychain.swift`, MZ2AZ-335) — 옛 자리(`UserDefaults` `scenetrip.deviceId`)의 값은
  첫 실행에 옮긴다. 키체인은 앱을 지워도 남으므로 설치 뒤 첫 실행에는 남은 값을 버린다(지웠다 깔면 새 설치본).
- `InstallIdentity.swift` 를 `CartStore` 밖으로 뗐다 — 코스 API 도 같은 설치 식별자가
  필요해서다 (MZ2AZ-261).

## 빌드가 되는 조건

- **macOS + 정식 Xcode 만.** 모든 타깃에 `tags = ["ios"]` 가 달려 있고 `.bazelrc` 가
  리눅스에서만 그 태그를 걸러내므로 리눅스 러너는 이 모듈을 건너뛴다. **새 타깃을
  추가하면 `tags = ["ios"]` 도 함께 단다** — 상세와 실측 근거는 `BUILD.bazel` 머리말
  과 계획서 §5-3.
- `.swift` 파일이 있으므로 `just check` 가 `swiftformat`·`swiftlint` 를 요구한다 —
  없으면 게이트가 빨간불이다. `brew install swiftformat swiftlint`.
- 규칙 설정 파일(`.swiftlint.yml`·`.swiftformat`)은 아직 만들지 않았다 — 화면을 몇 개
  옮긴 뒤 실제로 나온 경고를 근거로 쓴다 (계획서 §6).

## 명령

```bash
just build-module apps/scenetrip-ios    # 빌드
just ios-run                            # 시뮬레이터에 띄운다
just ios-xcode                          # Xcode 로 연다 (코드 탐색·디버깅·실기기)
```

`just ios-xcode` 는 `SceneTrip.xcodeproj` 를 만들고 연다. **그 파일은 생성물이라
커밋하지 않는다** — 사람마다 서명 설정과 기기 목록이 달라 서로 덮어쓴다. 정본은
`BUILD.bazel` 의 `xcodeproj` 타깃이다.

프로젝트를 열어도 **실제 빌드는 그 안에서 Bazel 이 한다.** 빌드 경로가 둘로 갈라지지
않는다 (ADR 0001 제1법칙).

> **네이버 지도 키 주의** — Xcode 가 부르는 빌드에는 `just ios-run` 의 `--define` 이
> 닿지 않는다. `.bazelrc.user` 에 아래 한 줄을 넣어야 지도가 뜬다. 그 파일은
> gitignore 대상이라 키가 저장소에 들어가지 않는다.
>
> ```
> build --define=naver_client_id=<발급받은 키>
> ```

## 실기기에 올리기

앱은 iPhone 전용·세로 방향으로 실행한다. iPad에서는 iPhone 호환 모드를 사용하며, 가로로 든 iPad에서도 앱이 가로 화면으로 늘어나지 않도록 세로 방향만 허용한다(MZ2AZ-416).

**시뮬레이터가 아니라 진짜 아이폰에서 보려면** 애플 서명이 필요하다. 서명 파일은
사람마다·기기마다 다르고 무료 애플 ID 로 만들면 **7일마다 새로 발급된다.** 저장소에
넣을 수 있는 물건이 아니라서 **기본으로 켜 두지 않았다** — 켜 두면 아이폰이 없는
팀원의 빌드까지 깨진다.

아이폰을 가진 사람이 자기 기계에서 한 번 켜면 된다.

### 1. 애플 ID 를 Xcode 에 등록한다

`Xcode → Settings → Accounts → +` 에서 애플 ID 를 넣는다. **유료 개발자 계정이 아니어도
된다.** 무료 계정으로도 자기 기기에는 설치할 수 있다.

**Apple 로그인은 유료 개발자 팀의 Sign in with Apple capability가 필요하다.** SceneTrip은 김태환님의
개발자 팀에서 번들 ID `com.mz2az.scenetrip`의 capability를 켜고 같은 권한이 든 프로파일로 서명한다.
`SceneTrip.entitlements`에는 `com.apple.developer.applesignin = [Default]`가 포함되어 있다.
아래 실기기 서명 설정에는 `deploy/SceneTrip-device.entitlements`를 선택한다.
시뮬레이터의 키체인 식별자는 유지한다. 실제 가입·로그아웃·재로그인·탈퇴는 Apple 키가 설정된 DEV에서
서명된 실기기로 확인해야 한다. 서버 개인 키를 앱이나 저장소에 넣지 않는다.

### 2. BUILD.bazel 에서 device 를 켠다

`apps/scenetrip-ios/BUILD.bazel` 의 `xcodeproj` 타깃에서 한 줄을 고친다.

```python
target_environments = (["simulator"],)
# ↓
target_environments = (["device", "simulator"],)
```

그리고 `ios_application` 에 서명을 붙인다. `local_provisioning_profile` 이 **내 기계에
깔린 프로파일을 찾아 준다** — 경로를 손으로 적지 않아도 된다.

```python
load("@rules_apple//apple:apple.bzl", "local_provisioning_profile")
load("@rules_xcodeproj//xcodeproj:defs.bzl", "xcode_provisioning_profile")

local_provisioning_profile(
    name="local_profile",
    profile_name="iOS Team Provisioning Profile: com.mz2az.scenetrip",
    tags=["ios", "manual"],
)

xcode_provisioning_profile(
    name="provisioning_profile",
    managed_by_xcode=True,  # 서명은 Xcode 가 한다
    provisioning_profile=":local_profile",
    tags=["ios", "manual"],
)
```

`ios_application(name = "bin", ...)` 에 `provisioning_profile = ":provisioning_profile"`를
더하고, 실기기 대상에서는 `entitlements = "deploy/SceneTrip-device.entitlements"`를
선택한다. 시뮬레이터 대상의 기존 키체인 그룹은 유지한다.

> **이 변경은 커밋하지 않는다.** 프로파일 이름이 사람마다 다르다. 팀 전원이 아이폰으로
> 확인하게 되면 그때 `--define` 으로 이름을 받는 형태로 정리한다.

### 3. Xcode 에서 실행한다

```
just ios-xcode
→ 아이폰을 USB 로 연결 (한 번 연결하면 이후 같은 와이파이에서 무선으로도 된다)
→ Xcode 상단에서 기기를 내 아이폰으로 선택 → Run
→ 아이폰: 설정 → 일반 → VPN 및 기기 관리 → 개발자 앱 신뢰
```

| `naver_client_id` | 빈 값 | 네이버 지도 클라이언트 ID (`just ios-run`은 환경변수 `NAVER_MAP_CLIENT_ID` 사용) |

DEV·PRD는 운영자가 준비한 HTTPS 주소를 명시해서 빌드한다. 다음 주소는 예시이며
실제 DNS·인증서·접근 제한이 설정된 해당 환경의 주소로 바꾼다.

```bash
just mobile-build-cloud ios https://api.example.com/v1
```

공용 Bazel 규칙이 `ApiConfiguration.swift`를 생성하고 앱 시작 시 생성 API 클라이언트에
주소를 넣는다. 비밀값은 포함하지 않는다. HTTP 원격 주소·인증정보·query·fragment·
잘못된 포트·`/v1` 이외 경로는 빌드 단계에서 거절한다. 잘못된 주소로 앱이 시작하거나
로컬 서버로 조용히 연결되는 폴백은 없다. 일반 `just ios-run`의 로컬 기본값은 유지된다.

Xcode에서 같은 환경을 쓰려면 gitignore 대상인 `.bazelrc.user`에
`build --define=scenetrip_api_base_url=https://api.example.com/v1`을 설정한다.
이 명령은 앱 빌드만 수행한다. 실기기 서명·TestFlight·App Store 배포는 별도 절차다.

## 운영

앱 자체 `UserDefaults` 사용 사유는 `resources/PrivacyInfo.xcprivacy`의 `CA92.1`로
선언하며 실제 번들 포함을 단위 시험으로 확인한다(MZ2AZ-416). 위치 권한 문구는
한국어·영어 `InfoPlist.strings`에서 제공한다. 최종 개인정보 수집 표시·SDK 선언
검토·실기기 서명·스토어 제출 조건은 [배포 준비 안내](deploy/README.md)에 있다.

스토어 배포 없음 — MZ2AZ-148 의 완료 조건이 "팀원이 로컬에서 실행"까지다.

배포용 실기기 패키지는 `just ios-package`를 사용한다. 시뮬레이터 실행과 구분하며
[서명·iPad 검증·TestFlight 준비 절차](deploy/README.md#배포용-패키지-mz2az-440)를 따른다.


### 빈 코스에서 여행 가이드 시작 (MZ2AZ-444)

직접 짜기의 새 빈 코스에 처음 들어오면 장바구니 버튼을 2.5초 한 번 강조하고,
「담아둔 장소로 코스를 시작해 보세요」를 표시한다. 장바구니가 비었으면
「장소를 담으면 여기서 코스에 넣을 수 있어요」로 안내한다. 표시 여부는 UserDefaults에
기록해 닫기·시간 만료·다시 실행 뒤 반복하지 않는다. 닫기 버튼과 VoiceOver 안내를 제공하고,
동작 줄이기에서는 고정 테두리만 표시한다. 기존 코스·AI 초안·장소가 있는 새 코스에서는 표시하지 않는다.
새 초안 여부는 편집기의 `isNew` 대신 서버 ID가 없는지로 판단하고, 편집기 진입 때 안내를 시작한다.
마법사의 당일치기 수동 초안도 같은 조건을 쓴다. 안내 task는 편집기에 두고 테두리는 즉시
강조한다. 문구·VoiceOver 낭독·seen 기록은 장바구니 조회가 끝난 뒤 시작하며, 조회에 성공하고
장소가 0개일 때만 빈 상태 문구를 쓴다. 조회 실패 시에는 「담아둔 장소로 코스를 시작해 보세요」를
표시한다. 안내는 문구가 표시된 시점부터 2.5초 유지한다.

빈 코스에서도 가이드가 열린다. 「지도 주변 촬영지 보기」는 누를 때의 현재 지도 중심을 고정해
생성 `GET /places`의 bbox 검색만 사용한다. 중심에서 남북·동서 약 3km인 사각 영역의
첫 40곳을 목록으로 보여 주고, 사용자가 누른 장소만 현재 일차에 추가한다.
위치 권한이 거절돼도 보이는 지도 기준으로 사용할 수 있다. 「내 위치로」는 위치 서비스 동의 뒤
기기 좌표로 조회하며, 기기 좌표를 얻지 못하면 비활성화한다. GPS가 자동 맞춘 지도는 기기 출처를
보존해 위치 동의를 받으며, 손으로 이동·확대한 지도는 동의 없이 조회한다(MZ2AZ-472).

「코스 추천받기 (AI)」와 AI 주변 질문은 별도로 표시하고 기존 AI 동의를 유지한다(MZ2AZ-468).
일정 추천은 편집할 초안으로 열리며 직접 저장해야 한다. 챗봇이 추천한 장소는 골라 담지만,
일정 변경 요청은 편집 초안에 반영될 수 있음을 안내한다. AI 오류는 「AI 가이드 오류」로 따로
표시하며, 대화·오류·AI 한도 상태와 관계없이 장바구니 미리보기·열기와 주변 조회 입구는 남는다.
가이드를 열기만 해서는 모델 요청을 보내거나 장소를 코스에 추가하지 않는다.
구현·fake 단위 시험·후속 화면 확인은 [첫 안내 계획](../../docs/project/plans/ios-first-course-guide.md)을 따른다.

### 신고·차단·문의 연락처 (MZ2AZ-461, App Store 1.2)

남의 리뷰(리뷰 시트의 줄)와 여행후기(목록 줄·상세·홈 「커뮤니티 지금」)에 「⋯」 이 있다 — 「신고」(이유 여섯 + 설명, 비회원 가능,
`POST /reports`)와 「이 사용자 차단」(확인 창 뒤 `POST /me/blocks`, 비회원이면 로그인 화면). 자기 글에는 없고,
탈퇴한 작성자의 글에는 차단이 없다. 차단하면 그 글을 바로 빼고 목록·방문자 사진·여행후기 목록을 다시 받는다 —
그 사람의 다른 글은 서버가 뺀다. 차단·풀기는 `ModerationEvents` 로 알려, 떠 있는 촬영지 상세·편의시설 카드·리뷰
시트가 방문자 사진을 비우고 다시 받는다(못 받아도 비운 채로 둔다). 나가 있던 여행후기 받기는 차단 때 무효가 된다.
신고 시트가 떠 있는 동안은 밑의 화면이 로그인 화면을 올리지 않고, 세션이 풀리면 신고 시트가 먼저 닫힌다. 마이페이지에 「차단한 사용자」(가입한 사람만, 풀기)와 「문의하기」
(`LegalLinks.supportEmail`, 글자로 보이고 메일 앱 열기 단추)가 있다. 리뷰·여행후기·닉네임·코스 저장이
`400 TEXT_NOT_ALLOWED` 면 「쓸 수 없는 말이 들어 있어요」 를 보인다. 사진첩·상세(촬영지·편의시설) 진입 전에는
`AuthRefresher.refreshIfStale()` 를 부른다 — 만료된 토큰이면 서버가 비회원으로 답해 차단한 사람의 사진이 섞이기
때문이다. 규칙은 `Models/Moderation.swift`, 화면은 `Reviews/ModerationViews.swift`·`ProfileTab/BlockedUsersView.swift`,
계획은 [`docs/project/plans/ios-moderation.md`](../../docs/project/plans/ios-moderation.md).
