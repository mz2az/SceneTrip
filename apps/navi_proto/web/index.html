1. 촬영지 담기

    지도 오른쪽 위의 📍 핀 찍기 로 POI 에 없는 곳도 담을 수 있다.

    🔍 장소 검색

    지도 범위와 무관하게 전국 47만 건에서 이름으로 찾는다. TMAP POI 다 — 네이버는 장소 검색 API 를 안 판다(6-7절, 공부 노트). 결과를 누르면 지도가 그 자리로 옮겨 가서 정확한 위치를 눈으로 대조할 수 있다.

      1-2. 장소 담기 0

        지금 보이는 지도 범위 안만 불러온다. 지도를 옮기면 다시 불러온다.

        2. 장바구니 0

          행을 잡아 끌면 순서를 바꿀 수 있다.

          여행 단계 v3

          담은 지점을 직선으로 잇는다. API 를 부르지 않는다.

          직선 거리로만 순서를 정한다 — 호출 0건. 세 방법을 다 돌려 가장 짧은 것을 고른다.

          3. 무엇을 중요하게 볼까 v2

          가중치가 클수록 그 항목이 나쁜 것으로 취급돼 뒤로 밀린다.

          이 버전에서 고정된 것
          • 대중교통은 ODsay · 경로선까지 받는다
          • 도보 구간은 TMAP 으로 그린다 — 계단·횡단보도를 주는 것이 TMAP 뿐이다
          • 고도는 Valhalla 로 잰다 — TMAP·ODsay 는 고도를 주지 않는다
          • 둘은 대안이 아니라 서로 다른 것을 주므로 둘 다 부른다
          • 도보냐 대중교통이냐는 점수가 고른다. 사람이 가르지 않는다
          • 보여 주는 것은 셋 — 그 셋만 실제로 채워 봐서 계단과 실제 오르막을 잰다

          담은 지점을 순서대로 잇는다. 지점은 여덟 개까지.

          경로를 무엇으로 풀까

          길찾기는 카카오로 통일했다 — 교통도 도보도 카카오다. (POI 는 TMAP 48만 건, 배경 지도는 네이버 그대로다.) 카카오는 출발지→역 · 역→도착지 도보를 아예 주지 않으므로 그 양 끝은 어느 교통을 골라도 따로 채운다.

          3. 이동 수단

          구간을 무엇으로 가를까 두 지점의 직선 거리 가 이 값보다 가까우면 걷고, 멀면 대중교통을 탄다. 직선이라 실제 도보 거리는 20~40% 더 길게 나온다 — 그만큼 낮춰 잡아야 한다. m

          4. 엔진

            ODsay 도보 구간을 무엇으로 채울까 ODsay 는 정류장까지 걸어가는 구간에 좌표를 주지 않는다. 승·하차 지점 (지하철은 출입구 좌표)을 알려 주므로, 그 사이를 도보 엔진으로 따로 이어 붙인다. OSRM 은 내 컴퓨터라 호출 비용이 없다.

            5. 결과 요약

            🤖 여행 가이드

            로컬 LLM 이 지금 위치 주변에서 골라 준다. 밖으로 나가는 것이 없다.

            지금 위치는 지도 한가운데다. 지도를 옮기면 기준도 따라 옮겨진다.

            6. 눈으로 비교하기

            네이버는 도보 경로 API 를 열어 두지 않았다. 그래서 비교는 사람이 한다 — 아래로 같은 두 지점을 네이버에서 열고, 이 화면의 선과 나란히 놓고 본다.

            7. GeoJSON

            서버가 앱에 보낼 형식 그대로다. geojson.io 에 붙여 넣으면 지도에 바로 그려진다.
